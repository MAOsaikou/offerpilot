# SPA navigation white-screen fix

The reported white pane is consistent with the nested `out-in` transitions in App and AppLayout: the inner RouterView waits for the old page's leave callback before mounting the matched page, and had no explicit page key. A regression against the original source confirms this mounting dependency. Ordinary and rapid browser navigation with isolated API fixtures did not reproduce the user's permanent stuck state, so the exact deployed trigger remains unconfirmed; no specific page exception was found.

Removed App's layout transition while keeping `auth.identityKey` on RouterView and the rendered layout. AppLayout uses one real enter transition, a keyed PageBoundary (`route.name ?? route.path`), and a Component existence guard. Its leave callback immediately removes the old page, so CSS cannot delay navigation or leave an invisible page occupying the pane. Page render/lifecycle crashes show an accessible retry message; retry remounts the page and navigation clears the error, including within the same named route. Auth guards, titles and mobile sidebar behavior are preserved. Frontend design and test contracts were updated.

Verification: six new SPA regression cases and the related auth tests pass; full frontend Vitest passes (47 files, 264 tests), as do format:check, lint, typecheck and production build. Chromium checked the production build at 1280×900 and 390×844, including reduced motion, all main sidebar pages, rapid navigation, mobile sidebar closure, visible content, no horizontal overflow and no page errors. Browser API responses were isolated 503 fixtures to exercise recoverable data errors; this is not a check of the user's nginx/backend environment.
