# 05 · 接口文档

分支整合（2026-10-08）：定向改写、补丁采纳和服务器岗位板接口均接受同一 CurrentUser 校验后的 JWT 或有效访客凭据；下文功能分支端点与认证契约同时生效。优化 SSE 与普通聊天共用前端身份取消和逐帧校验，切换身份不交付旧报告。升级不修改 HTTP、事件或卡片结构。

## 求职看板已实现契约（2026-10-04）
本增量取代 §8 的规划接口描述；未列出的删除、历史、排序和下一步时间接口尚未实现。
- GET /api/v1/applications：返回当前身份的 ServerApplication 数组，按 createdAt DESC、id 排序。
- POST /api/v1/applications：请求 {jobId}，仅接受已存在的真实岗位；唯一 (user_id, job_id) 保证重复收藏返回原记录，保留阶段和备注。
- PATCH /api/v1/applications/{id}：请求 {status?, note?}，至少一个非 null 字段；只更新提供的字段。note 最多 2000 Unicode 字符，空字符串清空备注。status 为 TODO、APPLIED、INTERVIEW、OFFER、CLOSED，分别显示收藏、已投递、面试中、Offer、已结束；允许回退或跨阶段。
响应沿用 ApiResponse。每条记录含 id、jobId、status、note、createdAt、updatedAt（UTC ISO 时间）和 job（现有 RealJob DTO，来自保存的公共岗位）。不接收客户端的 userId 或岗位快照。身份缺失/失效为 401；不存在的 job 为 30501/404；不存在或不属于当前用户的 Application 为 30601/404；无效状态、空补丁或过长备注为 10001/400。
数据按已有访客身份持久化；另一浏览器或设备使用同一身份可恢复，新建访客身份不会读取别人的记录。本次不增加登录、身份迁移或 Agent 看板写工具。


## 聊天定向改写已实现契约（2026-10-03）

## 1. 通用约定

### 聊天岗位增量（2026-09-28，覆盖下文 M1 的 JOB 占位描述）

请求仍为 POST `/agent/chat`，支持 AUTO 与 JOB。JOB 动作解析为 search/match/clarify；search 无需简历标识，match 必须明确意图并在 `options.context` 提供完整 `{jobId,resumeId,resumeVersionId}`。规划模型生成的资源ID不进入匹配；不把旧匹配上下文当作新的匹配指令。信息不足时仅生成澄清回复、无 Plan/工具事件。

搜索事件沿用现有序列，tool.call/result.name=`search_jobs`，source=`mcp:jobs-mcp`，access=`READ`，args=`{inputs:{action:'search',query,site,nature,location},upstreamOutputs}`。工具步骤包括指定企业时的 list_sites 校验和 search_jobs 调用；不逐条记录 MCP 握手。输入企业名称在适配层解析为正式站点ID，卡片 criteria 保存实际执行条件。搜索成功（含空结果）发出一张 `job_card`；全站故障/超时/非法企业使步骤 FAILED，不发空成功卡片。最终 run COMPLETED 仍仅表示整轮回复已保存，不能替代步骤成功状态。

`job_card` 新增兼容分支 schemaVersion=2：

```json
{"schemaVersion":2,"criteria":{"query":"Java","site":"didi","nature":"campus","location":"北京"},"items":[{"id":"job_...","site":"didi","title":"Java工程师","company":"滴滴","locations":"北京","nature":"campus","updatedAt":""}],"returnedCount":14,"fetchedAt":"2026-09-28T00:00:00Z","meta":{"sites":["didi"],"cached":false,"truncated":false,"skipped":[],"degradedSites":[]}}
```

items 最多5条，各字符串最多200字符，不附带完整JD；returnedCount 为本次去重返回数量（现有服务最多30），不是全站招聘总数。meta 的站点数组最多100项，站点名最多60字符，skipped.reason 统一为“暂不可用”，不保存外部错误正文。卡片超出32,768字符则失败并提示缩小查询。cardId 为 runId+stepId 派生的稳定UUID。旧 job_card 单岗位 payload 保持兼容。完整详情通过 `/jobs/{id}` 读取；“按这些条件继续搜索”导航 `/jobs?q=...&site=...&nature=...&location=...` 并重新查询，不承诺原结果分页。匹配沿用 `matchJobToResume` 与 job_match，不新增审批写操作。

当前聊天实现（2026-09-23）：POST `/agent/chat` 为持久化多轮模型流，沿用既有请求/事件字段。`options.modelTier` 缺省使用后端默认档位；无效档位或非空附件返回 HTTP 400。缺省 conversationId 自动创建会话；指定 ID 必须属于当前访客，否则 HTTP 404。纯文字成功序列仍为 `run.started → text.delta* → usage（上游提供时）→ run.completed`，COMPLETED 必须在消息和运行事务提交后发出。失败终止为 `error(recoverable=false)`；错误码 40009 为模型未配置、40010 为模型调用失败、40001 为超时、50001 为持久化失败，供应商正文不透传。costEstimate=0 表示未估算。支持 15 秒注释心跳和显式 cancel；事件回放与 Last-Event-ID 续传仍是后续目标。岗位搜索、岗位匹配与基础简历诊断已接入聊天；简历定向改写已接入（见本文顶部2026-10-03契约）；看板更新仍未接入。

M1 Orchestrator v1：AUTO 在回复前识别意图，复合任务生成结构化 Plan，单专家意图和显式模式生成一步 Plan。闲聊、澄清与安全拒绝不生成 Plan，保持纯文字事件兼容。规划非法最多重试两次，之后降级文字建议；不新增必需请求字段或事件类型。岗位匹配需要 `options.context` 同时带有字符串 `jobId`、`resumeId`、`resumeVersionId` 且本轮动作明确为 match；JOB 的搜索、澄清与资源标识规则见上方增量。

计划事件序列：`run.started → plan.created → [step.updated(RUNNING) → tool.call → tool.result → ui.card? → step.updated(DONE|FAILED)]* → text.delta* → usage? → run.completed`。`ui.card` 在已接入的真实业务工具成功时出现（搜索含合法空结果）。依赖失败的步骤只发布 SKIPPED，独立步骤继续；`plan.created.steps` 为校验后稳定拓扑顺序，初始状态 PENDING。`stepId` 关联步骤，`toolCallId` 为本轮唯一的 `runId:stepId`，所有事件共用同一递增 ID 序列和 runId。

占位工具名称为 `placeholder.CAREER_DISCOVERY|RESUME|JOB|INTERVIEWER|COACH`（前缀后接其中一个枚举），`source=local`、`access=READ`；args 为 `{inputs, upstreamOutputs}`，结果明确标注占位、未执行真实业务操作。岗位步骤在具备上述完整标识时工具名为 `matchJobToResume`，同样 source=local、access=READ；成功结果摘要来自校验报告，卡片类型为 `job_match`。DONE/ok=true 对占位仅表示占位调用完成，对匹配表示报告已保存。某步失败后仍可成功生成汇总，运行 COMPLETED 不等同于所有步骤成功。步骤和工具 durationMs 可以为 0。usage 汇总规划重试和最终回复中供应商已报告的用量，未报告部分不估算。

取消会释放当前规划/专家/回复订阅；显式 cancel 的连接仍有效时以 `run.completed(CANCELLED)` 结束。终止时未完成步骤由前端收束为 SKIPPED（失败运行中正在执行的步骤为 FAILED），未完成调用显示取消或失败。Plan/工具事件仅当前页面可见，刷新不恢复；持久化文字、FAILED/CANCELLED 部分回复与多轮上下文规则不变。

### 当前访客认证与会话契约

- `POST /auth/guest` 无需认证，返回 `{accessToken, expiresAt}`，响应 `Cache-Control: no-store`。每次创建独立用户；令牌由服务器生成 256 位随机值，数据库仅保存 SHA-256 摘要，有效期 30 天。浏览器保存令牌并随之后的会话/聊天/取消请求携带 Bearer 头；未带令牌 401，过期令牌 401/20002。不会在失效时自动换身份，也不会自动重放发送请求。下文 JWT 登录已实现，刷新令牌仍是规划，访客身份尚无跨设备找回流程。
- §3 六类会话接口均已实现。列表 `page=1&size=20`，置顶优先，再按 updatedAt、id 倒序，size 最大 100。title 非空白且最多 100 字符；首条问题自动生成最多 40 字符的标题。每次请求都校验 owner，不区分“不存在”和“属于其他用户”。
- 消息分页默认 `size=30`，最大 100，返回 `{items,nextBefore?,hasMore}`；每页内部按稳定 ordinal 升序，首次取最近一页，nextBefore 用于加载更早消息。非法或跨会话游标返回 400。消息保留 parts、usage，并增加 plainText、status（RUNNING/COMPLETED/CANCELLED/FAILED）。
- 同一会话最多一个 RUNNING，每用户最多两个；超出返回 HTTP 429/30204。运行中的会话不能删除。删除单个会话级联删除其消息和运行，前端先显示确认。
- `POST /agent/runs/{id}/cancel` 已实现且对终态幂等，校验 owner，无权访问返回 404/30201。保留已生成内容并记为 CANCELLED。断流也释放订阅并尝试保存部分内容；每秒最多一个正文检查点，异常停机最多可能丢失最近约一秒输出。最长运行 10 分钟；遗留 RUNNING 在后续读取消息或开始运行时按租约置 FAILED，解除并发占用。
- 最近 10 个成功完整轮次、最多 24,000 字符进入上下文；中断/失败轮次仍展示但不进入模型上下文。模式选择记录到会话和运行。显式 JOB 与计划中的岗位步骤解析动作后执行搜索或选定资源匹配；RESUME 基础诊断已接入，其余专家仍未接入。

成功：

```json

```

```json
{ "code": 30402, "message": "简历不存在或无权访问", "data": null, "traceId": "8f3c2a1e9b",
  "errors": [ { "field": "resumeId", "reason": "not_found" } ] }
```

### 1.6 SSE 约定

- 请求头：`Accept: text/event-stream`；响应头：`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
- 建立流之前的认证、参数和业务错误保留对应 HTTP 状态码，返回 `Content-Type: application/json` 的通用失败包裹；建立流后的错误使用 `error` 事件。
- 帧格式：

```text
id: 42
event: text.delta
data: {"runId":"run_01J8...","stepId":"s2","ts":"2026-10-12T10:00:03.120+08:00","text":"根据你的项目经历"}

```

- 心跳：每 15s 一条 `: ping` 注释行。
- 断线续传：客户端重连时携带 `Last-Event-ID`，请求 `GET /agent/runs/{runId}/events?after=<id>&follow=true`，服务端从 Redis 缓冲（5 分钟）或 `EventStore` 补发并继续推送。
- 结束：`run.completed` 或 `error(recoverable=false)` 后服务端关闭连接。
- 事件 schema 见 §17。

### 已实现的密码登录增量（2026-10-07）

认证修复（2026-10-08）：密码登录 JWT 签名密钥必须由 JWT_SECRET 提供至少 64 字节随机值；缺失、短值或 change-me 占位值会拒绝启动。V11 已共享且保持原样，新增 V12 停用固定 ID/邮箱且密码哈希仍为原公开测试值的账号；已轮换密码或邮箱的账号及历史数据保留。正式客服通过受控流程创建，不提供公开登录凭据。

### 基础诊断已实现契约（2026-09-26）

以下端点均使用访客 Bearer token；跨用户或版本不匹配返回404，沿用既有错误结构。报告只分析已保存版本，未保存编辑不在输入中。

- `POST /resumes/{id}/versions/{vid}/analyze`：body `{requestId}`，16–80位字母、数字或连字符；返回 SSE。相同用户/请求ID/版本已成功时返回原报告，不再调用模型；同请求ID换版本400，运行中或已失败/取消重复请求429，显式重试用新ID。每用户同时最多一个诊断。此首版不支持 targetJobId，岗位定向仍属后续设计。
- SSE envelope 为 `{type,id,runId,ts,...}`，id 单调；`run.started` 增加 reportId/versionId；成功 `ui.card`（cardId=reportId，cardType=resume_diagnosis）→`run.completed(status=COMPLETED)`；失败 `error(code,message,recoverable=false)`。独立诊断 SSE 没有 conversationId/messageId，不能当聊天 started 事件直接塞进聊天仓库。15秒注释心跳，不支持 Last-Event-ID 续传。
- `GET /resumes/{id}/diagnoses`：最新30条任务数组，字段 id/versionId/versionNo/requestId/status/error/createdAt。
- `GET /resumes/diagnoses/{reportId}`：任务详情，另含 resumeId；SUCCEEDED 才含 report。
- `POST /resumes/diagnoses/{reportId}/cancel`：取消 RUNNING 任务，终态幂等；返回 ApiResponse(null)。断连/超时释放模型订阅并取消尚未提交任务；已保存成功报告不撤销。取消竞争通过条件更新拒绝迟到结果。客户端连接中断后先按 requestId 查询记录，避免盲目重试。

卡片 `resume_diagnosis` v2：schemaVersion=2，reportId/resumeId/versionId/versionNo/createdAt、summary、strengths[{message,evidence}]、findings[{findingId,ruleId,kind,priority,evidence,reason,suggestion,questions}]、checks[{path,message}]、limitations[]、model/modelTier/promptVersion/ruleVersion/durationMs/inputTokens/outputTokens。evidence=[{path,quote}]，路径指向该版本字符串叶节点、quote 必须原文子串。ruleId 为 CONTRIBUTION/EVIDENCE/RESULT/CLARITY/CONSISTENCY；kind 为 OBSERVATION/NEEDS_CLARIFICATION；priority 为 HIGH/MEDIUM/LOW。优点≤5，发现≤12，单项引用1–3条，问题≤3；允许空发现。checks 仅为程序生成的联系方式或教育缺项。没有总分，保留无 schemaVersion 的旧 overall/dimensions/issues 卡片读取。报告≤30000字符，满足消息卡片32768字符上限。

聊天 `options.context` 可携带 resumeId、resumeVersionId、diagnosisReportId；前两者必须来自调用方明确选择。带报告ID时检查报告归属与版本，只读取报告用于后续讨论。新生成/读取的报告都使用现有 ui.card 与消息 parts 持久化。

`POST /resumes/{id}/versions/{vid}/optimize` 接收 `{requestId, jobDescription}`：requestId 为16–80位字母/数字/连字符，jobDescription 非空且最多20000字，拒绝未知字段（包括 jobId）。使用用户已配置文字模型和所指定的 READY 简历保存版本，移除 basics/confidence 后发送模型。模型阶段在数据库事务外，限90秒；同用户同时只允许一个改写任务；同请求ID不同版本或JD拒绝，成功重试读取原结果，不再次调用模型。失败或取消不自动重试，重新生成使用新请求ID。

SSE 顺序 `run.started {reportId,versionId} → ui.card {cardId,cardType:resume_diff,payload} → run.completed {status:COMPLETED}`；card 提交到数据库后发出。payload 为 `{reportId,resumeId,resumeVersionId,versionNo,batchId,summary,patches,stats,model,modelTier,promptVersion,durationMs,inputTokens,outputTokens,createdAt}`。无建议时 patches=[]、batchId=null，不创建批次或新版本；卡片最多30000字符。只在结构/引文失败时修复一次；路径与 from 原文必须匹配，非空 jdEvidence 必须逐字出自所提供 JD；value 中的数字/百分比必须已出现在该条 from，不能借用其他经历或JD的成果数字。无法通过校验则 error(40003)，不落未经核实的建议。该数字规则不能证明所有文字事实真实，仍需用户核对。

`GET /resumes/{id}/optimizations` 返回最近30项 `{id,versionId,versionNo,requestId,status,error,createdAt}`；`GET /resumes/optimizations/{reportId}` 返回该任务（额外有resumeId、jobDescription和成功report）；`POST /resumes/optimizations/{reportId}/cancel` 取消本用户RUNNING任务。状态 RUNNING/SUCCEEDED/FAILED/CANCELLED；超过3分钟的RUNNING转FAILED，迟到执行不得保存报告/批次。所有读取/取消按用户隔离，未知任务404/30402；每人并发超限429/30204。离开生成面板取消当前连接；断流后可按requestId恢复已提交的结果。JD只由客户端文本提供，后端不依赖job模块；岗位页面可读取公开岗位并交由用户核对后提交JD。

补丁采纳请求 `{batchId, accepted: string[], edited?: { [patchId]: {value: string} }, confirmed?: string[]}` 使用当前访客 Bearer 凭据和标准 ApiResponse。accepted 与 edited 的并集为本次选中项，两者不得重叠；未选中项原样保留。confirmed 必须是选中项的子集；所有 needsUserConfirmation=true 的选中项（包括编辑后采纳）必须显式出现在 confirmed 中。拒绝空选择、重复/未知 ID、额外字段和无效值，400/10001。

首期仅支持 `replace`：`/summary`、`/experience/{i}/bullets/{j}`、`/projects/{i}/bullets/{j}` 和 `/skills/{i}/items/{j}`，下标必须是无前导零的非负整数，路径必须存在且值为字符串；from 必须与基准版本原文完全相同。禁止修改联系方式、经历身份/日期和整段对象，禁止重复路径和 add/remove/move/copy。每批 1–50 条，id 为 1–80 位字母/数字/下划线/连字符；from/value 最长5000字，reason 非空且最长2000字，jdEvidence/confirmationHint 可省略且最长2000字，needsUserConfirmation 必须为布尔值（为true时 confirmationHint 必填）。保存建议不创建简历版本；最终仍校验完整 ResumeStructure。

首次采纳要求简历 READY 且 vid 仍为当前版本，否则409/30401或30403。锁定简历后，补丁决策与 OPTIMIZED 新版本原子提交，parentVersionId=vid，parseMeta 包含 channel=patch、batchId。成功返回 `{batchId, version: ResumeVersion}`，不覆盖原版本。每批仅允许一次决策；相同决策重试返回同一个结果版本，即使当前简历之后已变化；不同决策重试409/30403。accepted/confirmed 顺序及 edited 属性顺序不影响幂等性。不存在或不属于调用方/路径版本的批次返回404/30402；读历史批次无需其基准版本仍为当前版本。GET 返回 `{batchId,resumeId,resumeVersionId,patches,stats:{added:0,replaced:N,removed:0},appliedVersionId,createdAt}`。

前端已接入 JD 生成、历史恢复、逐条选择/编辑/事实确认与采纳；生成只读，采纳才创建版本。默认零选择，编辑确认项后需重新确认。断流先读取任务结果，采纳响应丢失先读取批次及 appliedVersionId，不自动重发 POST。历史基准或未保存草稿只读。确认与数字/引文规则不能证明所有文字事实真实，真实模型无编造率与人工采纳率仍需评测。

## 7. 岗位

### 当前已实现（2026-09-21）

以下接口均使用当前访客 Bearer 凭据和标准 ApiResponse 包裹。与下方尚未实现的自然语言搜索/SSE 设计区分：本页匹配为同步 JSON 响应，不发送 Agent 工具事件。聊天里的岗位步骤另有一条路径：调用方已提供真实 `jobId`、`resumeId`、`resumeVersionId` 时，执行器调用同一个 `JobMatchService.create`，成功后发送 `ui.card`（`cardType=job_match`，`cardId` 为报告 id）。幂等键是运行 id 与步骤 id 生成的 UUID，不作为新的资源 id。没有这组标识时不调用匹配。

- `GET /jobs/sites`：`{sites:[{id,name,supportedNatures,...}],_meta}`，通过 MCP `list_sites` 获取。
- `GET /jobs?query=&site=&nature=&location=`：关键词必填，最长100字符；单企业可选，最长60字符；招聘类型为小写 `campus/intern/social/all`；城市可选，最长60字符。返回 `{items:RealJob[],meta:{sites,cached,skipped,degradedSites,truncated,...},fetchedAt}`。最多30条，非完整企业岗位总数；按站点、外部ID、实际招聘类型去重。全部站点失败返回502，不伪装成零岗位。
- `GET /jobs/{id}`：读取保存的岗位快照；`POST /jobs/{id}/refresh`：通过 MCP 获取并保存详情。RealJob 字段：`id,externalId,site,company,title,locations,category,nature,department,updatedAt,url,source,description,requirement,detailFetchedAt`。`updatedAt` 为企业原始字符串（可为空），`detailFetchedAt` 为本系统获取详情的ISO时间。非HTTP(S)或含凭据的URL丢弃。没有职责和要求的岗位不能匹配。
- `POST /jobs/{id}/matches`：`{resumeId,resumeVersionId,requestId}`。requestId 为16–80位字母/数字/连字符，客户端使用UUID；同用户同requestId成功结果重复返回，同ID不同输入拒绝。仅允许所有者的READY简历及明确版本，每用户一个进行中分析，模型阶段最多90秒。失败请求不自动重放，重新分析使用新ID。
- `GET /jobs/{id}/matches`：当前访客最近20条状态记录（RUNNING/COMPLETED/FAILED）。超过3分钟的运行在再次查询/创建时标失败。
- `GET /jobs/matches/{id}`：所有者读取成功报告，其他用户返回404。

匹配报告为 `{id,jobId,resumeId,resumeTitle,resumeVersionId,resumeVersionNo,createdAt,score,summary,requirements,jobSnapshot,resumeSnapshot,model,promptVersion,durationMs}`。requirements每项为 `{requirement,status,jdQuote,resumePath,resumeQuote,reason,suggestion}`，status 为 `MET/PARTIAL/MISSING`。引用必须是岗位文本/简历指定字符串叶子字段中的连续原文，MISSING引用路径和文本必须为空。score由服务端计算 `round(100 × (MET数 + 0.5×PARTIAL数) / 要求数)`，不是录用概率。最多12项，不允许重复JD引文；验证失败422且不保存成功报告。

岗位页通过 CardRenderer 的 `job_evidence_match` 渲染完整报告（含快照）。聊天卡片使用 `job_match`，payload 是去掉 `jobSnapshot`、`resumeSnapshot` 的同一份校验报告，并保留 `requirements`。为了让现有 `MatchReport` 能显示分数和证据，另外写入：`matched`（仅 `MET`，strength=`STRONG`，evidence 为 `resumeQuote`）、`gaps`（`PARTIAL` 与 `MISSING`，severity 固定为 `MEDIUM`，suggestion 为报告原文）、`advice`（suggestion 去重）。报告没有严重程度字段，因此不把缺失写成 `HIGH`，也不合成 `dimensions`。`resume_diff` 现由明确的聊天定向改写/已保存建议讨论发出；`board_update` 仍未接入。

错误新增：30501岗位不存在(404)、30502岗位内容不足(422)、30503报告不存在或无权访问(404)。MCP异常返回40005/502；认证、简历所有者、模型错误复用既有错误码。

## 17. SSE 事件 schema

以下 TypeScript 类型为前后端共同契约（前端放 `shared/types/agent-events.ts`，后端 `AgentEvent` sealed interface 一一对应）。

```ts
export interface EventBase { id: number; runId: string; stepId?: string; ts: string }

export type AgentEvent =
  | (EventBase & { type: 'run.started'; conversationId: string; messageId: string; model: string; mode: AgentMode })
  | (EventBase & { type: 'plan.created'; goal: string; steps: PlanStepView[] })
  | (EventBase & { type: 'step.updated'; stepId: string; status: StepStatus; summary?: string; durationMs?: number })
  | (EventBase & { type: 'reasoning.delta'; text: string })
  | (EventBase & { type: 'text.delta'; text: string })
  | (EventBase & { type: 'tool.call'; toolCallId: string; name: string; args: unknown; source: ToolSource; access: 'READ' | 'WRITE' | 'EXTERNAL_SIDE_EFFECT' })
  | (EventBase & { type: 'tool.result'; toolCallId: string; name: string; ok: boolean; resultPreview: string; durationMs: number; truncated: boolean })
  | (EventBase & { type: 'ui.card'; cardId: string; cardType: CardType; payload: unknown })
  | (EventBase & { type: 'approval.required'; approvalId: string; toolCallId: string; name: string; args: unknown; reason: string; expiresAt: string; editableFields?: string[] })
  | (EventBase & { type: 'approval.resolved'; approvalId: string; decision: 'APPROVE' | 'REJECT' | 'TIMEOUT' })
  | (EventBase & { type: 'citation'; sources: CitationSource[] })
  | (EventBase & { type: 'memory.used'; facts: { id: string; fact: string }[] })
  | (EventBase & { type: 'usage'; model: string; promptTokens: number; completionTokens: number; costEstimate: number; fallbackUsed: boolean })
  | (EventBase & { type: 'error'; code: number; message: string; recoverable: boolean })
  | (EventBase & { type: 'run.completed'; messageId: string; status: 'COMPLETED' | 'CANCELLED' | 'FAILED'; durationMs: number });

export type AgentMode = 'AUTO' | 'CAREER_DISCOVERY' | 'RESUME' | 'JOB' | 'INTERVIEWER' | 'COACH';
export type StepStatus = 'PENDING' | 'RUNNING' | 'DONE' | 'FAILED' | 'SKIPPED';
export type ToolSource = 'local' | `mcp:${string}`;
export type ExpertType = Exclude<AgentMode, 'AUTO'>;
export interface PlanStepView { id: string; title: string; agent: ExpertType; status: StepStatus; dependsOn: string[] }
export interface CitationSource { docId: string; title: string; snippet: string; score: number; url?: string; collection: string; index: number }

export type CardType =
  | 'career_profile_confirm' | 'career_recommendation' | 'career_compare'
  | 'resume_diagnosis' | 'resume_diff'
  | 'job_card' | 'job_match' | 'campus_calendar'
  | 'board_update'
  | 'interviewer_state' | 'interview_turn_score' | 'interview_report'
  | 'skill_gap' | 'skill_radar' | 'roadmap'
  | 'reminder';
```

前端消费时对 `type` 做 `switch`，`default` 分支使用 `never` 断言以保证新增事件类型编译期可见。

## 18. 卡片 payload schema

| cardType | payload 要点 |
