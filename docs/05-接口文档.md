## 1. 通用约定

当前聊天实现（2026-09-23）：POST `/agent/chat` 为持久化多轮模型流，沿用既有请求/事件字段。`options.modelTier` 缺省使用后端默认档位；无效档位或非空附件返回 HTTP 400。缺省 conversationId 自动创建会话；指定 ID 必须属于当前访客，否则 HTTP 404。纯文字成功序列仍为 `run.started → text.delta* → usage（上游提供时）→ run.completed`，COMPLETED 必须在消息和运行事务提交后发出。失败终止为 `error(recoverable=false)`；错误码 40009 为模型未配置、40010 为模型调用失败、40001 为超时、50001 为持久化失败，供应商正文不透传。costEstimate=0 表示未估算。支持 15 秒注释心跳和显式 cancel；事件回放与 Last-Event-ID 续传仍是后续目标。岗位匹配是目前唯一接入聊天的业务工具，简历改写和看板更新仍未接入。

M1 Orchestrator v1：AUTO 在回复前识别意图，复合任务生成结构化 Plan，单专家意图和显式模式生成一步 Plan。闲聊、澄清与安全拒绝不生成 Plan，保持纯文字事件兼容。规划非法最多重试两次，之后降级文字建议；不新增必需请求字段或事件类型。`options.context` 只在同时带有字符串 `jobId`、`resumeId`、`resumeVersionId` 时，供岗位步骤调用已有匹配；缺任何一个就不读取业务资源。步骤 `inputs` 若自身已带齐同一组字段，优先使用 `inputs`，不与 `context` 混拼。

计划事件序列：`run.started → plan.created → [step.updated(RUNNING) → tool.call → tool.result → ui.card? → step.updated(DONE|FAILED)]* → text.delta* → usage? → run.completed`。`ui.card` 仅在 `matchJobToResume` 成功时出现。依赖失败的步骤只发布 SKIPPED，独立步骤继续；`plan.created.steps` 为校验后稳定拓扑顺序，初始状态 PENDING。`stepId` 关联步骤，`toolCallId` 为本轮唯一的 `runId:stepId`，所有事件共用同一递增 ID 序列和 runId。

占位工具名称为 `placeholder.CAREER_DISCOVERY|RESUME|JOB|INTERVIEWER|COACH`（前缀后接其中一个枚举），`source=local`、`access=READ`；args 为 `{inputs, upstreamOutputs}`，结果明确标注占位、未执行真实业务操作。岗位步骤在具备上述完整标识时工具名为 `matchJobToResume`，同样 source=local、access=READ；成功结果摘要来自校验报告，卡片类型为 `job_match`。DONE/ok=true 对占位仅表示占位调用完成，对匹配表示报告已保存。某步失败后仍可成功生成汇总，运行 COMPLETED 不等同于所有步骤成功。步骤和工具 durationMs 可以为 0。usage 汇总规划重试和最终回复中供应商已报告的用量，未报告部分不估算。

取消会释放当前规划/专家/回复订阅；显式 cancel 的连接仍有效时以 `run.completed(CANCELLED)` 结束。终止时未完成步骤由前端收束为 SKIPPED（失败运行中正在执行的步骤为 FAILED），未完成调用显示取消或失败。Plan/工具事件仅当前页面可见，刷新不恢复；持久化文字、FAILED/CANCELLED 部分回复与多轮上下文规则不变。

### 当前访客认证与会话契约

- `POST /auth/guest` 无需认证，返回 `{accessToken, expiresAt}`，响应 `Cache-Control: no-store`。每次创建独立用户；令牌由服务器生成 256 位随机值，数据库仅保存 SHA-256 摘要，有效期 30 天。浏览器保存令牌并随之后的会话/聊天/取消请求携带 Bearer 头；未带令牌 401，过期令牌 401/20002。不会在失效时自动换身份，也不会自动重放发送请求。下文 JWT 登录/刷新仍是规划，访客身份尚无跨设备找回流程。
- §3 六类会话接口均已实现。列表 `page=1&size=20`，置顶优先，再按 updatedAt、id 倒序，size 最大 100。title 非空白且最多 100 字符；首条问题自动生成最多 40 字符的标题。每次请求都校验 owner，不区分“不存在”和“属于其他用户”。
- 消息分页默认 `size=30`，最大 100，返回 `{items,nextBefore?,hasMore}`；每页内部按稳定 ordinal 升序，首次取最近一页，nextBefore 用于加载更早消息。非法或跨会话游标返回 400。消息保留 parts、usage，并增加 plainText、status（RUNNING/COMPLETED/CANCELLED/FAILED）。
- 同一会话最多一个 RUNNING，每用户最多两个；超出返回 HTTP 429/30204。运行中的会话不能删除。删除单个会话级联删除其消息和运行，前端先显示确认。
- `POST /agent/runs/{id}/cancel` 已实现且对终态幂等，校验 owner，无权访问返回 404/30201。保留已生成内容并记为 CANCELLED。断流也释放订阅并尝试保存部分内容；每秒最多一个正文检查点，异常停机最多可能丢失最近约一秒输出。最长运行 10 分钟；遗留 RUNNING 在后续读取消息或开始运行时按租约置 FAILED，解除并发占用。
- 最近 10 个成功完整轮次、最多 24,000 字符进入上下文；中断/失败轮次仍展示但不进入模型上下文。模式选择记录到会话和运行。显式 JOB 或计划中的岗位步骤只有在带齐 `jobId`、`resumeId`、`resumeVersionId` 时才调用匹配，其余专家仍未接入。

### 1.1 认证

| 项 | 约定 |
| --- | --- |
| 访问令牌 | `Authorization: Bearer <accessToken>`，JWT，有效期 15 分钟 |

### 1.2 响应包裹

成功：

```json
{ "code": 0, "message": "ok", "data": { }, "traceId": "8f3c2a1e9b" }
```

失败：

```json
{ "code": 30402, "message": "简历不存在或无权访问", "data": null, "traceId": "8f3c2a1e9b",
  "errors": [ { "field": "resumeId", "reason": "not_found" } ] }
```

HTTP 状态码与 `code` 同时使用：400 参数、401 未认证、403 无权限、404 不存在、409 冲突、413 过大、422 业务校验、429 限流、500 系统、502/504 上游模型或 MCP 故障。

### 1.3 错误码

| 区段 | 含义 | 示例 |
| --- | --- | --- |
| 0 | 成功 | — |
| 1xxxx | 参数与请求格式 | `10001` 参数校验失败 · `10002` 文件类型不支持 · `10003` 文件过大 · `10004` JSON 解析失败 |
| 2xxxx | 认证授权 | `20001` 未登录 · `20002` 令牌过期 · `20003` 令牌无效 · `20004` 无权限 · `20005` 账号或密码错误 · `20006` 邮箱已注册 · `20007` 体验账号不允许该操作 |
| 3xxxx | 业务 | `30101` 会话不存在 · `30201` 运行不存在 · `30202` 运行已结束 · `30203` 审批不存在或已过期 · `30204` 并发运行超限 · `30301` 画像不存在 · `30302` 测评未完成 · `30401` 简历解析中 · `30402` 简历不存在 · `30403` 补丁与版本不匹配 · `30501` 岗位不存在 · `30601` 投递记录不存在 · `30602` 非法状态流转 · `30701` 面试会话不存在 · `30702` 面试已结束 · `30801` 知识库文档不存在 · `30901` MCP 服务器不存在 · `30902` MCP 连接失败 |
| 4xxxx | 模型与工具 | `40001` 模型调用超时 · `40002` 模型限流 · `40003` 结构化输出校验失败 · `40004` 内容审核未通过 · `40005` 工具执行失败 · `40006` 工具调用超限 · `40007` 用户拒绝审批 · `40008` 每日配额用尽 |
| 5xxxx | 系统 | `50000` 未知错误 · `50001` 数据库不可用 · `50002` 存储不可用 · `50003` 缓存不可用 |

### 1.4 分页、排序、过滤

- 查询参数：`page`（从 1 开始，默认 1）、`size`（默认 20，最大 100）、`sort`（如 `createdAt,desc`）。
- 响应 `data`：`{ "items": [], "page": 1, "size": 20, "total": 137 }`。

### 1.5 通用格式

| 项 | 约定 |
| --- | --- |
| ID | 字符串，前缀 + ULID，如 `conv_01J8…`、`run_…`、`res_…`、`job_…`、`occ_…` |
| 时间 | ISO-8601 带时区，如 `2026-10-12T10:00:00+08:00` |
| 枚举 | 大写下划线，如 `WRITTEN_TEST` |
| 幂等 | 创建类 POST 可携带 `Idempotency-Key` 头，24 小时内重复返回首次结果 |
| 限流头 | `X-RateLimit-Limit`、`X-RateLimit-Remaining`、`Retry-After` |
| 追踪 | 请求可带 `X-Trace-Id`，否则服务端生成并回写响应头与包裹体 |
| 文件上传 | `multipart/form-data`，字段 `file`；类型白名单见各接口；最大 10MB |

### 1.6 SSE 约定

- 请求头：`Accept: text/event-stream`；响应头：`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
- 建立流之前的认证、参数和业务错误保留对应 HTTP 状态码，返回 `Content-Type: application/json` 的通用失败包裹；建立流后的错误使用 `error` 事件。
- 帧格式：

```text
id: 42
event: text.delta
data: {"runId":"run_01J8...","stepId":"s2","ts":"2026-10-12T10:00:03.120+08:00","text":"根据你的项目经历"}

```

- 心跳：每 15s 一条 `: ping` 注释行。
- 断线续传：客户端重连时携带 `Last-Event-ID`，请求 `GET /agent/runs/{runId}/events?after=<id>&follow=true`，服务端从 Redis 缓冲（5 分钟）或 `EventStore` 补发并继续推送。
- 结束：`run.completed` 或 `error(recoverable=false)` 后服务端关闭连接。
- 事件 schema 见 §17。

### 4.1 `POST /agent/chat`

请求：

```json
{
  "conversationId": "conv_01J8...",
  "content": "帮我找字节和美团的后端校招岗，然后按字节的 JD 改我的简历",
  "attachments": [ { "fileId": "file_01J8...", "kind": "IMAGE" } ],
  "mode": "AUTO",
  "options": { "modelTier": "FLASH", "enableReasoning": true, "context": { "resumeId": "res_01J8..." } }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| conversationId | string | 否 | 为空则自动创建会话，`run.started` 中返回 |
| content | string | 是 | 1-4000 字符 |
| attachments[] | object[] | 否 | `fileId` 来自 `/files`；`kind`：`IMAGE`、`PDF`、`DOCX`、`AUDIO` |
| mode | enum | 否 | `AUTO`（默认）、`CAREER_DISCOVERY`、`RESUME`、`JOB`、`INTERVIEWER`、`COACH` |
| options.modelTier | enum | 否 | `FLASH`、`CHEAP`、`PRO`；体验账号忽略 |
| options.enableReasoning | boolean | 否 | 是否回传 `reasoning.delta` |
| options.context | object | 否 | 默认简历、目标职业、当前岗位等 |

响应：SSE 事件流（§17）。典型序列：`run.started → plan.created → step.updated → reasoning.delta* → tool.call → approval.required? → tool.result → ui.card → text.delta* → citation → step.updated → … → usage → run.completed`。

限制：每用户同时运行 ≤ 2（超出 `30204`）；每次运行最长 10 分钟。

### 4.2 `POST /agent/runs/{runId}/approvals/{approvalId}`

```json
{ "decision": "APPROVE", "editedArgs": { "status": "INTERVIEW", "nextActionAt": "2026-10-15T14:00:00+08:00" }, "reason": null }
```

`decision`：`APPROVE` / `REJECT`；`editedArgs` 仅 `APPROVE` 时可选；响应 `data: { "approvalId", "status": "APPROVED" }`。审批默认 10 分钟过期。

## 6. 简历

### 当前已实现的上传解析契约（2026-09-19）

所有端点要求访客 Bearer token，身份由 CurrentUser 校验；跨用户访问统一 404。响应沿用 ApiResponse 包裹。

模型设置（2026-09-20）：GET /resume-model-settings 返回 {models:[{id,label,provider,model,supportsVision,configured}],selection:{textTier,visionTier}}；PUT 同路径接收 {textTier,visionTier} 并返回相同结构。只修改当前访客；未登录401，未知档位/视觉能力不匹配400，配置不完整503。configured 表示地址、Key、型号的静态配置齐全，不是联网检测。响应不含 Key 或地址。上传与失败重试复制当前偏好，之后网页改偏好不影响既有排队/执行任务；旧任务无快照时使用默认档位。供应商级配置仍由部署环境管理。

- `POST /resumes`：multipart `file`，可选 `title` ≤100 字。支持 PDF / DOCX / PNG / JPG / JPEG / UTF-8 TXT / MD，≤10MB，空文件拒绝；同时校验扩展名与内容签名。返回完整 Resume DTO，`id` 为新简历 ID，状态 QUEUED。原文件写入私有 MinIO，数据库保存 files 元数据；不返回公开文件 URL。
- `GET /resumes?page=1&size=20`：`{items,total,page,size}`，size 1–50。列表项 currentVersion=null；详情另取。
- `GET /resumes/{id}`：Resume DTO：`id,title,fileName,parseStatus,parseProgress,parseError,currentVersionId,currentVersion,createdAt,updatedAt`。currentVersion 在解析成功前为 null。
- `GET /resumes/{id}/parse-status`：`{status,progress,error}`；状态 QUEUED / PARSING / READY / FAILED。进度 0（已排队）、10（读取文件）、50（模型抽取）、100（版本已提交），不是逐字节百分比。
- `POST /resumes/{id}/retry`：仅 FAILED 可重新入队；返回 Resume DTO。成功或执行中的任务返回 409。
- `PATCH /resumes/{id}`：`{title}`，非空且≤100 字；当前未实现 isDefault。
- `GET /resumes/{id}/versions`、`GET /resumes/{id}/versions/{vid}`：版本包含 `id,versionNo,parentVersionId,source,structured,plainText,parseMeta,createdAt`。
- `PUT /resumes/{id}/versions/{vid}/structured`：请求体直接是下方 structured 对象；vid 必须是当前版本，否则 409/30403。保存创建 MANUAL_EDIT 新版本，返回更新后的 Resume DTO；不会覆盖历史版本。

2026-09-20：上传版本 parseMeta 增量包含 channel、promptVersion=v2、model、tier、durationMs、imageCount；inputTokens/outputTokens/totalTokens 仅供应商返回有效用量时存在。旧版本保持原样，客户端不可假定新字段必有。

结构字段必须完整（confidence 可省略）；字符串最长 5000 字，分组最多50条、字符串数组最多100项、完整 JSON 最多10万字符，拒绝未知字段。证书为字符串数组。原件、解析结果与手动版本只归当前用户所有。

错误：10002 文件类型不符，10003/HTTP 413 文件过大，30401/409 状态冲突，30402/404 不存在或无权访问，30403/409 版本冲突，30404/400 无效文件，40003/422 结构校验失败，50002/503 文件存储不可用。异步解析失败通过 parseError 显示安全的原因，不透传模型响应或凭据。

## 7. 岗位

### 当前已实现（2026-09-21）

以下接口均使用当前访客 Bearer 凭据和标准 ApiResponse 包裹。与下方尚未实现的自然语言搜索/SSE 设计区分：本页匹配为同步 JSON 响应，不发送 Agent 工具事件。聊天里的岗位步骤另有一条路径：调用方已提供真实 `jobId`、`resumeId`、`resumeVersionId` 时，执行器调用同一个 `JobMatchService.create`，成功后发送 `ui.card`（`cardType=job_match`，`cardId` 为报告 id）。幂等键是运行 id 与步骤 id 生成的 UUID，不作为新的资源 id。没有这组标识时不调用匹配。

- `GET /jobs/sites`：`{sites:[{id,name,supportedNatures,...}],_meta}`，通过 MCP `list_sites` 获取。
- `GET /jobs?query=&site=&nature=&location=`：关键词必填，最长100字符；单企业可选，最长60字符；招聘类型为小写 `campus/intern/social/all`；城市可选，最长60字符。返回 `{items:RealJob[],meta:{sites,cached,skipped,degradedSites,truncated,...},fetchedAt}`。最多30条，非完整企业岗位总数；按站点、外部ID、实际招聘类型去重。全部站点失败返回502，不伪装成零岗位。
- `GET /jobs/{id}`：读取保存的岗位快照；`POST /jobs/{id}/refresh`：通过 MCP 获取并保存详情。RealJob 字段：`id,externalId,site,company,title,locations,category,nature,department,updatedAt,url,source,description,requirement,detailFetchedAt`。`updatedAt` 为企业原始字符串（可为空），`detailFetchedAt` 为本系统获取详情的ISO时间。非HTTP(S)或含凭据的URL丢弃。没有职责和要求的岗位不能匹配。
- `POST /jobs/{id}/matches`：`{resumeId,resumeVersionId,requestId}`。requestId 为16–80位字母/数字/连字符，客户端使用UUID；同用户同requestId成功结果重复返回，同ID不同输入拒绝。仅允许所有者的READY简历及明确版本，每用户一个进行中分析，模型阶段最多90秒。失败请求不自动重放，重新分析使用新ID。
- `GET /jobs/{id}/matches`：当前访客最近20条状态记录（RUNNING/COMPLETED/FAILED）。超过3分钟的运行在再次查询/创建时标失败。
- `GET /jobs/matches/{id}`：所有者读取成功报告，其他用户返回404。

匹配报告为 `{id,jobId,resumeId,resumeTitle,resumeVersionId,resumeVersionNo,createdAt,score,summary,requirements,jobSnapshot,resumeSnapshot,model,promptVersion,durationMs}`。requirements每项为 `{requirement,status,jdQuote,resumePath,resumeQuote,reason,suggestion}`，status 为 `MET/PARTIAL/MISSING`。引用必须是岗位文本/简历指定字符串叶子字段中的连续原文，MISSING引用路径和文本必须为空。score由服务端计算 `round(100 × (MET数 + 0.5×PARTIAL数) / 要求数)`，不是录用概率。最多12项，不允许重复JD引文；验证失败422且不保存成功报告。

岗位页通过 CardRenderer 的 `job_evidence_match` 渲染完整报告（含快照）。聊天卡片使用 `job_match`，payload 是去掉 `jobSnapshot`、`resumeSnapshot` 的同一份校验报告，并保留 `requirements`。为了让现有 `MatchReport` 能显示分数和证据，另外写入：`matched`（仅 `MET`，strength=`STRONG`，evidence 为 `resumeQuote`）、`gaps`（`PARTIAL` 与 `MISSING`，severity 固定为 `MEDIUM`，suggestion 为报告原文）、`advice`（suggestion 去重）。报告没有严重程度字段，因此不把缺失写成 `HIGH`，也不合成 `dimensions`。`resume_diff` 与 `board_update` 仍不从聊天发出。

错误新增：30501岗位不存在(404)、30502岗位内容不足(422)、30503报告不存在或无权访问(404)。MCP异常返回40005/502；认证、简历所有者、模型错误复用既有错误码。

## 17. SSE 事件 schema

以下 TypeScript 类型为前后端共同契约（前端放 `shared/types/agent-events.ts`，后端 `AgentEvent` sealed interface 一一对应）。

```ts
export interface EventBase { id: number; runId: string; stepId?: string; ts: string }

export type AgentEvent =
  | (EventBase & { type: 'run.started'; conversationId: string; messageId: string; model: string; mode: AgentMode })
  | (EventBase & { type: 'plan.created'; goal: string; steps: PlanStepView[] })
  | (EventBase & { type: 'step.updated'; stepId: string; status: StepStatus; summary?: string; durationMs?: number })
  | (EventBase & { type: 'reasoning.delta'; text: string })
  | (EventBase & { type: 'text.delta'; text: string })
  | (EventBase & { type: 'tool.call'; toolCallId: string; name: string; args: unknown; source: ToolSource; access: 'READ' | 'WRITE' | 'EXTERNAL_SIDE_EFFECT' })
  | (EventBase & { type: 'tool.result'; toolCallId: string; name: string; ok: boolean; resultPreview: string; durationMs: number; truncated: boolean })
  | (EventBase & { type: 'ui.card'; cardId: string; cardType: CardType; payload: unknown })
  | (EventBase & { type: 'approval.required'; approvalId: string; toolCallId: string; name: string; args: unknown; reason: string; expiresAt: string; editableFields?: string[] })
  | (EventBase & { type: 'approval.resolved'; approvalId: string; decision: 'APPROVE' | 'REJECT' | 'TIMEOUT' })
  | (EventBase & { type: 'citation'; sources: CitationSource[] })
  | (EventBase & { type: 'memory.used'; facts: { id: string; fact: string }[] })
  | (EventBase & { type: 'usage'; model: string; promptTokens: number; completionTokens: number; costEstimate: number; fallbackUsed: boolean })
  | (EventBase & { type: 'error'; code: number; message: string; recoverable: boolean })
  | (EventBase & { type: 'run.completed'; messageId: string; status: 'COMPLETED' | 'CANCELLED' | 'FAILED'; durationMs: number });

export type AgentMode = 'AUTO' | 'CAREER_DISCOVERY' | 'RESUME' | 'JOB' | 'INTERVIEWER' | 'COACH';
export type StepStatus = 'PENDING' | 'RUNNING' | 'DONE' | 'FAILED' | 'SKIPPED';
export type ToolSource = 'local' | `mcp:${string}`;
export type ExpertType = Exclude<AgentMode, 'AUTO'>;
export interface PlanStepView { id: string; title: string; agent: ExpertType; status: StepStatus; dependsOn: string[] }
export interface CitationSource { docId: string; title: string; snippet: string; score: number; url?: string; collection: string; index: number }

export type CardType =
  | 'career_profile_confirm' | 'career_recommendation' | 'career_compare'
  | 'resume_diagnosis' | 'resume_diff'
  | 'job_card' | 'job_match' | 'campus_calendar'
  | 'board_update'
  | 'interviewer_state' | 'interview_turn_score' | 'interview_report'
  | 'skill_gap' | 'skill_radar' | 'roadmap'
  | 'reminder';
```

前端消费时对 `type` 做 `switch`，`default` 分支使用 `never` 断言以保证新增事件类型编译期可见。
