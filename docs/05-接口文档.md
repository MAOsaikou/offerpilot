## 聊天卡片与完成面试增量（2026-10-11）

- JOB 匹配聊天成功按顺序发送并保存 job_match、job_eval_report 两张卡片；后者 payload 为已有 evaluation（含 title/company、具名 dimensions、overall/grade、summary/advice/note）。job_match.cardId 仍为匹配报告 ID，评估卡 cardId 是合法的稳定 UUID（不能包含冒号），均遵守消息卡片大小/数量限制。REST 与规则评分不变。
- INTERVIEWER 的自然评分请求在任何会话状态下走只读评分；调用方明确 interviewAction 优先。已完成会话收到答案请求返回正常的只读 tool.result 和最终回复，说明本轮未保存答案，可评分/复盘/新面试；不发 approval.required，不返回矛盾的未完成错误。资源仍按 owner 校验。
- 所有审批写工具 REJECT/TIMEOUT 保留 approval.resolved 与 tool.result.ok=false；叙述明确用户拒绝/确认超时、操作未执行、数据未改动，可重新发起。批准后的文字只使用业务名称，不输出内部标识；卡片和 SSE 的机器标识继续保留。
- COACH INTERVIEW evidenceSources 的 jobId 与会话的 interview_sessions.job_id 同源，STAR 弱结构证据也填入真实关联；不按练习角色推断岗位。skill_gap.name 使用具名的「岗位评估：…」「面试表现：…」，不改变评分与差距字段。

## Demo 契约与体验修复（2026-10-11）

生成任务主动取消使用新增业务码 `30205`，HTTP `409`，message 为「已取消，可重新发起」（匹配为「匹配已取消，可重新分析」）。取消端点仍为成功 `200` 且幂等，仅修改所属 RUNNING 任务；已经完成的报告不被取消。JOB_MATCH 取消向当前模型订阅传播，原 POST `/jobs/{id}/matches` 和所属 CANCELLED 的 GET `/jobs/matches/{id}` 返回同一取消业务码；其他用户仍为 `404/30503`。真正的匹配过期保持 `504/40001`。简历诊断与改写的 SSE 在取消时发终态 `error {code:30205,message:"已取消，可重新发起",recoverable:false}`，不发卡片；GET/list 保留 `status:CANCELLED`。同一 requestId 重试已取消任务也返回 30205；重新生成使用新 requestId。客户端将该业务码显示为安静的状态提示，可重新发起，不展示错误通知。

POST `/interviews`、GET `/interviews/{id}`、GET `/interviews` 的会话/摘要新增 `jobId:string|null`，回显 V25 已保存的显式来源；答案、进度更新返回的会话亦保留它。旧记录为 null，不按 role 推断来源。岗位标题可由既有 GET `/jobs/{jobId}` 读取，所属投递由 GET `/applications` 的精确 jobId 匹配。

匹配生成器返回空值或非 JSON 对象时，服务层返回既有 `422/40003`（报告结构无效），任务标记 FAILED 且不保存报告；已取消的任务仍优先返回 `409/30205` 并保持 CANCELLED。REST 与聊天共用此检查，demo、缓存副本及离线岗位快照均适用。

简历上传的文件上限仍为 10MiB（界面称 10MB）；multipart 超限和业务检查均返回 HTTP `413`、JSON `10003`「简历文件不能超过 10MB」。Tomcat 吞读被拒绝上传的剩余请求体，避免默认吞读上限导致普通 HTTP 客户端收到连接重置。前端选文件后，在隐私扫描与上传请求前校验大小。


## 投递工作区增量（2026-10-11）

`GET /api/v1/applications/{id}` 返回 `{application, latestMatch, resumeOptimizations, interviews, starStories, timeline, linkageNote}`。身份门禁沿用 CurrentUser，跨 owner / 不存在统一 404。application 沿用列表字段，新增 `nextAction`（文本）与 `nextActionAt`（YYYY-MM-DD 或 null）；列表、创建和 PATCH 返回相同字段。

latestMatch 是同 user_id + job_id 最近的 COMPLETED 匹配，或 null：`{id, createdAt, grade, topGaps, exportUrl}`。grade 复用现有 A–F 规则，topGaps 最多 3 项、MISSING 优先于 PARTIAL；exportUrl 为既有 `/api/v1/jobs/matches/{id}/eval.md`。打开完整报告仍调用 `GET /api/v1/jobs/matches/{id}`。V25 后 resumeOptimizations 为同 user_id+job_id 的改写任务（含进行中/失败）：`{id,resumeId,resumeVersionId,createdAt,status,viewUrl,pdfAvailable,exportUrl}`；viewUrl 打开指定简历版本的改写建议。interviews 为 `{id,status,overallScore,createdAt,recapExportUrl}`，status 为 IN_PROGRESS / COMPLETED；overallScore 是已有回答的当前规则评分，无回答为 null，recapExportUrl 使用既有 `/api/v1/interviews/{id}/recap.md`。starStories 为同 owner 的来源会话 job_id 命中的 `{id,title,sourceSessionId}`。旧记录无 job_id 仍不关联，linkageNote 说明明确来源与旧记录限制，不按 JD / role 模糊匹配。已有 PDF `/resumes/{id}/export.pdf` 导出的是**当前保存版本**，不能把它标为任意历史定向版本的 PDF。

`POST /api/v1/resumes/{id}/versions/{vid}/optimize` 保留 requestId / jobDescription，新增可选 jobId（字符串，非空且≤80字符；省略/null 为通用改写）；幂等校验包含 jobId，不能复用 requestId 改变来源。`POST /api/v1/interviews` 保留 role / kind，增加相同可选 jobId。job 不存在为404，非法标识为400；jobs 沿用共享快照可见性，简历/材料与 application/match 上下文按 owner 校验。聊天定向改写与 startInterview 从所选 jobId，或 owner-scoped applicationId / matchId（兼容 jobMatchId）解析岗位；不接受模型生成来源 ID，面试来源随批准参数保存且不可编辑。材料创建及收藏已有材料同事务记录 RESUME_OPTIMIZATION / INTERVIEW / STAR_STORY 的 ARTIFACT_LINKED；重复收藏不重复写事件，GET 不写。

聊天的直接 jobId 始终保留为用户选择，供匹配与 JD 工具按原业务契约处理；可选产物来源校验只影响保存的 job_id，不把直接选择改成未选择。不存在或非当前 owner 的 applicationId / matchId 不补岗位选择，不因可选来源解析发送终态 error，不暴露资源是否存在；缺少岗位的动作沿用澄清或参数校验。开始面试在审批前过滤不可用岗位来源，定向改写在读取所选 JD 后过滤保存来源，未知岗位仅省略来源；JD 读取或匹配本身的业务错误仍按原工具路径报告。看板 applicationId 仍是调用方提供的待审批目标，沿用审批后业务执行时的 owner 校验；拒绝审批不调用看板业务服务、不写入投递记录。数据库等非资源缺失故障仍报错。REST 创建的 jobId 是显式引用，未知岗位仍为30501/404（与收藏、面试创建一致），未知字段或非法输入仍为10001/400。

`PATCH /api/v1/applications/{id}` 增加可选 nextAction（≤1000 Unicode 字符）与 nextActionAt（有效 YYYY-MM-DD）。省略或 null 保持原值；`nextAction:""` 清空行动，`nextActionAt:""` 清空日期。状态/备注原契约保持；整次更新原子提交，相同值不新增事件。timeline 按时间、id 正序返回 `{id,kind,fromStatus,toStatus,detail,artifactType,artifactId,actor,createdAt}`，kind 为 CREATED / STATUS_CHANGED / NOTE_EDITED / NEXT_ACTION_EDITED / ARTIFACT_LINKED，actor 为 USER / AGENT / SYSTEM。旧记录只有迁移阶段快照，历史变化不可还原。

聊天沿用 #26 的 createApplication / updateApplicationStatus 和 approval.required → APPROVE → board_update，可编辑字段增加 nextAction / nextActionAt；拒绝、取消、超时不写。显式 context 可带 `boardAction`、已选 jobId 或 applicationId 及这些编辑字段，资源 ID 不取模型猜测。`boardAction:getApplicationDetail` + applicationId 使用 JOB 只读路径，无审批、无新专家。

## 面试 → STAR → 复盘契约（2026-10-11）

- 创建沿用 `{role,kind,jobId?}`，kind 是 `项目与经历` / `表达与结构` / `职业动机`，不接受 BEHAVIORAL。PUT `/interviews/{id}/answers/{index}` 的正文为 `{answerText}`，index=0..4；短 STAR 答案和内部换行均有效，长度上限12000 Unicode字符不变。成功保存后才查询候选。
- GET `/star-stories/candidates?sessionId=…` 返回数组，只有非空且 STAR≥3 的回答，含 questionIndex/questionText/title/body/role/starCount/situation/task/action/result/alreadySaved；进行中或已完成均可查询。POST `/star-stories` 接收 `{sessionId,questionIndex}`，从数据库重读验证，返回 Story；来源或正文重复幂等返回已存故事，空答案/STAR不足为400/10001。GET 返回 `{items,limit:30}`，DELETE `/{id}` 删除单条，DELETE 根路径清空；均按认证 owner 隔离。
- 聊天动作和会话标识推荐位于 `options.context.interviewAction/interviewSessionId`；兼容同名字段误放 `options` 顶层，嵌套 context 优先。未知动作/非法会话标识返回清楚的参数错误。新增只读动作 recallStarStories（AUTO/INTERVIEWER）；明确“引用已入库故事继续追问”的 continueInterview 请求也按只读处理，不写答案、不等待审批。
- 评分、完成报告和只读追问的实际会话确定 STAR 匹配，沿用 `ui.card` / `cardType=star_story_citations` / `payload={items:[{id,title,role,starCount,excerpt}],count}`，无匹配不发引用卡；引用使用现有消息卡片持久化。查询/构建/专家运行失败发终态 `error`（recoverable=false，友好 message），不再生成成功叙述；用户拒绝审批仍返回未执行的工具结果。
- GET `/interviews/{id}/recap.md` 需要 Bearer 身份，Accept 为 `text/markdown` 或 `*/*`；成功返回 UTF-8字节、`text/markdown;charset=UTF-8`、`Cache-Control:no-store`，Content-Disposition 含兼容 filename 和 RFC 5987 UTF-8 filename*。不接受 application/json 时返回406 JSON错误，不转成500；鉴权/不存在仍使用原JSON错误契约。前端服务端会话下载失败显示错误并允许重试，本机旧练习才使用本地问答导出。

## 聊天简历补丁采纳审批（2026-10-10）

聊天 `resume_diff` 卡片选择后发送新聊天请求：`{content:"请采纳所选的简历改写建议",mode:"RESUME",options:{context:{resumeAction:"applyPatches",resumeId:"rs_…",resumeVersionId:"rv_…",batchId:"pb_…",accepted:["p1"],edited:{p2:{value:"核对后的内容"}},confirmed:["p2"]}}}`。AUTO / RESUME 对该 context 直接路由为单个 RESUME 步骤，不调用规划或动作模型；资源与选择只取调用方 context，不从文字或模型提取补丁 ID。缺少关联或无效选择则澄清，要求重新在卡片选择。

`applyPatches` 为 local / WRITE，事件顺序为 `tool.call → approval.required → approval.resolved → tool.result → step.updated`。审批 args 固定为 resumeId/resumeVersionId 与上述决策字段，editableFields=[]；改变选择需发起新请求。标识只允许字母、数字、下划线和连字符（简历/版本 ≤80、批次 ≤100），决策复用 §6 ResumePatches 规则（≤50项，edited 值为 `{value:string}`，accepted 可为空但需非空编辑选择）。owner 始终取聊天身份，审批 POST 复用 §4.2，跨用户404、非法参数400/10001、重复或超时409/30203。只有 APPROVE 后才调用 `ResumePatchService.apply`，成功返回新版本编号和 ID 的工具文字；APPROVE 本身不代表写入成功。REJECT / TIMEOUT / 取消不写入，resolved 为 REJECT / TIMEOUT 时 tool.result.ok=false，错误码沿用 APPROVAL_REJECTED。

简历详情 / ResumeOptimizationPanel 的 `POST /api/v1/resumes/{id}/versions/{vid}/apply-patches` 仍是页面按钮直接采纳路径，不经过 ApprovalService。两个入口复用同一所有者、当前版本、事实确认及幂等检查，原版本保留。

## 成长教练双卡片与审批（2026-10-10）

COACH 已支持真实 `planLearning`（source=local、access=READ）。现有 `POST /api/v1/agent/chat` 的 AUTO/COACH 学习计划与技能差距请求，在档案目标可关联职业库时按顺序发布两条 ui.card：skill_gap、roadmap，cardId 分别由 runId+stepId 派生稳定 UUID。`ExpertResult.card()` 兼容首卡，cards() 为完整集合；消息 parts 使用既有8卡/字节限制保存，刷新读取快照不重算。无目标返回「设为目标」指导，无卡；未知目标引导职业库选择。可选 context.resumeId/resumeVersionId 仅作为一对已保存所有者版本读取；未选择时取当前用户 READY 简历中最近保存的当前版本。无可用/无权限简历降级档案技能，不泄露其他用户数据。

## 聊天文字面试增量（2026-10-09）

## 模型配额错误（2026-10-09）

模型配额拒绝返回 HTTP 429：40008 表示当日 token 配额已用尽（提示“今日模型额度已用尽，请明天再试”），40011 LLM_RATE_LIMITED 表示用户模型请求过于频繁（提示“模型请求过于频繁，请稍后再试”）。普通 HTTP 错误携带 Retry-After 秒数：RPM 到下一 UTC 分钟、日额度到下一 UTC 零点。聊天、诊断、改写在创建新工作/SSE 前做不消耗额度的预检查；每次实际模型调用再原子检查并消耗 RPM。若已开始 SSE 后因规划、重试或竞争触发配额，只能发既有 error 事件与相同业务错误码，不能改变已发送的 HTTP 状态或响应头。访客请求 PRO 返回 403/20004，并提示登录，不自动选择其他档位。

分支整合（2026-10-08）：定向改写、补丁采纳和服务器岗位板接口均接受同一 CurrentUser 校验后的 JWT 或有效访客凭据；下文功能分支端点与认证契约同时生效。优化 SSE 与普通聊天共用前端身份取消和逐帧校验，切换身份不交付旧报告。升级不修改 HTTP、事件或卡片结构。

### 聊天岗位增量（2026-09-28，覆盖下文 M1 的 JOB 占位描述）

请求仍为 POST `/agent/chat`，支持 AUTO 与 JOB。JOB 动作解析为 search/match/clarify；search 无需简历标识，match 必须明确意图并在 `options.context` 提供完整 `{jobId,resumeId,resumeVersionId}`。规划模型生成的资源ID不进入匹配；不把旧匹配上下文当作新的匹配指令。信息不足时仅生成澄清回复、无 Plan/工具事件。

搜索事件沿用现有序列，tool.call/result.name=`search_jobs`，source=`mcp:jobs-mcp`，access=`READ`，args=`{inputs:{action:'search',query,site,nature,location},upstreamOutputs}`。工具步骤包括指定企业时的 list_sites 校验和 search_jobs 调用；不逐条记录 MCP 握手。输入企业名称在适配层解析为正式站点ID，卡片 criteria 保存实际执行条件。搜索成功（含空结果）发出一张 `job_card`；全站故障/超时/非法企业使步骤 FAILED，不发空成功卡片。最终 run COMPLETED 仍仅表示整轮回复已保存，不能替代步骤成功状态。

`job_card` 新增兼容分支 schemaVersion=2：

```json
{"schemaVersion":2,"criteria":{"query":"Java","site":"didi","nature":"campus","location":"北京"},"items":[{"id":"job_...","site":"didi","title":"Java工程师","company":"滴滴","locations":"北京","nature":"campus","updatedAt":""}],"returnedCount":14,"fetchedAt":"2026-09-28T00:00:00Z","meta":{"sites":["didi"],"cached":false,"truncated":false,"skipped":[],"degradedSites":[]}}
```

items 最多5条，各字符串最多200字符，不附带完整JD；returnedCount 为本次去重返回数量（现有服务最多30），不是全站招聘总数。meta 的站点数组最多100项，站点名最多60字符，skipped.reason 统一为“暂不可用”，不保存外部错误正文。卡片超出32,768字符则失败并提示缩小查询。cardId 为 runId+stepId 派生的稳定UUID。旧 job_card 单岗位 payload 保持兼容。完整详情通过 `/jobs/{id}` 读取；“按这些条件继续搜索”导航 `/jobs?q=...&site=...&nature=...&location=...` 并重新查询，不承诺原结果分页。匹配沿用 `matchJobToResume` 与 job_match，不新增审批写操作。

当前聊天实现（2026-09-23）：POST `/agent/chat` 为持久化多轮模型流，沿用既有请求/事件字段。`options.modelTier` 缺省使用后端默认档位；无效档位或非空附件返回 HTTP 400。缺省 conversationId 自动创建会话；指定 ID 必须属于当前用户，否则 HTTP 404。纯文字成功序列仍为 `run.started → text.delta* → usage（上游提供时）→ run.completed`，COMPLETED 必须在消息和运行事务提交后发出。失败终止为 `error(recoverable=false)`；错误码 40009 为模型未配置、40010 为模型调用失败、40001 为超时、50001 为持久化失败，供应商正文不透传。costEstimate=0 表示未估算。支持 15 秒注释心跳和显式 cancel；事件回放与 Last-Event-ID 续传仍是后续目标。岗位搜索、岗位匹配与基础简历诊断已接入聊天；简历定向改写已接入（见本文顶部2026-10-03契约）；看板写入已接入审批流程（§4.2）。

M1 Orchestrator v1：AUTO 在回复前识别意图，复合任务生成结构化 Plan，单专家意图和显式模式生成一步 Plan。闲聊、澄清与安全拒绝不生成 Plan，保持纯文字事件兼容。规划非法最多重试两次，之后降级文字建议；不新增必需请求字段或事件类型。岗位匹配需要 `options.context` 同时带有字符串 `jobId`、`resumeId`、`resumeVersionId` 且本轮动作明确为 match；JOB 的搜索、澄清与资源标识规则见上方增量。

计划事件序列：`run.started → plan.created → [step.updated(RUNNING) → tool.call → tool.result → ui.card? → step.updated(DONE|FAILED)]* → text.delta* → usage? → run.completed`。`ui.card` 在已接入的真实业务工具成功时出现（搜索含合法空结果）。依赖失败的步骤只发布 SKIPPED，独立步骤继续；`plan.created.steps` 为校验后稳定拓扑顺序，初始状态 PENDING。`stepId` 关联步骤，`toolCallId` 为本轮唯一的 `runId:stepId`，所有事件共用同一递增 ID 序列和 runId。

占位工具名称为 `placeholder.JOB`（JOB 仅在匹配标识或服务缺失时降级；CAREER、INTERVIEWER 与 COACH 已接入真实路径），`source=local`、`access=READ`；args 为 `{inputs, upstreamOutputs}`，结果明确标注占位、未执行真实业务操作。岗位步骤在具备上述完整标识时工具名为 `matchJobToResume`，同样 source=local、access=READ；成功结果摘要来自校验报告，卡片类型为 `job_match`。DONE/ok=true 对占位仅表示占位调用完成，对匹配表示报告已保存。某步失败后仍可成功生成汇总，运行 COMPLETED 不等同于所有步骤成功。步骤和工具 durationMs 可以为 0。usage 汇总规划重试和最终回复中供应商已报告的用量，未报告部分不估算。

取消会释放当前规划/专家/回复订阅；显式 cancel 的连接仍有效时以 `run.completed(CANCELLED)` 结束。终止时未完成步骤由前端收束为 SKIPPED（失败运行中正在执行的步骤为 FAILED），未完成调用显示取消或失败。Plan/工具事件仅当前页面可见，刷新不恢复；持久化文字、FAILED/CANCELLED 部分回复与多轮上下文规则不变。

### 当前访客认证与会话契约

- `POST /auth/guest` 无需认证，返回 `{accessToken, expiresAt}`，响应 `Cache-Control: no-store`。每次创建独立用户；令牌由服务器生成 256 位随机值，数据库仅保存 SHA-256 摘要，有效期 30 天。浏览器保存令牌并随之后的会话/聊天/取消请求携带 Bearer 头；未带令牌 401，过期令牌 401/20002。不会在失效时自动换身份，也不会自动重放发送请求。下文 JWT 登录已实现，刷新令牌仍是规划，访客身份尚无跨设备找回流程。
- §3 六类会话接口均已实现。列表 `page=1&size=20`，置顶优先，再按 updatedAt、id 倒序，size 最大 100。title 非空白且最多 100 字符；首条问题自动生成最多 40 字符的标题。每次请求都校验 owner，不区分“不存在”和“属于其他用户”。
- 消息分页默认 `size=30`，最大 100，返回 `{items,nextBefore?,hasMore}`；每页内部按稳定 ordinal 升序，首次取最近一页，nextBefore 用于加载更早消息。非法或跨会话游标返回 400。消息保留 parts、usage，并增加 plainText、status（RUNNING/COMPLETED/CANCELLED/FAILED）。
- 同一会话最多一个 RUNNING，每用户最多两个；超出返回 HTTP 429/30204。运行中的会话不能删除。删除单个会话级联删除其消息和运行，前端先显示确认。
- `POST /agent/runs/{id}/cancel` 已实现且对终态幂等，校验 owner，无权访问返回 404/30201。保留已生成内容并记为 CANCELLED。断流也释放订阅并尝试保存部分内容；每秒最多一个正文检查点，异常停机最多可能丢失最近约一秒输出。最长运行 100 分钟（覆盖最多 8 个串行审批窗口）；遗留 RUNNING 在后续读取消息或开始运行时按租约置 FAILED，解除并发占用。
- 最近 10 个成功完整轮次、最多 24,000 字符进入上下文；中断/失败轮次仍展示但不进入模型上下文。模式选择记录到会话和运行。显式 JOB 与计划中的岗位步骤解析动作后执行搜索、选定资源匹配或审批看板写入（§4.2）；RESUME 基础诊断已接入，其余专家仍未接入。

### 1.6 SSE 约定

- 请求头：`Accept: text/event-stream`；响应头：`Content-Type: text/event-stream; charset=utf-8`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
- 建立流之前的认证、参数和业务错误保留对应 HTTP 状态码，返回 `Content-Type: application/json` 的通用失败包裹；建立流后的错误使用 `error` 事件。
- 帧格式：

```text
id: 42
event: text.delta
data: {"runId":"run_01J8...","stepId":"s2","ts":"2026-10-12T10:00:03.120+08:00","text":"根据你的项目经历"}

```

- 心跳：每 15s 一条 `: ping` 注释行。服务端 `offerpilot.sse.heartbeat-interval` 可调整间隔（默认 `PT15S`；回归测试使用 `2ms`），不改变帧格式。心跳直接在 boundedElastic 定时 worker 内发送，避免跨发送队列与终止取消竞争；CPU 繁忙时调度可能延后，短流不保证包含心跳。
- 聊天、诊断与改写共用串行 SSE writer：发送与终止互斥，终止立即停心跳/释放订阅，不依赖延后的容器完成回调；断开后不再发送或 flush。流内应用异常发送原有 `error(code,message,recoverable=false)` 后正常完成，不通过 MVC 异常处理向已提交 SSE 追加 JSON。
- 断线恢复（当前实现）：没有 `GET /agent/runs/{runId}/events`，不支持 `Last-Event-ID` 续传。`useConversationChat` 重新读取会话消息；存在 RUNNING 消息时每 2 秒轮询消息接口，恢复已持久化正文、状态和卡片，不重放 Plan/工具事件。
- 结束：`run.completed` 或 `error(recoverable=false)` 后服务端关闭连接。
- 事件 schema 见 §17。

### 删除当前用户数据（2026-10-10）

`DELETE /api/v1/users/me/data` 仅从 CurrentUser 校验 JWT/访客 Bearer 得到 owner，不接受用户 ID。正文必须恰为 `{ "confirm": "DELETE" }`；缺正文、缺词、大小写不同、非字符串或额外字段返回 400/10001，非法 JSON 返回 400/10004。未认证返回 401；共享 demo 返回 403/20007（客服使用专用 reset），含 STAFF 的账号返回 403/20004（避免自助删除管理权限）。注册 USER 和独立访客均可删除。

请求校验加固（2026-10-09）：register、login、staff/login 的 email/password 必须非空白；`PATCH /staff/users/{id}/status` 的 status 必须非空白且为 ACTIVE 或 DISABLED；`PATCH /applications/{id}` 可选 status 仅允许 TODO、APPLIED、INTERVIEW、OFFER、CLOSED，note 最多 2000 个 Unicode 字符（包括换行和补充平面字符，空字符串仍用于清空）；空补丁继续由服务拒绝。`PUT /resume-model-settings` 的 textTier/visionTier 均必填且为 FLASH、PRO、VISION_ALT（旧 CHEAP 兼容写为 FLASH），模型配置及视觉能力仍由服务检查。上述请求字段通过 Bean Validation，失败由 MethodArgumentNotValidException 统一返回 HTTP 400 / 10001 及字段 errors。不存在的邮箱与错误密码均执行一次密码哈希校验，再返回 20005，不跳过 BCrypt 计算。

认证修复（2026-10-08）：密码登录 JWT 签名密钥必须由 JWT_SECRET 提供至少 64 字节随机值；缺失、短值或 change-me 占位值会拒绝启动。V11 已共享且保持原样，新增 V12 停用固定 ID/邮箱且密码哈希仍为原公开测试值的账号；已轮换密码或邮箱的账号及历史数据保留。正式客服通过受控流程创建，不提供公开登录凭据。

`POST /auth/login` 与 `POST /auth/staff/login` 已实现：BCrypt 校验 `users.password_hash`，账号须为 `ACTIVE`；用户端要求 `USER` 角色、客服端要求 `STAFF` 角色（不满足返回 20004，密码错误返回 20005）。两者均签发 HS256 JWT（claims：`sub=userId`、`roles`、`nickname`），失效时间取 `offerpilot.security.access-ttl`，当前为 **12 小时**（`expiresIn=43200`）。`GET /auth/verify` 解析 Bearer 令牌并比对签名、有效期与账号状态；令牌无效 20003、过期 20002、缺失 20001。迁移 V11 中的公开测试账号由 V12 精确禁用，客服账号需由管理员独立配置。刷新令牌 Cookie 机制仍为规划，未随本次实现。

业务接口认证已接入登录令牌：`CurrentUser.require` 按令牌格式分流——43 位随机串走既有访客会话校验，JWT 走签名/有效期/账号状态校验；两类令牌在使用 `CurrentUser.require` 的业务接口均可用，访客流程向后兼容；`/staff/users*` 仍单独要求 STAFF JWT，`/auth/verify` 校验登录 JWT。前端登录后所有业务请求自动携带 JWT，路由守卫将未登录访问重定向到 `/login`。

`POST /auth/register` 已实现：仅需 `{email, password}`（邮箱格式校验；密码至少 6 位、不能全为空白，UTF-8 编码最多 72 字节），BCrypt 存储，昵称取邮箱前缀，角色默认 `USER`；邮箱重复返回 20006，格式/长度不合法返回 10001。注册成功直接签发 JWT（即注册即登录），响应结构与 `/auth/login` 相同。用户及客服登录也拒绝空白或超过 72 字节的密码，不裁剪或去除密码两端空格；已有短密码登录规则保持兼容。此前按字符上限注册的超长密码须经受控流程重置，不修改已有哈希或账号数据。

认证并发补充（2026-10-08）：访客锁等待期间保存发起时的身份作用域，获锁后若身份已改变则取消旧操作；发出业务请求前再次比对 Bearer 凭据，旧身份请求不发送、不重放。客服列表及启用/禁用请求复用同一身份作用域，迟到正文不得交付新账号，当前 401 仅使原凭据失效；旧页面验证失败不得注销后来登录的账号，网络错误保留当前身份并允许重试。

> 已实现（P1-4）：完整路由为 `POST /api/v1/agent/runs/{runId}/approvals/{approvalId}`，沿用 Bearer 身份与标准响应包裹。

```json

  "decision": "APPROVE", "args": { "applicationId": "app_123", "status": "INTERVIEW", "note": "周五面试" }, "reason": "确认修改"
}, "traceId": "trace_123" }
```

看板动作 `createApplication(jobId,status=TODO,note?)` / `updateApplicationStatus(applicationId,status?,note?)` 使用 JOB 专家，更新至少提供状态或备注。事件顺序为 `tool.call(access=WRITE) → approval.required → approval.resolved → tool.result → ui.card(board_update)? → step.updated`。只有 APPROVE 且 ApplicationService 成功提交才有 `ok=true` 和 `board_update`；拒绝/超时为 `ok=false`，摘要明确为用户拒绝/确认超时、该操作未执行、数据未改动并可重新发起。卡片 payload 为 `{application:{id,company,title,status,note,nextAction,nextActionAt},change:CREATED|UPDATED,changedFields:{...}}`，company/title与所有值来自保存结果；changedFields只包含本次批准并应用的status/note/nextAction/nextActionAt，清空值保留为空字符串或null。最终叙述完整接收changedFields。前端仅提供后端的五种状态，收到写入卡片后刷新 applications 查询。

## 7. 岗位

### 当前已实现（2026-09-21）

以下接口均使用 JWT 或访客 Bearer 凭据和标准 ApiResponse 包裹。与下方尚未实现的自然语言搜索/SSE 设计区分：本页匹配为同步 JSON 响应，不发送 Agent 工具事件。聊天里的岗位步骤另有一条路径：调用方已提供真实 `jobId`、`resumeId`、`resumeVersionId` 时，执行器调用同一个 `JobMatchService.create`，成功后发送 `ui.card`（`cardType=job_match`，`cardId` 为报告 id）。幂等键是运行 id 与步骤 id 生成的 UUID，不作为新的资源 id。没有这组标识时不调用匹配。

- `GET /jobs/sites`：`{sites:[{id,name,supportedNatures,...}],_meta}`，LIVE/AUTO 优先通过 MCP `list_sites` 获取；LOCAL 与 AUTO 服务失败时读取共用快照目录。
- `GET /jobs?query=&site=&nature=&location=`：关键词必填，最长100字符；单企业可选，最长60字符；招聘类型为小写 `campus/intern/social/all`，缺省 campus；城市可选，最长60字符。返回 `{items:RealJob[],meta:{sites,cached,skipped,degradedSites,truncated,...},fetchedAt}`。最多30条，非完整企业岗位总数；按站点、外部ID、实际招聘类型去重。LIVE 全部站点失败返回502/40005；默认 AUTO 在服务失败、超时、全部失败或错误导致零结果时回退示例快照；正常零匹配不回退。
- `GET /jobs/{id}`：读取保存的岗位快照；`POST /jobs/{id}/refresh`：官网岗位通过 MCP 获取并保存详情；快照岗位返回已保存快照，LOCAL 对已有官网岗位也只读取缓存、不触网。RealJob 字段：`id,externalId,site,company,title,locations,category,nature,department,updatedAt,url,source,description,requirement,detailFetchedAt`。`updatedAt` 为企业原始字符串（可为空），`detailFetchedAt` 为本系统获取详情的ISO时间。非HTTP(S)或含凭据的URL丢弃。没有职责和要求的岗位不能匹配。
- `POST /jobs/{id}/matches`：`{resumeId,resumeVersionId,requestId,modelTier?}`。modelTier 可选 FLASH/PRO，省略沿用部署默认档位；非法值400。requestId 为16–80位字母/数字/连字符，客户端使用UUID；同用户同requestId成功结果重复返回，同ID不同输入拒绝。仅允许所有者的READY简历及明确版本，每用户一个进行中分析；生成与最多一次原文依据修复共用总预算：FLASH 60秒、PRO 180秒。成功仍返回200与既有报告，新增可选 modelTier 元数据；同请求标识返回已完成结果，不重新收费。超时返回504/40001，message说明档位、等待上限（含证据校验）、未保存及重试方式；配额429/40011和Retry-After不变。失败请求不自动重放，重新分析使用新ID。客户端或代理断连可能发生在保存前后，先刷新历史确认，不能凭断连判断失败。
- `GET /jobs/{id}/matches`：当前用户最近20条状态记录（RUNNING/COMPLETED/FAILED）。超过5分钟的运行在再次查询/创建时标失败（覆盖PRO总预算及岗位详情/持久化余量）。
- `GET /jobs/matches/{id}`：所有者读取成功报告，其他用户返回404。

岗位源增量（2026-10-10）：原有字段保持兼容。官网 `source=company-career-site`；示例岗位 `source=LOCAL_SNAPSHOT`，新增可选 `snapshotDate`（YYYY-MM-DD）、`skills`（字符串数组）。`id` 仍为本系统 job_ ID；本地 `externalId=snapshot-<site>-<序号>`，`url=""`，无虚构官方详情链接。`meta` 新增 source、本地时的 snapshotDate/sourceDescription，AUTO 回退另有 fallbackReason（LIVE_UNAVAILABLE / LIVE_TIMEOUT / ALL_SITES_FAILED / EMPTY_DUE_TO_ERROR）；后端协议超时归为 LIVE_UNAVAILABLE，不返回外部异常正文。独立 jobs-mcp 使用 `_meta` 名称承载相同标记。total 是返回条数，truncated 保留截断语义，不新增 page/size。

聊天 job_card schemaVersion=2 的 meta 同样透传 source/snapshotDate/sourceDescription/fallbackReason，包括持久化后重放；搜索页与聊天显示「离线快照」，title 含日期及非实时声明。后端 MCP jobs.search 复用同一 JobService 并保留这些字段；jobs.match 只匹配调用方提供的 JD，不搜索。模式/预算/刷新见 [09 岗位源模式](09-部署与运维.md#岗位源模式2026-10-10)。

匹配报告为 `{id,jobId,resumeId,resumeTitle,resumeVersionId,resumeVersionNo,createdAt,score,summary,requirements,jobSnapshot,resumeSnapshot,model,promptVersion,durationMs}`。requirements每项为 `{requirement,status,jdQuote,resumePath,resumeQuote,reason,suggestion}`，status 为 `MET/PARTIAL/MISSING`。引用必须是岗位文本/简历指定字符串叶子字段中的连续原文，MISSING引用路径和文本必须为空。score由服务端计算 `round(100 × (MET数 + 0.5×PARTIAL数) / 要求数)`，不是录用概率。提示词建议最多12项（结构安全上限100项），超出建议仍保留核实项；枚举/并列技能优先拆分，每个具体技能均须可评估；不同要求可共享JD引文，按要求内容（NFKC/大小写/空白归一）去重。合并要求须列全技能，全部有证据才为MET，部分覆盖为PARTIAL；无效项从计分 requirements 中移到 unverifiedRequirements（每项 `{requirement,status:"UNVERIFIED",verificationIssue}`），新增 verifiedCount/unverifiedCount。失败引文/路径不保存。核实不足生成项一半时重试一次，保留核实项更多的一次；只有全无效或结构不可读在修复后仍无核实项才失败422/40003，不保存成功报告。引文可忽略空白、行首数字编号、全半角/弯引号及尾部分号/句号，保存原文子串；不省略内部内容。聊天保留错误码，校验耗尽 error.recoverable=true 并以 run.completed(FAILED) 收尾；新请求可重试。

岗位页通过 CardRenderer 的 `job_evidence_match` 渲染完整报告（含快照）。聊天卡片使用 `job_match`，payload 是去掉 `jobSnapshot`、`resumeSnapshot` 的同一份校验报告，并保留 `requirements`。为了让现有 `MatchReport` 能显示分数和证据，另外写入：`matched`（仅 `MET`，strength=`STRONG`，evidence 为 `resumeQuote`）、`gaps`（`PARTIAL` 与 `MISSING`，severity 固定为 `MEDIUM`，suggestion 为报告原文）、`advice`（suggestion 去重）。报告没有严重程度字段，因此不把缺失写成 `HIGH`，也不合成 `dimensions`。`resume_diff` 现由明确的聊天定向改写/已保存建议讨论发出；`board_update` 已接入审批看板写入（§4.2）。

错误新增：30501岗位不存在(404)、30502岗位内容不足(422)、30503报告不存在或无权访问(404)。MCP异常返回40005/502；认证、简历所有者、模型错误复用既有错误码。

## 17. SSE 事件 schema

以下类型保留事件与卡片的设计形态，已实现状态如下；不承诺所有枚举当前都会产生事件。聊天的已实现字段见 §1 / §4；简历独立 SSE 的 started/completed 字段见 §6，不要求 conversationId/messageId。

| 状态 | 事件 | 说明 |
| --- | --- | --- |
| 已实现 | run.started、text.delta、usage、error、run.completed | usage 仅上游提供有效用量时发送；失败可仅以 error 结束 |
| 已实现 | plan.created、step.updated、tool.call、tool.result、ui.card | 仅发生在计划 / 已接入工具流程，真实卡片范围见 §18 |
| 已实现 | approval.required、approval.resolved | 看板写入审批（§4.2），不表示所有写工具均已实现 |
| 已实现 | memory.used | 回复上下文使用的记忆原文 `{facts:[{id,fact}]}`，≤5条；owner仅取身份 |
| 未实现 | reasoning.delta、citation | 推理增量与独立RAG引用事件为后续设计 |

```ts
export interface EventBase { id: number; runId: string; stepId?: string; ts: string }

export type AgentEvent =
  | (EventBase & { type: 'run.started'; conversationId: string; messageId: string; model: string; mode: AgentMode })
  | (EventBase & { type: 'plan.created'; goal: string; steps: PlanStepView[] })
  | (EventBase & { type: 'step.updated'; stepId: string; status: StepStatus; summary?: string; durationMs?: number })
  | (EventBase & { type: 'reasoning.delta'; text: string })
  | (EventBase & { type: 'text.delta'; text: string })
  | (EventBase & { type: 'tool.call'; toolCallId: string; name: string; args: unknown; source: ToolSource; access: 'READ' | 'WRITE' | 'EXTERNAL_SIDE_EFFECT' })
  | (EventBase & { type: 'tool.result'; toolCallId: string; name: string; ok: boolean; resultPreview: string; durationMs: number; truncated: boolean })
  | (EventBase & { type: 'ui.card'; cardId: string; cardType: CardType; payload: unknown })
  | (EventBase & { type: 'approval.required'; approvalId: string; toolCallId: string; name: string; args: unknown; reason: string; expiresAt: string; editableFields?: string[] })
  | (EventBase & { type: 'approval.resolved'; approvalId: string; decision: 'APPROVE' | 'REJECT' | 'TIMEOUT' })
  | (EventBase & { type: 'citation'; sources: CitationSource[] })
  | (EventBase & { type: 'memory.used'; facts: { id: string; fact: string }[] })
  | (EventBase & { type: 'usage'; model: string; promptTokens: number; completionTokens: number; costEstimate: number; fallbackUsed: boolean })
  | (EventBase & { type: 'error'; code: number; message: string; recoverable: boolean })
  | (EventBase & { type: 'run.completed'; messageId: string; status: 'COMPLETED' | 'CANCELLED' | 'FAILED'; durationMs: number });

export type AgentMode = 'AUTO' | 'CAREER_DISCOVERY' | 'RESUME' | 'JOB' | 'INTERVIEWER' | 'COACH';

export type ToolSource = 'local' | `mcp:${string}`;
export type ExpertType = Exclude<AgentMode, 'AUTO'>;
export interface PlanStepView { id: string; title: string; agent: ExpertType; status: StepStatus; dependsOn: string[] }
```

## 19. MCP Server 工具定义（已实现）

使用 Spring AI **1.0.0** 的 WebMVC **SSE** 传输（[官方说明](https://docs.spring.io/spring-ai/reference/1.0/api/mcp/mcp-server-boot-starter-docs.html)），不是 Streamable HTTP：客户端连接 `GET http://localhost:8081/sse`，会话通知给出 `POST /mcp/message?sessionId=...`。两条传输路径的每个请求都必须携带 `X-API-Key`；`/mcp` 本身不是连接入口，也受密钥门禁保护。

### 启用与连接

默认关闭。通过后端进程环境设置：

```bash
MCP_SERVER_ENABLED=true
MCP_SERVER_API_KEY=<replace-with-a-random-secret>
```

`MCP_SERVER_API_KEY` 绑定 `offerpilot.mcp.server-api-key`；`spring.ai.mcp.server.enabled` 是装配开关。诊断与匹配沿用默认文字模型，需配置其供应商地址、Key 和模型名；搜索依赖 `JOBS_MCP_URL` 的既有 jobs-mcp 服务。未配置模型时返回明确错误，不生成虚构诊断。

先让客户端进程继承 `MCP_SERVER_API_KEY` 环境变量。Cursor 的 `.cursor/mcp.json` 可直接复制（[官方 url/headers 与环境变量插值说明](https://cursor.com/docs/mcp)；示例使用18081，可换成部署端口）：

```json
{
  "mcpServers": {
    "offerpilot": {
      "url": "http://127.0.0.1:18081/sse",
      "headers": { "X-API-Key": "${env:MCP_SERVER_API_KEY}" }
    }
  }
}
```

Inspector 0.16.2（Node 22，固定版本的 [CLI/自定义请求头说明](https://github.com/modelcontextprotocol/inspector/tree/0.16.2)）可直接列工具、执行搜索：

```bash
export MCP_SERVER_URL=http://127.0.0.1:18081/sse
# MCP_SERVER_API_KEY 由本地环境注入；不要把密钥写入命令历史或版本库。
npx -y @modelcontextprotocol/inspector@0.16.2 --cli "$MCP_SERVER_URL" --transport sse --method tools/list --header "X-API-Key: $MCP_SERVER_API_KEY"
npx -y @modelcontextprotocol/inspector@0.16.2 --cli "$MCP_SERVER_URL" --transport sse --method tools/call --tool-name jobs.search --tool-arg query=Java --tool-arg nature=campus --tool-arg limit=3 --header "X-API-Key: $MCP_SERVER_API_KEY"
```

### 实际注册的工具

| 工具名 | 参数 | 输出与只读边界 |
| --- | --- | --- |
| `resume.diagnose` | `resumeText` 必填，非空且 ≤50,000 字符；`jobDescription` 可选，≤20,000 字符 | `summary`、`overallScore: null`、`strengthsCount`、`issuesCount`、最多5条 `topIssues[{title,severity,ruleId}]`，按 HIGH/MEDIUM/LOW 排序；可选 JD 追加 `jobMatch{score,summary}`。不保存诊断或修改简历 |
| `jobs.search` | `query` 必填非空，≤100字符；`site` / `location` 可选，各≤60字符；`nature` 可选 `campus/intern/social/all`，不区分大小写，默认 `all`；`limit` 可选整数1–20，默认10 | `items[{id,url,title,company,locations,site,nature,source,snapshotDate?,excerpt,excerptTruncated}]`、上游 `meta`（来源站点/降级信息）、`fetchedAt`、`limit`、`truncated`。title/company/locations最多200个UTF-16字符；excerpt合并职责/要求并折叠空白，最多240个UTF-16字符（含省略号，截断不切开Unicode代理对）；url超过2048字符时为空。省略全文description/requirement，完整JD沿url或HTTP岗位详情读取。复用 HTTP 搜索，可刷新公开 jobs 缓存，不写用户看板 |
| `jobs.match` | `resumeText` 必填非空，≤50,000字符；`jobDescription` 必填非空，≤20,000字符 | `score`、`summary`、`requirements`（MET/PARTIAL/MISSING、JD引文、简历引文与建议）；不保存 `job_matches` |

参数超过上限或枚举不合法返回 `VALIDATION_FAILED`（10001），协议层以工具错误返回。文本会去除首尾空白，不访问简历 ID / 用户 ID。文本仅包装为 `{rawText: resumeText}`，没有虚构结构化教育或项目字段；匹配的 `resumePath` 引用 `/rawText`。基础诊断沿用线上无总分契约；可选 JD 的分数由独立 JobMatcher 计算，不能视作诊断总分。调用会把提供的文本发给配置的模型供应商。

### 安全边界与验证

密钥缺失、错误或服务端密钥为空/纯空白均返回 **401**；没有 Spring Security 会话登录要求。过滤器使用常量时间比较，并覆盖默认传输路径以及配置的 `base-url` / SSE 路径。JWT 与 `/api/v1/**` 原有鉴权和限流契约保持不变。

只注册上述三个工具，不暴露看板、职业档案、补丁采纳、成长任务等写工具，也不提供私有用户记录读取。API Key 代表服务访问权限，不绑定用户身份；现有用户 LLM 配额不适用于无用户上下文的 MCP 调用，当前未增加每 Key 限流。公网部署需在网关限制访问与调用频率。密钥只由环境注入，示例均为占位符，轮换后重启服务。

`McpServerHttpIntegrationTest` 在一次性 PostgreSQL、离线 ModelGateway/jobs-mcp 桩下启用服务器，使用真实 SSE 客户端初始化、列工具和调用三工具；验证 schema/描述、HTTP 缺失及错误密钥拒绝、参数错误、公开岗位缓存允许更新，以及用户业务表无写入。`OfferPilotMcpToolsTest` / `McpApiKeyFilterTest` 覆盖参数上限、关闭开关、空密钥拒绝和自定义传输路径。

## 20. jobs-mcp 工具定义（内部 MCP Client 使用，已接入）

> 本节保留已有内部工具契约；已接入证据来自 §1 / §7 已实现增量与 JobController 对应的站点、搜索、详情刷新路由。它们不是新增的 Spring 公共 HTTP 路由；输出 _meta 等字段由适配层裁剪，HTTP 字段以 §7 为准。

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `list_sites` | `{}` | `{ sites: [ { id, name, supportedNatures: [] } ] }` |
| `search_jobs` | `{ site?: string, query: string, nature: 'campus' \| 'intern' \| 'social' \| 'all', location?: string, limit?: number }` | `{ items: [ { id, site, company, title, category, nature, locations, department, updatedAt, url } ], _meta: { source: 'company-career-site', skipped: [] } }` |
| `get_job_detail` | `{ site: string, jobId: string, nature: string }` | `{ id, …, description, requirement, raw? }` |

两档模型增量（2026-10-10）：默认 FLASH → DeepSeek deepseek-flash，PRO → deepseek-v4-pro。`text.delta` 与结构化解析仅接收 content，不包含 reasoning_content。服务器默认深度思考开启，工具轮次关闭思考；`options.enableReasoning` 保留旧字段兼容，实际开关由服务器档位配置决定。会话 DTO 没有 tier 字段，仅消息保存实际模型名；前端聊天不持久化档位，URL modelTier/tier 的旧值统一规范化为 FLASH。


### AUTO规划的资源选择状态（2026-10-10）

规划模型与JOB动作模型使用同一份调用方资源选择状态：jobId/resumeId/resumeVersionId/applicationId仅传是否已选的布尔值（字符串非空且不超过80字符），实际ID仍由服务端绑定。AUTO不能在动作解析前因为用户未重复岗位名或ID而澄清已选择的资源；意图明确时交给专家解析，缺少必需选择仍澄清。没有指定可选阶段/备注仍可创建默认TODO的审批票据；写入必须APPROVE后执行。未扩充整句匹配规则，不把模型推断变成关键词路由，不改变HTTP/SSE结构。

### 显式聊天匹配动作（2026-10-10）

`POST /agent/chat` 的可选 `options.context.jobAction="match"` 配合 `{jobId,resumeId,resumeVersionId}` 在 AUTO/JOB 确定性执行 JOB/match；不依赖规划或JOB动作模型，最终报告/叙述仍使用原模型。资源ID只绑定 context，不接受步骤 inputs 的猜测ID。三标识必须为非空且不超过80字符的字符串；缺少选择、其它专家模式或同轮混入 boardAction/resumeAction/careerAction/interviewAction/coachAction 时返回流内可见 error，不执行任务或写入。匹配是 READ；看板等写操作仍必须通过现有HITL。

岗位详情入口只为一次发送带该动作，发送后保留资源ID并移除动作，后续普通提问不自动重匹配。只有资源上下文、没有 jobAction 的旧请求继续模型识别；完整三资源的 AUTO/JOB 若规划 fallback/澄清，error 明确未执行任务并提示补充请求或重新从岗位详情发起匹配。合法报告转换后的 job_match 若未通过32,768字符等卡片门禁，流内 error 明确报告无法展示，不以无卡 completed 结束。已有成功卡片ID的本轮重复事件仍按原规则去重。没有新增必填字段/事件类型/报告格式。

岗位匹配超时对齐（2026-10-10）：聊天匹配实际使用 options.modelTier（兼容旧调用方的默认档位），job_match 卡片契约不变；匹配专家步骤的外层总预算FLASH 90秒/PRO 210秒，覆盖模型60/180秒、岗位详情10秒和保存。PRO运行步骤提示「深度模式较慢」。入口所有者检查、证据校验及看板/简历写入HITL不变。

模型入口超时沿用504/40001但区分message：本地完整预算到期说明60/180秒上限；连接超时说明10秒连接上限；供应商HTTP504说明「模型服务返回等待超时」。客户端非JSON504说明反代等待超时，不透传供应商正文。

### 文本隐私设置（2026-10-10）

`GET /api/v1/privacy-settings` 返回 `{piiMasking:true}`（无偏好记录时默认开启）；`PUT` 接收相同结构，必填布尔值，仅更新当前认证用户的 `user_preferences.pii_masking`。不接受 userId。
`POST /api/v1/privacy-settings/check` 接收 `{text:"…"}`（最多64000字符），返回 `{detected:boolean,warning:string|null}`；检测手机号、校验码及日期有效的18位身份证、邮箱。只有关闭脱敏且检测到 PII 时有风险提示。不调用模型、不记录检查文本。
`POST /api/v1/resumes/privacy-check` 接收 multipart `file`（既有类型/10MB限制），关闭脱敏时读取文本并返回同一风险结构，不保存文件、不调用模型；开启时不解析文件。图片像素无 OCR 检测保证。设置页持久化开关；上传与聊天在送模型前检查并展示非阻断提示。
模型网关在供应商发送前统一替换文本 PII，跨 SSE 块还原后交给既有原文/数字/JSON Pointer 校验；原件、数据库和用户显示仍为原文。图片、姓名和地址不在此能力范围。
