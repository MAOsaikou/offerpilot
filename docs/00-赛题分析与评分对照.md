## 5. 「比赛环境」要求解读与 Java 后端可行性

赛方原文：

> 参赛作品须以前端 Web 应用为主要呈现形态，后端服务仅作为 AI 能力的接入层，不作为重点考察对象。鼓励充分利用现代前端框架的全栈能力简化后端逻辑。技术选型不做强制限定。

解读与结论：

1. **后端技术不受限**，Java 后端完全允许。评分表中没有任何一项针对后端语言或框架，后端只影响「AI 技术深度」的实现质量。
2. **重点仍在前端**：前端工程 10% + 用户体验 10% 直接考前端，AI 交互体验也在前端呈现。因此前端投入不得少于总工时的 40%。
3. **Java 后端的加分点**：Spring AI 2.0 对 MCP（官方 Java SDK 由 Spring 团队维护）、工具循环（可组合 `ToolCallingAdvisor`）、向量库、结构化输出、可观测性支持完整，便于把 Agent 内核做深；答辩时能清晰解释每一层。
4. **需要主动规避的印象风险**：不要把「后端很重」当卖点；文档与视频的叙事以「前端体验 + AI 能力」为主线，后端作为「AI 能力接入层」出现。

推荐技术栈对照（赛方推荐 → 本项目）：

| 赛方推荐类别 | 赛方示例 | 本项目 |
| --- | --- | --- |
| 前端框架 | React + Next.js（首选）、Vue 3 + Nuxt、React + Vite 等 | Vue 3 + Vite + TypeScript（团队熟悉 Vue；Java 承担全部 API，无需 SSR） |
| UI 与样式 | Tailwind CSS（强烈推荐）、shadcn/ui、Ant Design / Element Plus | Tailwind CSS 4 + shadcn-vue |
| 前端 AI 交互 | Vercel AI SDK、LangChain.js、Transformers.js、WebGPU、Web Speech API、MediaPipe | Web Speech API + MediaPipe（端侧）；自研 SSE composable（P2 兼容 AI SDK UI Message Stream） |
| 模型接入 | OpenAI、Claude、Gemini、智谱、DeepSeek；多模态 GPT-4o、通义千问 VL | 通义千问 Qwen3.8、DeepSeek V4、智谱 GLM-5.3（均 OpenAI 兼容协议） |
| 状态与数据 | Zustand / Pinia、TanStack Query、IndexedDB、WebSocket / SSE | Pinia、TanStack Query、SSE、IndexedDB（草稿与离线缓存） |
| 开发工具 | Cursor / Copilot、Figma / v0、Storybook、pnpm、ESLint + Prettier + TS | Cursor、Figma、pnpm、ESLint + Prettier + TS |

赛方特别说明「允许使用 AI 辅助编程工具，但选手须能清晰解释所有代码逻辑」—— 团队约定：每个 PR 必须由非作者成员评审并能复述实现思路；答辩前进行代码走读演练。

## 7. 结论

- 选题「求职与职业发展 Agent」与「AI Agent 智能助手」方向完全契合，且天然覆盖评分表六个 AI 子项（Agent、LLM、RAG、多模态、安全、MCP）。
- Java（Spring Boot 4 + Spring AI 2.0）作为 AI 能力接入层不违反任何规则，但前端投入必须充足。
- 11 周工期紧凑：P0 必须在 11-16 冻结，文档与视频与开发并行推进。
