## 2. 代码仓库

### 2.1 结构要求

- 根目录 `README.md`：项目简介、功能、架构图、技术栈、快速开始（Docker 与本地）、环境变量说明、体验账号、文档索引、数据来源与合规声明、团队信息、许可证。
- `.env.example`（后端 / Compose）与 `frontend/.env.example`：全部变量、注释、示例值；真实 `.env` 在 `.gitignore`。
- `docs/`：本套 00-11 文档 + `eval-results/` + 视频脚本 + PDF 源文件。
- `LICENSE`：MIT。
- `AGENTS.md`：模块边界、验证命令与自动化开发规则。

### 2.2 Git 历史

- 从 M0 起真实提交，不 squash 重写；提交信息遵循 Conventional Commits；三人均有持续提交（评审可查看贡献图）。
- 每个里程碑打 tag（`v0.1-m1` … `v1.0-province`）。
- 提交前检查：`gitleaks detect`；`git log --all -p | grep -i "api_key"` 抽查。

### 2.3 密钥与敏感信息核对

| 检查 | 方法 |
| --- | --- |
| 无 `.env` 被跟踪 | `git ls-files | grep -E '^\.env$|/\.env$'` 为空 |
| 无硬编码 Key | `gitleaks detect --source . --verbose` |
| 无真实个人简历 | 种子与测试简历均为虚构（姓名「林同学」「小北」等），并在 README 声明 |
| 第三方数据声明 | README「数据来源与合规」：企业官网公开接口、公开聚合仓库、O*NET 公共领域数据、公开许可面经 |

### 2.4 可复现性

- 新克隆 + `cp .env.example .env` + 填 Key + `docker compose up -d` 10 分钟内可跑通（在干净虚拟机上验证一次并录屏留档）。
- `README` 中「常见问题」：端口冲突、Docker 内存不足、模型 Key 无效的现象与处理。

### 3.2 写作要求

- 每个评分子项在文中可定位：在 §4 各小节标题后用括注标明对应评分点（如「4.6 MCP 双向集成（评分：MCP / 工具集成）」）。

### 4.2 制作规范

- 录屏：1920×1080、60fps、Chrome 无痕窗口、隐藏书签栏、字体缩放 110%；关闭通知。
- 数据：体验账号虚构数据；提前预热岗位缓存与模型，避免录制时等待；网络异常段落重录。
- 旁白：真人或 TTS（CosyVoice）均可；配字幕（SRT 烧入）；背景音乐音量 ≤ -25dB。
- 剪辑：等待超过 3s 的生成过程加速 2-4 倍并标注「已加速」；关键点用高亮框 / 缩放。
- 导出：H.264，码率 8-12 Mbps，AAC 音频；文件名 `OfferPilot-演示视频-1080p.mp4`；大小 ≤ 500MB（按赛方上传限制调整）。
- 校对：至少 2 人完整观看检查错别字、跳帧、音画同步。
