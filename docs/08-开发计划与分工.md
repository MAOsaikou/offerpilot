## 4. 协作规范

### 4.1 节奏

- 每日异步站会（群内三句话：昨天 / 今天 / 阻塞）；每周六 1 小时评审（演示 + 下周计划 + 想法池评估）。
- 每周日更新 `docs/02` 功能状态列与本文件的检查点。

### 4.2 Git

- 分支：`main`（可部署）、`dev`（集成）、`feat/<scope>-<desc>`、`fix/<scope>-<desc>`；PR 合入 `dev`，每周合 `main` 并打 tag（`v0.x`）。
- 提交：Conventional Commits；禁止 squash 覆盖历史（赛方要求真实开发过程）；禁止提交 `.env`、密钥、大文件（> 5MB 走 Git LFS 或 MinIO）。
- 评审：每个 PR 至少一名非作者评审；评审者须能复述实现思路（应对「选手须能清晰解释所有代码逻辑」）。
- CI 门禁：后端 `mvn -q verify`（含 Checkstyle、单测）、前端 `pnpm lint && pnpm typecheck && pnpm test`；失败不得合并。

### 4.3 文档同步

- 接口变更：先改 `docs/05`，再实现，PR 附 OpenAPI diff。
- 数据库变更：新增 Flyway 版本，禁止修改已合并的迁移。
- Prompt 变更：必须跑对应评测并在 PR 描述贴指标。
