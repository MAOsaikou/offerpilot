# 07 · 前端设计规范

## 知识库状态归属（2026-10-10）

KnowledgeView 通过 shared/api/knowledge 和 TanStack Query 读取当前身份的服务端笔记，支持分页、服务端搜索、编辑、确认删除与 Markdown 原文下载。加载、空列表、无命中、网络错误及重试均有独立状态；保存失败保留输入。搜索结果为最多 50 条的原文摘录，编辑/导出重新读取完整原文。身份切换清空表单、搜索与确认状态，迟到写响应不影响新身份。

workspace.notes 仅作为旧本地笔记迁移来源，不再接收新笔记。页面提示数量并提供 JSON 备份；点击导入后还需确认上传到当前身份，服务器逐批确认 imported + alreadyImported 后只清除该批未变化的本地副本。失败/冲突、未确认或途中改动的原件保留，刷新重试复用 sourceId 的服务器幂等凭据。跨设备需要同一账号，访客属于原身份；不会自动将访客笔记转给登录账号。


## 已存岗位详情回退（2026-10-10）

JobSourceBadge 区分人工离线快照、虚构 demo 岗位和 STORED_SNAPSHOT（实时更新不可用的已存企业岗位）。详情刷新直接消费服务端返回 DTO 写入当前 job 查询缓存，保留本次回退标记，不立即 GET 覆盖它；路由变更时拒绝迟到结果。已存副本仍可匹配并核对官网，demo/人工快照不提供实时刷新按钮。HTTP 字段兼容见05。


## 岗位来源标记（2026-10-10）

shared/components/JobSourceBadge 接收可选 source/snapshotDate/cached，搜索页、详情与聊天 JobSearchCard 共用。仅 source=LOCAL_SNAPSHOT 时显示低强调的「离线快照」tag，原生 title 含日期及“人工整理的示例岗位快照，非实时数据”；旁边文字始终可见，触屏也能了解来源。官网保留「企业官网 · 本次查询/近期缓存」。空快照结果也标记；快照更新时间展示为快照日期，不暗示企业当前在招。聊天来源随服务端 v2 卡片 meta 保存/恢复，旧载荷没有新增字段时兼容。


生产镜像装配（2026-10-10）：Docker 安装依赖前复制 `pnpm-workspace.yaml`，沿用仓库构建脚本许可并使用冻结锁文件；静态产物复制任务成功退出后 Caddy 才启动。

## 成长教练卡片（2026-10-10）

CardRenderer 注册 `skill_gap → features/growth/components/SkillGapCard`、`roadmap → RoadmapCard`，复用 shared/types/cards 既有载荷。技能卡显示规则等级进度、参考要求/差距、优先补齐与真实证据；无证据说明不代表没有能力，空核心技能显示引导。路线卡显示四周主题、六项固定任务、小时估计、资源文字、已完成状态及相对周次里程碑。

ChatPage 通过 ChatView 插槽接收 adoptGrowth 事件，发送 COACH 新轮次 context `{coachAction:"adoptGrowthPlan",taskTitles}`，自动打开执行面板并复用 ApprovalCard。默认没有勾选；用户只勾选确认已完成的任务，按钮「同步到成长任务」在选择后启用；卡片明确同步是合并完成记录并需批准，不直接 PUT career/tasks。已有完成项只读显示。忙碌/远端运行/会话不可用时禁用选择和提交；非交互场景隐藏操作，空路线给状态说明。离线和审批失败沿用聊天错误/重试与审批状态，刷新恢复持久化卡片；成长页面重读档案获得最新完成状态。技能/任务长文字换行，窄屏单列，checkbox 和 progress 有可访问名称、按钮至少44px。

## 聊天职业推荐卡片（2026-10-09）

CardRenderer 注册 career_recommendation→features/discovery/components/CareerRecommendationCard.vue；shared/types/cards 定义 CareerRecommendationPayload。卡片按排名显示职业名称、岗位族、Holland 码及规则理由，空结果引导调整兴趣。每行“设为目标”经 CardRenderer 事件和 app 的聊天 slot 传回 ChatView，发送当前职业的显式选择，不从卡片直接 PUT 档案。聊天忙碌/记录不可用时禁用操作，非交互卡片隐藏按钮；服务端推荐快照可在刷新后继续选择。

选择后自动打开执行面板；其他 WRITE 审批到达时也自动打开。复用 ApprovalCard 展示固定职业名称与批准/拒绝，不显示状态/备注编辑器；等待、倒计时、错误重试、运行结束不可提交与看板一致。窄屏沿用现有面板下排布局，职业行和按钮允许换行。目标写入后探索/成长页通过现有档案 GET 读取最新值。


## 文字面试练习服务端持久化（2026-10-09）

InterviewListView 通过 shared/api/interviews 与 Query 缓存读取/创建，InterviewRoomView 按路由 id 获取会话、题目快照和回答；服务端 DTO 独立放在 shared/types/interview。新练习不写 workspace.interviews，列表保留“本机旧练习”归档导出。新旧记录均可导出 Markdown，服务端记录使用保存的题目文本。

草稿通过“保存草稿”明确提交；上一题、下一题和离开房间先保存修改，成功后才更新进度/导航。失败显示可重试错误，保留回答和原位置；输入/切题在写入期间禁用，刷新前提示保存。最后一题提交后标记完成并显示原始回答，不生成 AI 评分。列表与详情提供加载、错误重试、空列表、404 状态；请求随路由/卸载取消，迟到结果不覆盖新会话；沿用身份切换取消请求/清缓存与页面重挂载。布局沿用 split-content、card-footer 的窄屏换行，不增加语音或 AI 面试官状态。

## 职业探索与成长状态归属（2026-10-09，P1-6）

DiscoverView 与 CareerView 经 `shared/api/career.ts` 读取当前用户服务端档案，共用 `useCareerProfile` 管理本页乐观状态。首次挂载及身份切换读取 profile；加载/读取失败期间禁用编辑，提供状态文字、错误横幅与重试。探索文本输入 400ms 防抖保存，设为目标/兴趣勾选及成长清单勾选立即提交。请求串行处理，迟到结果只确认保存时间，不覆盖新编辑；保存失败保留草稿并可重试。SPA 离页刷新待提交的防抖编辑，下一页读取等待已排队保存；身份切换清空旧草稿并拒绝旧身份队列写入新账号。

这两页仅使用 API 状态，不读取或双写 workspace 的 target/city/skills/interests/tasks；旧字段保留供其他页面过渡使用，原浏览器数据不自动导入。成长页聊天链接使用本页 API 档案的 target/skills。成长目录仍由已有 learningTasks 展示，与服务端六个标题一致。刷新或同账号其他浏览器重新打开页面可恢复服务器数据；访客仅能用原访客凭据恢复。加载、空档案及错误提示沿用响应式 panel/subtle/error-banner 样式。

## 客服账号列表分页（2026-10-09，S-11）

`/staff` 默认勾选「隐藏访客」，请求服务器分页（每页20条），切换访客过滤回到第1页；共计账号数取服务器 `total`，启用/禁用计数限于当前页。邮箱/昵称搜索仅过滤当前页，输入提示及说明均明确这一范围。上一页/下一页依据 `page/size/total` 启用，加载中禁止重复翻页及改变过滤；失败保留原页并显示可重试错误，沿用身份切换和迟到响应保护。空页、无搜索匹配及加载状态区分显示，分页导航有可访问名称；窄屏工具栏/分页换行、表格在自身容器横向滚动。


## 登录入口视觉统一（2026-10-08）

用户登录/注册与客服登录共用 features/auth/styles/auth.css，使用 §11 的雾白/墨蓝与深色令牌、Archivo 品牌字标、28px 简介标题、21px 表单标题、4px 基数间距、14px 面板及 8px 控件圆角。面板为不透明纸面和 1px 细线，无投影、玻璃、极光、渐变字、装饰光斑或循环装饰动画；取消登录页航线绘制，保留工作台唯一的装饰航线。移除虚构评分/匹配/Offer 悬浮数据及未经当前功能支持的“操作留痕”宣称。品红仅保留品牌既有航线、主操作和焦点环，辅助入口使用灰蓝文字。

桌面用户页为简介与表单两列，900px 以下收为单列，640px 以下缩小面板留白；客服页为单列表单。按钮、密码显示控件和辅助入口至少 44px 高，键盘焦点沿用 2px 令牌环；浅深色、加载、错误、注册切换和访客恢复说明均沿用认证契约。仅请求中显示加载转圈，遵守全局减少动态设置。认证 API、路由及身份持久化规则未变。

分支整合（2026-10-08）：简历定向改写与服务器岗位板共用既有账号/访客守卫及 shared 身份请求作用域。改写 SSE 也逐帧校验身份并随身份切换关闭；收藏、阶段和备注使用同一认证 Query 缓存。两个功能均允许有效原访客继续使用；JWT 失效需要重新认证，不以新访客替代旧数据。

## 认证与身份切换修复（2026-10-08）

客服管理合并回归修复：恢复登录页首次访客体验、明确继续原访客以及失效身份说明；生成或恢复访客前保留发起时身份，浏览器锁获准执行时再次检查，切换身份后取消排队操作。共享请求在发送前核对凭据，客服管理 GET/PATCH 与其他认证请求共用取消信号及迟到正文校验。客服页在提交结果或处理错误前检查原身份作用域，旧校验与旧请求不能注销新账号；网络故障显示可重试错误，保留登录。登录期间禁用模式切换，返回业务页只接受单斜杠开头的站内路径；访客说明与按钮在窄屏纵向排列，登录背景在固定边界内裁剪，避免装饰动画产生横向滚动。本次保留合并的其余视觉效果，其与 §11 的偏差仍需后续统一。

登录页支持邮箱密码登录/注册、首次访客体验及明确继续已有访客。密码注册创建独立账号，不自动迁移访客数据；已有访客刷新业务页保持原身份。JWT、用户摘要和访客令牌持久化于 localStorage，认证 API/DTO 与 QueryClient 放在 shared，统一 useAuthStore 管理用户及客服登录。客服入口 `/staff/login`，工作台 `/staff` 要求 STAFF；表单不预填凭据，有加载、错误、退出和窄屏状态。

侧栏身份摘要区分账号“已登录”和“访客体验”；数据保存说明明确草稿在当前浏览器，求职看板、文字面试练习、上传简历、对话和匹配报告在服务端。

JWT 当前有效期 12 小时；浏览器按 exp 安排失效并由服务端校验签名。失效/当前请求 401 后路由返回相应登录页并保留来路，不自动调用 refresh、重放请求或切换到访客。旧访客令牌保留，有效时用户可明确恢复；失效时说明访问限制且不新建替代身份。注销时先写入重新登录标记，再移除 JWT，防止另一标签在存储事件间隙创建新访客或静默回退已有访客。登录、注销、跨标签身份切换均取消请求、关闭旧 SSE、清除服务器 Query 缓存并重新挂载页面，旧页面私有状态及迟到响应正文和事件不显示给另一身份。本地 workspace 按身份保存，切换或失效时同步卸载旧内存状态与持久化监听，重新加载当前身份的数据并重算存储错误；同一身份返回时恢复其浏览器草稿。刷新 Cookie 和访客迁移仍为后续规划。

本地身份隔离（2026-10-09，P1-1）：简历草稿、面试答案、知识笔记、学习任务及旧岗位归档使用 `offerpilot-workspace-v1:<identity>`。账号采用 `user:<编码后的用户 ID>`，缺少用户摘要时采用 JWT 的稳定 64 位指纹，不将原 JWT 放入键；访客采用 `guest:<编码后的有效凭据>`，注销或无有效身份时采用 `anonymous`，不静默加载保留的访客数据。旧无后缀键只归属升级时首次打开工作区的身份：目标键不存在且旧内容通过结构校验才复制，成功后移除旧键；迁移归属单独保留，损坏旧内容、已有目标或迁移失败不会使后来身份继承旧数据，也不覆盖损坏原文。

## 看板状态归属更新（2026-10-04）
真实岗位收藏、应用阶段和跟进备注由服务端保存，替代本文较早的本地看板说明。岗位搜索/详情、BoardView 和工作台航线统一使用 shared/composables/useBoard、shared/api/applications 和 TanStack Query applications 缓存，DTO 位于 shared/types/board，不混入本地 workspace 模型。加载期间显示提示，读取失败显示重试并阻止收藏；写入期间禁用相关操作，成功后更新共享缓存并失效读取，失败显示可重试错误且保留原阶段和备注草稿。备注通过“保存备注”明确提交；有未保存备注时暂禁阶段移动，避免跨列卸载丢失草稿。五列与既有窄屏样式保留，不增加拖拽、面试或规划功能。
旧 workspace applications 作为本地归档保留并仍可导出，不自动覆盖服务器数据；示例岗位只读，不再新增本地收藏。真实旧岗位可从搜索/详情重新收藏。跨浏览器恢复要求同一已有身份；新访客不会看到其他身份的数据。收藏和状态变更不发送真实投递。


## 聊天改写入口与恢复（2026-10-03）

岗位详情在选定已加载保存版本后提供「在聊天中改写」，带 mode=RESUME、jobId/resumeId/resumeVersionId 与可编辑提示语，不自动发送。生成后的 resume_diff 在聊天中支持逐条选择、编辑和事实确认；按钮「审批采纳所选建议」经 ChatPage → ChatView 插槽发送 RESUME 聊天 context（resumeAction=applyPatches、resumeId、resumeVersionId、batchId、accepted、edited、confirmed），打开现有审批面板。批准后保存新版本，拒绝/超时不写；卡片不直接调用 REST。空建议提供「查看改写记录」。URL带 tab=optimize/resumeVersionId/optimizationReportId；面板直接读取该报告和批次，无再次生成或自动采纳，检查简历/版本绑定后才显示。关联优先取当前卡片，其次路由及同版本优化上下文；缺简历/版本/批次时显示可见错误并停止发送。忙碌或会话不可用时禁用选择及提交。旧卡片不构造失效链接。

后续聊天优先保留用户明确的报告选择，否则从本会话可见卡片中关联与已选简历/版本一致的最新改写报告，作为讨论上下文；不替换不同简历/版本的选择。options.context 与当前URL保留 optimizationReportId，刷新恢复卡片与关联提示；明确重新生成由本轮动作解析决定，携带旧ID不触发生成。改写面板「带着建议继续讨论」传递保存报告/版本并预填不重新生成的提问。报告或批次读取失败显示可重试错误，未完成、跨简历深链拒绝显示；采纳仍遵循当前版本/无草稿/逐条确认规则。桌面与390px视口沿用聊天滚动区、窄屏按钮换行，无横向溢出。

## 岗位定向改写与采纳（2026-10-03）

## 1. 技术栈与版本

当前会话工作区：桌面提供历史栏，1000px 以下以“历史会话”按钮展开；支持新建、切换、重命名、置顶、单个删除确认、列表分页和更早消息加载。URL 使用 `/chat/:conversationId`，刷新后恢复服务端记录。服务端 DTO 位于 shared/types/conversation.ts，API 位于 shared/api/conversations.ts，交互状态由 features/chat/composables/useConversationChat 管理，与本机工作区模型分开。

对话页组件拆分（2026-09-26）：`app/views/ChatPage` 组合 `features/chat/views/ChatView` 与 widgets（AgentPanel、CardRenderer）。ChatView 只负责路由同步、发送与滚动，界面由同 feature 的 `ChatToolbar`（历史开关、会话标题、执行过程开关）、`ConversationHistory`（会话列表；重命名、删除确认等局部状态在组件内，保存与删除通过 props 传入的异步函数完成）、`ChatWelcome`（空会话建议）、`MessageList` 与 `Composer`（模式与档位通过 `tools` 插槽放入输入框工具栏）组成。首条消息发送后，服务端会把“新对话”改写为内容摘要；前端刷新会话列表时同步当前会话，标题无需刷新页面即可更新。新会话在创建后立即刷新一次列表，回复生成期间历史栏就能看到它，不再显示空状态。

卡片保留（2026-09-26）：回复结束后，前端用服务端记录替换临时消息。服务端在运行结束时把本轮已发出的卡片写入消息 `parts`。聊天只有在请求或步骤里带齐岗位、简历和版本标识并成功匹配时才发出 `job_match`；其他专家仍不发卡片，刷新后通常还是只有文字。`job_match` 由现有 `MatchReport` 渲染：有分数和 `matched`/`gaps`/`advice` 数组，没有 `dimensions` 时不画维度条。本页会话内仍按 runId 保留该轮已渲染的生成式卡片与思考摘要，切换会话后再回来仍可见；刷新页面后，只有服务端消息 `parts` 中带 `{type:'card', cardId, cardType, payload}` 的卡片（docs/05 §3）会恢复。前端已兼容读取，缺少 `cardId` 时用消息 id 和序号兜底。

加载中、空会话、不可访问、网络失败均有明确状态；切换会话用请求版本号忽略迟到响应。发送前创建会话，结束后与服务端记录核对，避免重复气泡；不自动重试 POST。FAILED/CANCELLED 保留部分回复并提示不进入后续上下文，允许重新编辑问题。恢复时遇到 RUNNING 每 2 秒更新当前会话并允许取消；轮询离开页面即停止。访客凭据失效不静默创建新身份。开发 Mock 仅为临时脚本演示，不宣称保存历史。

## 7. SSE 消费：`useAgentStream`

```ts
// shared/composables/useAgentStream.ts（节选）
export function useAgentStream() {
  const runStore = useAgentRunStore();
  let controller: AbortController | null = null;

  async function start(body: ChatRequest, opts: { onEvent?: (e: AgentEvent) => void } = {}) {
    controller = new AbortController();
    const res = await fetch(`${API_BASE}/agent/chat`, {
      method: 'POST', headers: authHeaders({ 'Content-Type': 'application/json', Accept: 'text/event-stream' }),
      body: JSON.stringify(body), signal: controller.signal,
    });
    if (!res.ok || !res.body) throw await toApiError(res);
    let lastId = 0; let runId = '';
    for await (const frame of parseSse(res.body)) {          // 解析 id/event/data 帧，忽略 ": ping"
      const event = JSON.parse(frame.data) as AgentEvent;
      lastId = frame.id ?? lastId; runId ||= event.runId;
      apply(event); opts.onEvent?.(event);
      if (event.type === 'run.completed' || (event.type === 'error' && !event.recoverable)) break;
    }
    return runId;
  }

  function apply(event: AgentEvent) {
    switch (event.type) {
      case 'run.started': runStore.begin(event); break;
      case 'plan.created': runStore.setPlan(event.runId, event.steps); break;
      case 'step.updated': runStore.updateStep(event.runId, event.stepId, event.status, event.summary); break;
      case 'reasoning.delta': runStore.appendReasoning(event.runId, event.text); break;
      case 'text.delta': runStore.appendText(event.runId, event.text); break;
      case 'tool.call': runStore.addToolCall(event); break;
      case 'tool.result': runStore.resolveToolCall(event); break;
      case 'ui.card': runStore.addCard(event); cardSideEffects(event); break;   // 如 board_update → setQueryData
      case 'approval.required': runStore.addApproval(event); break;
      case 'approval.resolved': runStore.resolveApproval(event); break;
      case 'citation': runStore.addCitations(event); break;
      case 'memory.used': runStore.setMemoryUsed(event); break;
      case 'usage': runStore.setUsage(event); break;
      case 'error': runStore.setError(event); break;
      case 'run.completed': runStore.complete(event); break;
      default: assertNever(event);   // 新增事件类型时编译期报错
    }
  }

  function stop(runId: string) { controller?.abort(); api.POST('/agent/runs/{runId}/cancel', { params: { path: { runId } } }); }

  return { start, stop };
}
```

要点：

- 使用 `fetch` 而非 `EventSource`（需要 POST 与自定义头）。
- `text.delta` 累积到 store 的 `streamingText`，`MarkdownStream` 以 `requestAnimationFrame` 节流渲染（每帧最多一次），完成后做一次完整渲染。
- 当前 `useAgentStream` 暴露 `start`、`stop` 和 `streaming`，不提供 SSE 续传。网络中断由 `useConversationChat` 重新读取会话消息；存在 RUNNING 消息时每 2 秒轮询，恢复持久化正文、状态和卡片。后端没有 events 续传接口，Plan/工具事件不回放。
- 审批：`ApprovalCard` 提交后调用 REST，流继续；倒计时到期显示「已超时」。

## 10. 多媒体与端侧 AI

### 10.1 语音（`useSpeech`）

- ASR：`webkitSpeechRecognition` / `SpeechRecognition`，`lang='zh-CN'`、`continuous=true`、`interimResults=true`；中间结果灰色显示，最终结果追加；无声 3s 自动结束一段。
- TTS：`speechSynthesis`，优先选择 `zh-CN` 女声；播放期间暂停 ASR 防回环；`voiceAutoPlay` 偏好控制。
- 能力检测：不支持时隐藏语音入口并提示使用 Chrome / Edge。
- Web Speech lite 已接入 `shared/composables/useSpeech.ts` 与 `InterviewRoomView`：最终字幕追加到现有 `answer`（最多 12000 字符），通过既有 `saveInterviewAnswer` 保存，不增加评分路径。保存、切题和离开前等待识别收尾（最长 1s）；离开或卸载取消语音，旧回调不写入下一题。麦克风权限被拒后禁用口述并提示文字作答；自动朗读默认关闭，以 `offerpilot.voiceAutoPlay` 保存显式偏好。女声按浏览器可用音色名称优先选择，无匹配时使用默认音色。此阶段不接入 MediaPipe 或录音归档。
- 可选录音：`MediaRecorder`（`audio/webm;codecs=opus`），用户勾选「保存录音」时上传。

### 10.2 端侧视觉（`useMediaPipe`）

- 在 Web Worker 中加载 `@mediapipe/tasks-vision`（wasm 与模型文件放 `public/mediapipe/`，首次使用时按需下载，约 10MB，显示进度）。
- 主线程用 `OffscreenCanvas` / `ImageBitmap` 每 500ms 传一帧；Worker 返回 `{ eyeContact, smile, headStability, postureStability }`。
- 指标计算：视线（虹膜相对眼眶位置）、微笑（blendshapes `mouthSmileLeft/Right`）、头部稳定（关键点位移方差）、姿态稳定（肩部关键点位移）。
- 隐私：视频流仅在浏览器内；UI 常驻「视频不会上传」标识；摄像头权限被拒时静默降级。

## 11. 设计系统：「航图」（2026-09-26 改版）

产品名「职航」本身就是导航隐喻。飞行员的行话是“沿品红航线飞”：机载导航屏上，当前生效的航线用品红色画出。界面借用这一点：冷雾白的底图、墨蓝色文字，全站只有一种强调色，即航线品红，并且只用来标出“你现在走到哪、下一步做什么”。其余元素保持安静、克制。

### 11.1 配色（令牌定义在 `shared/styles/index.css`）

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--background` 雾白 | `#F2F4F3` | `#0F1623` | 页面底色 |
| `--card` 纸面 | `#FFFFFF` | `#161F30` | 面板、输入框 |
| `--foreground` 墨蓝 | `#15213B` | `#E7ECF3` | 正文、标题 |
| `--muted-foreground` 灰蓝 | `#586377` | `#9AA6B8` | 辅助文字（对比度 ≥ 4.5:1） |
| `--border` 细线 | `#DCE1E5` | `#29364B` | 分隔线、描边 |
| `--primary` 航线品红 | `#B01A6E` | `#EF5DA8` | 主操作、当前导航、进行中状态、流式光标、焦点环 |

语义色：成功 `#1E7A4F`、警告 `#9A6300`、危险 `#B83A1E`（深色下相应提亮）。品红不用于装饰性背景、渐变或大面积色块；同一视图里品红元素应少于三处。不使用玻璃拟态、极光光斑或渐变描字。

### 11.2 字体

- 中文与正文：系统无衬线栈 `PingFang SC → HarmonyOS Sans SC → MiSans → Microsoft YaHei UI → Noto Sans SC`，不额外下载中文字体。
- 拉丁字母与数字：`Archivo Variable`（`@fontsource-variable/archivo`，自托管，只按 unicode-range 加载拉丁子集）。品牌字标使用 125% 字宽、800 字重；计数类数字使用 88% 字宽、600 字重、`tabular-nums`。
- 字号阶梯：12 / 13 / 15（正文）/ 17 / 21 / 28 / 40（仅工作台问候）。正文行高 1.65，标题 1.3。长文阅读区（对话、报告）行宽不超过 72 字符。
- 不使用全大写英文标签、英文眉标，也不在按钮或链接文字后面追加 `→`、`↗`。辅助信息优先用短句表达，不用 `A · B · C` 拼接串。

### 11.3 间距、圆角与层级

- 间距以 4px 为基数：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64。
- 圆角按层级区分：容器 14px、控件 8px、标签 4px，头像与状态点为圆形。不给所有元素套同一个圆角。
- 面板默认是平的：只有 1px 细线，没有阴影。只有浮层（对话输入框、移动端抽屉、确认框）带墨蓝色投影 `0 12px 32px -12px rgb(21 33 59 / .18)`。
- 布局：桌面端左侧是 232px 的浅色“航线栏”（字标、新对话、导航、数据保存说明、通知与设置），不再单独设顶栏；900px 以下航线栏收为抽屉，顶部显示 56px 标题栏。内容区左对齐，最大宽度 1280px。

### 11.4 标志性元素：航线

工作台首屏展示“你的航线”：把本地看板按 收藏 → 已投递 → 面试中 → Offer 画成一条航线，每站显示数量，品红线段画到当前走得最远的一站；“已结束”放在航线外侧。这是全站唯一的装饰性动画，只在进入工作台时绘制一次。

### 11.5 动效规则

动效只做两件事：回应用户操作，以及说明发生了什么变化。

| 场景 | 规则 |
| --- | --- |
| 时长 | 快 120ms（hover 颜色、按下）；中 200ms（进入、展开）；慢 700ms（仅航线绘制） |
| 缓动 | 进入用 `cubic-bezier(.2,.8,.2,1)`，退出用 `ease-in` |
| 页面进入 | 路由切换时新页面淡入并上移 6px，用时 200ms；导航不再等待整屏柔雾（原 StageCurtain 已移除） |
| 列表错位出现 | 仅用于用户操作后到达的列表（会话列表、搜索结果、卡片网格）：每项延迟 30ms，最多错开 8 项 |
| hover / 按下 | 按钮按下缩放到 0.97；导航与列表行 hover 只变背景色；卡片 hover 不上浮 |
| 流式消息 | 新消息淡入并上移 8px，用时 180ms；流式输出末尾显示品红光标，1s 闪烁一次 |
| 卡片出现 | CardRenderer 外层从上往下展开（clip-path），同时淡入，用时 260ms |
| 状态点 | 执行中的步骤或工具调用显示品红呼吸点，其余状态点静止 |
| 减少动态 | `prefers-reduced-motion: reduce` 时，全局把动画和过渡压到 0.01ms，光标不闪烁，航线直接显示完成态 |

### 11.6 其他

- 响应式断点：`640 / 900 / 1200`；1200px 以下对话执行面板改为按需展开，900px 以下航线栏收为抽屉。
- 状态设计：每个数据视图必须有加载、空、错误三种状态；AI 生成中显示流式光标与「停止接收」按钮。
- 无障碍：所有交互元素可键盘到达，`:focus-visible` 显示 2px 品红焦点环；图标按钮带 `aria-label`；流式区域 `aria-live="polite"`。触屏设备（`hover: none`）上，会话操作按钮常显。
- 图标：`shared/components/AppIcon.vue` 内置 1.7px 线性图标，统一 16 / 18 / 20px。

## 13. 代码规范

- TypeScript：`strict`、`noUncheckedIndexedAccess`、`noImplicitOverride`、`exactOptionalPropertyTypes`；禁止 `any`（用 `unknown` + 类型收窄）。
- Vue：`<script setup lang="ts">`；`defineProps` / `defineEmits` 泛型写法；组件文件 PascalCase；组合式函数 `useXxx`；单文件 ≤ 300 行，超出拆分。
- 导入：全部置于文件顶部，禁止函数体内动态 `import`（卡片注册表与路由懒加载的 `() => import()` 例外，且集中在注册文件）。
- 联合类型 `switch` 必须有 `default: assertNever(x)`。
- 样式：仅 Tailwind 类与 `@theme` 变量；避免 `<style>` 中写全局样式；类名合并用 `cn()`（clsx + tailwind-merge）。
- 命名：事件 `onXxx` / `emit('xxx')` kebab-case；store 状态名词、动作动词。
- ESLint flat config：`eslint-plugin-vue` recommended + `@vue/eslint-config-typescript` strict + `eslint-plugin-import` 顺序规则；Prettier 负责格式。
- 提交：Conventional Commits（`feat(chat): …`）；`lint-staged` 跑 eslint --fix 与 prettier。
