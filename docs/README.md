# OfferPilot 文档导航

本目录同时服务三类读者：第一次接触项目的开发者、正在实现功能的开发者，以及准备比赛材料的项目成员。文档数量较多时，不建议按编号从头读到尾，应按下面的阅读路径使用。

截至 2026-09-28，进度按用途分层记录；日常更新以功能清单、开发计划和测试记录为准，日期审计用于留档，不能代替代码验证。

- [02-需求分析与功能清单.md](02-需求分析与功能清单.md)：持续维护逐项需求状态；“进行中”表示已有部分实现但完整验收标准尚未满足，“完成”才表示该条验收成立。
- [08-开发计划与分工.md](08-开发计划与分工.md)：里程碑和周计划，并在顶部记录最近核实的项目进展与当前主要阻塞。
- [10-测试与评估方案.md](10-测试与评估方案.md)：测试计划、每次验证的范围与结果，以及真实模型评测边界。

## 第一次接触项目

1. 阅读 [12-项目架构与源码导读.md](12-项目架构与源码导读.md)，先区分“当前已经实现的代码”和“规划中的目标架构”。
2. 阅读 [02-需求分析与功能清单.md](02-需求分析与功能清单.md)，了解产品要解决什么问题。
3. 阅读 [03-系统架构设计.md](03-系统架构设计.md)，理解模块边界和数据流。
4. 根据准备开发的区域，继续阅读接口、数据库、AI、前端或部署文档。

## 文档边界

- README 回答“项目是什么、怎样启动”。
- 需求文档回答“应该实现什么、怎样验收”。
- 架构文档回答“模块怎样划分、依赖怎样流动”。
- AI 方案回答“模型与 Agent 怎样工作”。
- 接口文档回答“前后端传什么”。
- 数据库文档回答“数据怎样保存”。
- 前端规范回答“页面与状态怎样组织”。
- 部署文档回答“服务怎样运行”。
- 测试文档回答“怎样证明它正确”。
- 源码导读回答“当前仓库实际上已经有什么、每个文件怎样参与运行”。

如果设计文档与实际代码不一致，先确认这是“尚未实现的规划”还是“代码变更后文档漏改”。不要仅凭规划文档判断功能已经存在。
