# OfferPilot 项目完成度审计

日期：2026-09-28。基准：本次工作区当前源码（包括用户尚未提交的简历诊断等改动），不是仅看 Git HEAD，也不是沿用历史文档的完成标签。

## 结论与评估口径

当前是“已有若干真实后端闭环的开发中产品”。聊天、简历解析/版本、基础内容诊断、岗位搜索和匹配是主要成果；完整的多专家求职闭环尚未完成。页面数量和测试通过率不能替代业务完成度。

采用 0–4 阶段评估，避免没有验收权重支撑的精确百分比：0=未见可执行实现；1=页面/类型/占位；2=部分逻辑或本地功能可用；3=服务端闭环和工程回归成立，仍有范围/质量验收缺口；4=约定范围及真实质量、运行验收齐全。这是阶段，不代表 3/4 就完成了 75% 工作量。

## 各模块完成度与缺口

### 1. 账号、身份与偏好：2/4

已完成访客凭据创建、受检接口所有者校验、浏览器身份保存和模型偏好持久化。聊天/简历/报告的跨用户隔离有集成测试。

未完成邮箱密码注册登录、access/refresh 完整生命周期、体验账号每日重置、跨设备恢复。登录页目前是进入本地工作区。清除浏览器凭据或凭据过期后没有正常用户自助恢复链路。

证据：`GuestIdentityService`、`CurrentUser`、`LoginView.vue`、`client.ts`。SecurityConfig 放行 `/api/v1/**`，现有业务控制器自行校验访客；这不等于这些接口已验证可越权，但新增接口很容易漏掉手动检查，应统一认证边界。

### 2. 基础聊天与会话：3/4

已实现真实模型适配器、SSE、持久化多轮历史、分页、新建/重命名/置顶/删除、取消、用量事件、所有者隔离、历史卡片恢复；相关单元和 HTTP 集成通过。

未完成通用图片附件、Last-Event-ID 续传及运行回放。前端 `resumeAgentRun()` 请求 `/agent/runs/{id}/events`，后端 AgentController 只有 chat/cancel，不能把“刷新读取历史”说成“断线续传”。真实模型首 token P95 和内容质量本次未评测。

### 3. Orchestrator 与专家：2/4

意图识别、计划校验、依赖顺序执行、失败跳过、plan/step/tool 事件已实现；已有真实 `diagnoseResume`、`matchJobToResume` 两条业务接入，需要明确真实资源上下文。

职业探索、面试官、成长教练仍返回“占位专家”；岗位专家没有完整资源 id 时也占位，未自动调用岗位搜索；简历专家无保存版本时只提示选版本。不存在完整的“探索→搜索→改写→投递→面试→规划”自主执行闭环。通用工具循环、反思重规划、写操作审批尚未完成。

证据：`ExpertRegistry.java`、`Orchestrator.java`、`IntentPlanner.java`。

### 4. 审批、续传和生成式卡片：1/4

有事件类型、状态归约、时间线和卡片组件。17 种 CardType 仅注册 5 种：resume_diagnosis、job_match、job_evidence_match、resume_diff、board_update；其他走 JSON fallback。拥有渲染组件也不说明生产方已实现。

ApprovalCard 只展示状态和参数，没有批准/拒绝/编辑提交控件；后端无审批提交、挂起恢复、超时决策接口。resume_diff 的“采纳”只在组件中切换集合，页脚明确标注 apply-patches 接口待接入。

文件存储、异步 worker、文字/图片模型路由、状态轮询、失败重试、租约恢复、迟到结果隔离、文件安全校验已实现。工程测试覆盖 PDF/DOCX/图片/TXT 等读取、真实上传 HTTP、存储与版本写入。
