# 登录后页面移动端与桌面性能（2026-10-11）

## 范围与口径

- Before：`226ec8e`，普通 `pnpm run build` 产物，冻结为 `/tmp/offerpilot-perf-before`。After：本分支的路由首屏滚动、字体与加载骨架优化，仍使用普通生产构建，无 mock 环境变量。
- 同一机器：Node 22 / Vite 8.3.0 / Lighthouse 12.8.2 / HeadlessChrome 154，按页面依次串行测量，没有同时跑构建、测试或其他本任务的 Lighthouse。每次新建隔离 Chrome，Lighthouse 清 HTTP 缓存；只保留虚构登录 localStorage，不使用真实凭据。
- 本地 loopback gzip 静态服务器 + **Node HTTP fixture 后端**，每个 fixture 响应固定等待100ms；无 Docker/Postgres、无模型、无真实招聘站点。fixture 为虚构 USER、3份 READY 简历、8个岗位、5种看板状态、1场5题进行中面试、1段含 `job_card` / `job_match` / `board_update` 三张卡的聊天。页面运行真实路由守卫、Query、卡片异步注册、Markdown 与布局。
- 现有 MSW 只覆盖聊天 SSE，且仅 DEV 启用。本轮 fixture 服务在 Node 进程中，**不改变应用生产入口，不向生产包加入 mock**。harness 扫描生产 JS 不含 fixture / MSW 场景标记；生产页面使用普通 HTTP API。仓库原有 `public/mockServiceWorker.js` 仍作为未引用静态文件复制到 dist，未注册、未加载，不计入传输。
- Mobile 使用默认预设（412×823、DPR1.75、模拟4×CPU、150ms RTT、1638.4Kbps）；desktop 使用官方 desktop config（1350×940、DPR1、模拟1×CPU、40ms RTT、10240Kbps）。每页/每预设各3次，**各指标独立取中位数**；不是选择最好的一轮。harness调试与单次候选探索不纳入正式表，正式表没有按分数剔除任何一轮。
- 页面：`/`、`/chat/conv_perf`、`/resumes`（列表，不含编辑器/PDF导出）、`/jobs?q=Java`（有搜索结果）、`/board`、`/interviews/iv_perf`（有题目，不启用麦克风）。独立390×844/1280×844截图走查不计入分数。
- JS transferred 为 Lighthouse network 中所有 `Script.transferSize` 之和，包含入口、共享、路由与已请求的卡片/Markdown块以及 HTTP 头；不是 Vite 的入口 gzip 大小。不包含字体/CSS/API。
- 不代表真实后端/网络/CDN/TLS、真实移动硬件、SSE流式生成、INP、长对话或真实用户体验。三个卡片确实渲染，但聊天内部滚动容器的首屏 LCP 可能是工具栏/页脚；不把聊天分数当作卡片滚动/流式渲染性能。

## 测量驱动的改动

1. **移除首次文档导航的重复滚动。** Before 的 `forced-reflow-insight` 把强制布局指向 vue-router 的 `window.scrollTo`，工作台首轮约563ms。新文档无历史位置时本来就在顶部，跳过该调用；站内导航仍返回 `{top:0}`，历史恢复仍返回原 savedPosition。仅增加1项回归守住三条路径。After 正式三轮工作台该诊断无强制布局条目。
2. **保留字形的字体拆分与提前加载。** 全部字重/宽度轴不变，将常用 ASCII、NBSP、中点、乘号及标点单独子集，原Archivo字体仍覆盖其他拉丁/越南文，中文仍为系统字体。测量页面的字体请求从90,403B降到53,925B（含HTTP头），省36,478B（约40.3%）；preload去掉“CSS → 首次布局 → 字体”的晚请求链。子集生成脚本、OFL许可与来源一并保留。全量构建字体资产总大小增加53,636B，因为保留完整语言覆盖；实际测量页面只请求子集，不宣称全包变小。
3. **预留加载布局。** 工作台使用相同航线结构与高度，加载计数对辅助技术隐藏，提供status/aria-busy；简历首读预留三张普通卡片的高度，减少本地草稿区被远程列表推移。真实条数、长标题或错误状态不同仍可能产生偏移，不承诺任何数据下CLS都为0。
4. **保留既有按需加载。** 路由和卡片本就异步；本轮数据没有发现图表/PDF/高亮库被全站入口提前加载，没有为了拆包增加新的异步瀑布，也没有修改未测量的SSE逻辑。

## 可引用口径与剩余限制

“六个登录后页面，本地生产gzip静态构建 + 虚构HTTP后端，每页mobile/desktop各3次中位数。移动端 Performance 66–89→93–97，桌面94–99→100，A11y/BP均100；工作台与简历列表CLS降至0，移动端LCP分别3.18→2.29s、2.97→2.17s。” 必须同时写明虚构后端条件及范围，不能将本地fixture结果作为线上成绩。历史 [2026-10-10登录页记录](2026-10-10-Lighthouse前端性能.md) 仍只证明当时的desktop登录页；当前机器六页mobile预设正常出分，不回填旧记录的NO_FCP。

LCP预算2.0s是目标，本轮移动端中位数2.17–2.75s，**仍未达到该预算**；真实后端延迟、SSE/INP及公网部署仍须另测。
