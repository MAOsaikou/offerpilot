## 本轮写入与额度

- 只处理本轮自己创建的审批。目标审批拒绝；历史未决审批未修改。
- 自然语言“把这个投递的阶段改成面试中，备注：已约一面”在新请求中出现模型超时，没有进入写入。只读运行证据记录 40001，recoverable=false。
- 随后标准 API 用明确 `boardAction=updateApplicationStatus` 创建自己的票据，APPROVE HTTP 200；界面确认 INTERVIEW 后以 PATCH 恢复原 APPLIED，HTTP 200。此路径证明后端写入，恢复聊天的面板当时为空闲，没有把空面板作为审批图。
- 最终截图 07 改用真实 UI 的明确收藏指令，从 MCP 搜索结果选取 Baidu 岗位，新建自己的审批并批准，新增一条 TODO 收藏。原机会未被删除，新增记录留在演示账号。
- 日额度从 PostgreSQL 只读查询为 200000。UTC 当天 Redis 计数在采集期间先读到 10299，后读到 80250；因共享账号还有并行调用，差值不作为本轮用量。没有重置计数或读取 / 打印密钥。额度计数是已记账量，不保证正在进行的请求不会越界。
