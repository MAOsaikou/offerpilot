# 09 · 部署与运维

## MCP Server（2026-10-10）

默认 `MCP_SERVER_ENABLED=false`。启用时通过后端进程环境提供 `MCP_SERVER_ENABLED=true` 与非空 `MCP_SERVER_API_KEY`，并配置现有文字模型/jobs-mcp。Spring AI 1.0.0 使用 SSE：反向代理需转发 `/sse` 与 `/mcp/message`，传递 `X-API-Key` 并禁用 SSE 缓冲；公网使用 HTTPS。空密钥拒绝所有 MCP 调用，轮换密钥后重启。当前无每 Key 限流，在网关限制调用频率；真实密钥禁止进仓。完整 Cursor/Inspector 配置和三个只读工具见 [05 §19](05-接口文档.md#19-mcp-server-工具定义已实现)。

## 职业 embedding 生产（2026-10-10）

`OccupationEmbeddingJob` 在 seeder 后运行，`OCCUPATION_EMBED_ENABLED=true` 默认开启；设置 `BAILIAN_API_KEY`，沿用 `text-embedding-v4` / 1024 维配置，并确认 `spring.ai.model.embedding=openai`。dev 当前默认 embedding=none，需用 `SPRING_AI_MODEL_EMBEDDING=openai` 显式开启；test 默认关闭任务的模型阶段。无 Key/关闭 embedding/供应商失败只告警，仍维护 tsv 与提供规则推荐。

## LLM 配额配置（2026-10-09）

offerpilot.rate-limit.per-user-per-minute（LLM_PER_USER_PER_MINUTE，默认60）、guest-per-user-per-minute（LLM_GUEST_PER_USER_PER_MINUTE，默认20）、default-daily-token-limit（LLM_DEFAULT_DAILY_TOKEN_LIMIT，默认200000）、guest-daily-token-limit（LLM_GUEST_DAILY_TOKEN_LIMIT，默认50000）。登录用户有 user_preferences 行时以该行 daily_token_limit 为准；访客以配置为准。UTC 固定分钟/日窗口，与 concurrent-runs-per-user 的既有行为独立。

dev/prod 需要共享 Redis，测试 profile 可在 Redis 自动配置排除后使用内存。Redis 访问故障返回 503/50003；不得为恢复可用性自动清空计数或降级内存。配额状态使用短 TTL，Redis 重启后的状态由既有持久化配置决定。PRO 拒绝访客；live eval 无业务用户上下文时绕过日/RPM/PRO 检查，仍须显式启用原有环境开关并自行承担供应商费用。

## 认证修复部署要求（2026-10-08）

S-1 认证限流配置（2026-10-09）：`offerpilot.rate-limit.auth-guest-per-minute` / `auth-login-per-minute` / `auth-register-per-minute` / `auth-staff-login-per-minute` / `auth-demo-login-per-minute` 对应环境变量 `AUTH_GUEST_PER_MINUTE` / `AUTH_LOGIN_PER_MINUTE` / `AUTH_REGISTER_PER_MINUTE` / `AUTH_STAFF_LOGIN_PER_MINUTE` / `AUTH_DEMO_LOGIN_PER_MINUTE`，默认 15/20/20/20/20，均须正整数。统计所有 POST 尝试，每 IP/路由从首次请求起计 60 秒，失败尝试与成功尝试均消耗额度。现有 `per-user-per-minute=60`、`concurrent-runs-per-user=2` 保持原键与值；前者不在本次执行，后者既有业务并发规则保持。本次不增加 LLM 日配额或 token 限额。

生产使用现有 Redis，键 `offerpilot:rate-limit:auth:<route-bucket>:<remote-ip>` 保存计数，首次请求设置 60 秒 TTL，后续和拒绝请求不续期；各实例共享额度。Redis 自动配置缺失（如 test profile）时按进程使用内存计数，过期项在下一轮请求时按分钟清理；不适用于生产多实例共享限额。已配置 Redis 但故障时认证四端点返回 503/50003，恢复 Redis 后按其原计数/TTL 继续；不会悄悄开放不限量创建。

客户端 IP 必须来自可信反向代理。应用沿用 `server.forward-headers-strategy: framework`，限流只读取 Spring 处理后的 remoteAddr，不自行读取原始转发头。部署应禁止公网绕过代理直连后端，并在代理入口剥离或覆盖客户端提供的 `Forwarded` 和所有 `X-Forwarded-*` 头；多级代理仅信任受控上游。否则伪造头能改变 IP 桶，或所有用户被计入代理同一 IP。尤其不能仅拼接未经验证的 `$http_x_forwarded_for`。CORS 已暴露限流头，429 保留允许的来源与 `Retry-After`。

JWT_SECRET 必须配置为至少 64 字节的随机串（例如 `openssl rand -base64 64`），生产和 dev 均拒绝缺失、短值或 change-me 占位密钥；测试仅使用隔离 test profile 的固定测试值。可从 backend/.env.example 建立本机 .env.local，所有真实凭据只放环境或忽略的本机文件。JWT 当前为 12 小时，无自动刷新；部署前设置新密钥并验证登录。轮换密钥会使旧登录 JWT 失效，访客凭据与历史数据不受影响。

V12 自动停用 V11 中尚未轮换公开密码的固定测试账号，不删除数据。已改密/改邮箱账号保留；正式客服需按受控流程设置密码，不使用仓库中的测试密码。部署的迁移以目录实际版本为准，不能修改已共享 V11。

Windows 的 deploy/start-backend-detached.cmd、start-frontend-detached.cmd 通过脚本自身目录调用既有 windows 预览/静态前端入口，不依赖他人用户名或仓库绝对路径；前端入口需要先运行 prepare.ps1 生成 Nginx 预览包。Maven Wrapper 使用明确的 3.9.11 下载路径。

### 本地开发代理与同源（2026-09-26）

Compose 的 PostgreSQL、Redis、对象存储和 jobs-mcp 宿主机端口均绑定 127.0.0.1；容器内仍通过服务名访问。已存在的 PostgreSQL 容器需以原 pg_data 卷重新创建才能生效，不能删除卷或重新初始化数据库。

`pnpm dev` 的 Vite 代理转发 `/api` 与 `/actuator/health` 时会去掉浏览器的 `Origin` 头。原因是 `changeOrigin` 只改写 `Host`，原样转发的 `Origin` 会让后端把同源代理请求当作跨域；未配置 `CORS_ORIGINS` 时后端只放行 `http(s)://localhost:*`，因此通过 `127.0.0.1` 或局域网地址打开开发服务器时，访客身份、对话、简历、岗位请求都会返回 403。代理只在开发服务器生效，生产构建不受影响。Windows Nginx 入口仍请使用 `http://localhost:8080` 访问：当前配置以 `Host $host` 转发且不带端口，用 `127.0.0.1:8080` 打开同样会被判定为跨域。

### 真实岗位与匹配（2026-09-21）

后端升级自动执行V8；需PostgreSQL及jobs-mcp，匹配还需配置默认文字模型。`JOBS_MCP_URL`为服务基址（本机 `http://localhost:7001`，Compose `http://jobs-mcp:7001`），也接受末尾`/mcp`。前端只访问后端，不需要MCP凭据、额外CORS或外网直连。jobs-mcp只发布到本机回环端口，容器内部仍允许后端服务访问。

首次/升级后执行 `docker compose --env-file backend/.env.local -f deploy/docker-compose.yml up -d --build jobs-mcp` 更新岗位服务镜像；Windows“启动全部”现在自动构建jobs-mcp并等待健康检查，状态菜单也检查7001。运行期间岗位服务失败不会终止聊天/简历，岗位页面给出重试提示；统一启动入口会在依赖健康检查失败时停止，修复后重新启动。`/health`只证明服务存活，不代表所有企业在线。MCP仅限内置无状态服务，不用于任意远程带会话MCP。匹配模型超时90秒，岗位查询每次请求25秒；反代沿用600秒读取超时。

### 简历上传解析运行条件（2026-09-19）

后端启动执行 Flyway V7；需 PostgreSQL 与对象存储在线。**默认对象存储仅供本地开发 / 演示，S3Mock 不校验访问密钥；共享、非 localhost 或生产部署必须替换，见 [§2.1](#21-对象存储演示用-s3mock-与生产替换)。** 演示使用 Adobe S3Mock（`adobe/s3mock:5.2.0`，digest 固定）的历史原因：当时 Quay 对 `minio/minio` 的匿名 token `actions` 为空，拉取 `quay.io/minio/minio:latest` 的 manifest 返回 `UNAUTHORIZED`（401）；Docker Hub 的 `minio/minio` 不可用，`dl.min.io` 二进制返回 410 Gone。沿用 MINIO_ENDPOINT / MINIO_ROOT_USER / MINIO_ROOT_PASSWORD / MINIO_BUCKET。Compose 按 `MINIO_BUCKET` 在启动时创建 bucket；后端仍用 MinIO Java SDK 签名访问，S3Mock 不校验这对密钥，因此宿主机端口必须只绑定 `127.0.0.1:9000`。原文件在 `minio_data` 卷的 `/data`，版本和任务保存在 PostgreSQL，备份时两者必须一起覆盖。

dev 的文字与视觉默认共用 DEEPSEEK_API_KEY 和 deepseek-flash，无需额外百炼 Key。视觉可通过 LLM_VISION_PROVIDER=bailian 切换，同时填写 LLM_MODEL_VISION_ALT、BAILIAN_API_KEY 和 BAILIAN_BASE_URL。升级旧 .env 时请将原有 glm 视觉模型改为 deepseek-flash，或明确保留 bailian 供应商；修改后重启后端。网页 /settings/models 可在已经配置的档位间即时切换当前访客的简历解析偏好；无需为每次用户切换重启。FLASH/CHEAP/PRO 支持 LLM_PROVIDER_* 与 LLM_MODEL_*（dev 的 PRO 兼容 DEEPSEEK_MODEL_PRO），VISION_ALT 使用 LLM_VISION_PROVIDER。自定义兼容服务使用 CUSTOM_LLM_BASE_URL / CUSTOM_LLM_API_KEY / CUSTOM_LLM_COMPLETIONS_PATH，图片能力由各档位 LLM_VISION_* 显式声明。

Spring multipart 限制单文件10MB、请求12MB；网关应允许同等上传大小。后台默认每2秒领取一个任务，test profile 默认设置 `offerpilot.resume.worker-enabled=false` 关闭轮询，`offerpilot.resume.poll-delay` 可调整间隔。模型总时限120秒，PARSING超过10分钟标记失败，恢复后用户可重试；QUEUED任务重启后自动继续。不要手动把未处理任务标记为 READY。

## Windows 本地前后端查看入口

根目录统一入口为 `OfferPilot.cmd`，双击打开菜单。首次安装并打开 Docker Desktop，选「8 配置 DeepSeek」，再选「1 启动全部」；后续更新选「4 更新前端」或「5 重建并重启后端」。旧 CMD 逐个收纳到 `deploy/windows/legacy/` 并转发统一入口。操作说明见 [Windows 使用说明](../deploy/windows/README.md) 和 [后端启动说明](../backend/README.md)。PostgreSQL、Flyway、JPA、Redis 均保留，开发期默认文字档位接 DeepSeek。

Windows 部署脚本统一按显式 `-RuntimeRoot` 参数、非空环境变量 `OFFERPILOT_RUNTIME_ROOT`、默认 `D:\OfferPilot` 的优先级解析运行根目录，并用 `[IO.Path]::GetFullPath` 转为绝对路径。控制台和嵌套准备脚本传递同一目录；Nginx、后端日志/进程记录和默认 releases 目录均由此派生。`package.ps1 -OutputDirectory` 可单独覆盖分发包输出目录；项目源码位置不变。

统一入口复用 `deploy/windows/backend-preview.ps1`，以 dev profile 绑定 127.0.0.1:8081。如果 8081 已监听，保留原进程并提示，不接管也不停止它。菜单「2 停止前后端」核对 PID、启动时间与可执行路径后停止已管理 Java 进程，再停止本项目 Nginx；数据库容器继续运行。日志和进程元数据保存在解析后的运行根目录，默认为 `D:\OfferPilot`。

后端构建/重启入口在 `backend/target/preview-builds/<唯一标识>/backend/` 复制各模块 POM、源码、Maven Wrapper 和迁移测试夹具后执行带测试的 `package`；不复制环境凭据，不调用 `clean` 或删除旧产物。新构建失败保留运行中的后端；成功后才停止受管实例并等待退出，然后启动新副本的 JAR，工作目录保持原项目根目录。构建副本保留，无自动清理。

后端进程记录新增 `projectRoot`、`jarPath`，停止时除 PID、启动时间、Java 可执行路径外，还核对当前项目根目录与实际命令行的精确 `-jar` 路径。旧记录只认领当前项目原始 bootstrap target 下的精确 JAR；共用运行根目录的其他项目副本、无法核实的进程或被复用的 PID 均不停止。进程句柄在核实后用于停止；未确认退出或停止报错时阻止新版启动。无需也不允许按 offerpilot-bootstrap 名称片段查找并强停 Java。

菜单「3 查看运行状态」与启动依赖使用同一份 `backend/.env.local` 进行 Compose 变量解析；缺少配置时明确提示，不将环境变量错误笼统报告为 Docker 引擎故障。

菜单「4 更新前端」调用 `deploy/windows/prepare.ps1` 构建前端并下载官方 Windows Nginx，产物默认在 `D:\OfferPilot\nginx-1.31.5\`；「6 仅启动前端」执行配置校验与重复启动检测。访问 `http://localhost:8080`。

- Nginx 只绑定本机回环地址，静态资源与 SPA 路由回退同域访问；`/api/` 转发 `127.0.0.1:8081`，关闭 SSE 缓冲，600 秒读取超时。
- `/actuator/health`、`/v3/api-docs` 和 Swagger 页面转发到后端，便于检查联调。后端未启动时前端仍可用，健康检查和对话明确报告连接失败。
- `OfferPilot.cmd -Action stop-frontend` 只向本项目 Nginx 发送优雅退出，不结束其他 Nginx 实例；`prepare.ps1` 无递归清理，仅覆盖构建输出与本项目配置。
- 后端与数据库仍是独立进程：按本文及 backend README 启动。`nginx.exe` 不会启动 Java、数据库或模型服务。当前 Agent 为真实 DeepSeek 单轮 HTTP/SSE 聊天，尚未接入编排或历史持久化。
- 修改前端后重跑准备脚本；若使用已有 Nginx，可传 `-NginxDirectory`，该目录须在解析后的运行根目录（默认 `D:\OfferPilot\`）内。前端生产构建固定使用 `/api/v1` 且禁用 MSW。
- 官方 Windows 安装与控制命令参考 https://nginx.org/en/docs/windows.html ，下载来自 https://nginx.org/en/download.html 。

> 目标：新机器 10 分钟内一键启动；公网 HTTPS 演示在评审期可用率 ≥ 99.5%；所有密钥仅经环境变量注入。

## 2. Docker Compose（`deploy/docker-compose.yml`）

> **以下默认 S3Mock 配置仅限本地开发 / 演示（demo / local only），不适用于公网演示、共享或生产环境。即使 9000 仍绑定回环地址，部署到这些环境也必须先按 [§2.1](#21-对象存储演示用-s3mock-与生产替换) 换用强制校验密钥的存储。**

```yaml
name: offerpilot

services:
  caddy:
    image: caddy:2-alpine
    restart: always
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - frontend_dist:/srv/frontend:ro
      - caddy_data:/data
      - caddy_config:/config
    environment:
      DOMAIN: ${DOMAIN:-localhost}
    depends_on: [backend]

  frontend:
    build:
      context: ../frontend
      args:
        VITE_API_BASE_URL: ${VITE_API_BASE_URL:-/api/v1}
    image: offerpilot/frontend:${TAG:-latest}
    volumes: [frontend_dist:/dist]         # 仅负责产出静态文件到共享卷
    command: ["sh", "-c", "rm -rf /dist/* && cp -r /app/dist/. /dist/ && echo done"]
    restart: "no"

  backend:
    build: ../backend
    image: offerpilot/backend:${TAG:-latest}
    restart: always
    env_file: [../.env]
```

### 2.1 对象存储：演示用 S3Mock 与生产替换

**演示 / 本地开发：S3Mock 不认证 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`。** 后端签名不能阻止其他客户端访问对象。默认 Compose 必须保持 `127.0.0.1:9000:9000`，不得将 9000 暴露到公网、通过代理公开 S3Mock，或与不可信容器共享其网络。回环绑定只是本地缓解措施，不是认证机制；[S3Mock 官方说明](https://github.com/adobe/S3Mock#important-limitations) 将其用于本地测试并说明认证限制。

**共享 / 非 localhost / 生产（包括公网演示）：必须使用强制校验 access key + secret 的 S3 兼容存储。** 可选择 AWS S3、Cloudflare R2、有可信可拉取镜像或二进制的自建 MinIO，或配置好身份与访问策略的 SeaweedFS S3 gateway。不得启用业务 bucket 的匿名读写。云服务使用其签发的访问密钥；其他服务按对应文档开启认证，不能假定设置任意名为 `MINIO_ROOT_*` 的变量就会生效。

后端配置仍为 `MINIO_ENDPOINT`、`MINIO_ROOT_USER`、`MINIO_ROOT_PASSWORD`、`MINIO_BUCKET`、`MINIO_PUBLIC_ENDPOINT`，MinIO Java SDK 已签名请求，替换重点是让服务端真正验证签名。`MINIO_ENDPOINT` 填后端可达的 S3 API 地址；保留 Compose 服务名 `minio` 时仍为 `http://minio:9000`。`MINIO_PUBLIC_ENDPOINT` 填浏览器可达的 S3 API 地址（本机为 `http://127.0.0.1:9000`，远程部署为受控 HTTPS 存储域名），用于签名 URL；不能填容器内部服务名。当前 Caddy 不提供对象存储代理，需要另行配置存储 HTTPS 入口或使用云服务端点，转发时保留签名所依赖的 Host、路径与查询参数。预建 `MINIO_BUCKET` 或按后端行为授予建桶权限，再核验上传、下载和签名 URL。

可选模板 [docker-compose.storage-auth.example.yml](../deploy/docker-compose.storage-auth.example.yml) 以 MinIO server 为例，保留服务名及回环端口，不发布 9001 控制台；默认 `up` 和 CI 不加载它。**这是待配置模板，没有提供经 `docker pull` 验证可用的镜像 digest。** 设置 `STORAGE_AUTH_IMAGE` 为可信镜像的 `registry/repository@sha256:<digest>` 并自行验证可拉取；默认 `registry.invalid` 占位值故意不能运行，不能作为生产镜像。MinIO 会实际使用 [root 凭据环境变量](https://github.com/minio/minio/blob/master/docs/config/README.md)；请在忽略的 `.env` 或进程环境提供真实强凭据，与后端保持一致，不得沿用示例密码。

模板需要 Docker Compose **2.24.4 或更高**，使用 [`!override`](https://docs.docker.com/reference/compose-file/merge/#replace-value) 完整替换 `minio` 服务，避免继承 S3Mock 参数。所选镜像需提供 `minio` 可执行文件与 `curl`；否则按镜像调整入口和健康检查。MinIO 探针使用 [`/minio/health/live`](https://github.com/minio/minio/blob/master/docs/metrics/healthcheck/README.md)，不能沿用 S3Mock 的 `/`；此探针仅证明存活，上线前还需确认正确凭据可以读写、错误凭据和匿名对象请求被拒绝。

在仓库根目录操作（先填写 `.env` 中的存储配置与 `STORAGE_AUTH_IMAGE`；配置含敏感值，勿提交或分享 `config` 输出）：

```bash
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml config
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml pull minio
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml up -d minio
# 存储就绪、bucket / 对象迁移并验收后，启动完整应用
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml --profile full up -d
```

后续启动、重建和发布命令（包括 §7 / §8）也必须带两个 `-f`，否则可能切回 S3Mock。接入外部云存储时，按服务端配置更新端点与凭据，并在自己的部署覆盖中移除本地 `minio` 服务及后端对它的 `depends_on`；不要同时启动默认 S3Mock 充当生产存储。

模板使用独立 `minio_auth_data` 卷，原 `minio_data` 保留；两种服务的磁盘格式不能直接互换。已有数据应在受控迁移窗口通过 S3 API 导出 / 导入，保留 bucket 和 object key，核验后再切换后端。**对象数据与 PostgreSQL 必须配套备份和恢复**，保留迁移前备份；§9 的 S3Mock `/data` 打包示例不能直接视为其他服务或云存储的备份方案，应采用对应服务的备份 / 快照机制并验证恢复。

## 9. 备份、恢复与演示数据

### 9.1 备份（`deploy/scripts/backup.sh`，宿主机 cron 每日 03:30）

本地 S3Mock 对象存储数据在 `minio` 容器的 `/data`（卷 `minio_data`）。下面的 `volumes-from` 打包的就是这个目录；认证存储的卷 / 云端备份按 [§2.1](#21-对象存储演示用-s3mock-与生产替换) 和服务文档调整，对象数据与 PostgreSQL 必须配套备份。

```bash
#!/usr/bin/env bash
set -euo pipefail
cd /opt/offerpilot
TS=$(date +%F_%H%M)
docker compose -f deploy/docker-compose.yml exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" | gzip > "backups/pg_$TS.sql.gz"
docker run --rm --volumes-from offerpilot-minio-1 -v "$PWD/backups:/backup" alpine tar czf "/backup/minio_$TS.tgz" /data
find backups -type f -mtime +7 -delete
```

### 9.2 恢复

```bash
gunzip -c backups/pg_2026-11-20_0330.sql.gz | docker compose -f deploy/docker-compose.yml exec -T postgres psql -U "$POSTGRES_USER" "$POSTGRES_DB"
```

### 9.3 演示数据重置

- `DemoAccountBootstrap`（identity）在启用且环境密码有效时创建虚构 USER/is_demo 账号，启动刷新 BCrypt 哈希，补齐 FLASH 偏好。空白/非法配置 WARN 跳过；配置邮箱属于非体验账号时不接管。修改邮箱可复用唯一既有体验用户；多个体验用户且邮箱未匹配时跳过。
- `DemoJourneyBootstrap`（bootstrap）在零简历时调用 `DemoResetService.seedIfEmpty`。无需额外 `--seed=all` 进程，不调用 MCP 或模型，不重复灌入职业库。源数据在 `offerpilot-bootstrap/src/main/resources/demo/journey.json`，全部虚构。
- `DemoResetService` 复用 PostgreSQL 事务与体验用户行锁，删除该用户业务数据及依赖行，灌入 2 份 READY 简历及真实 DOCX 源件、10 个虚构岗位、6 条看板记录、2 场文字面试（1 完成、1 进行中）、1 份职业画像与 3 项成长完成记录。岗位 site=demo，仅供展示，无实际投递链接。真实岗位缓存、职业库和其他用户数据保留；公开虚构岗位用唯一键更新，保留其他用户引用。
- `DEMO_RESET_CRON` 默认 `0 0 4 * * *`，按后端服务器时区执行；`-` 禁用定时重置。仅开启且账号配置有效时运行。共享改动会被重置，请勿输入真实个人信息。数据库替换提交后清理旧源文件对象；对象存储删除失败会 WARN，可按文件 key 清理残留，数据库重置已完成。
- 手动调用 `POST /api/v1/admin/demo/reset` 需要有效 ACTIVE STAFF JWT（不接受普通 USER/访客）。先从 `/api/v1/auth/staff/login` 获取 accessToken，在环境设置 `STAFF_TOKEN`，运行 `API_BASE_URL=https://<domain>/api/v1 bash deploy/scripts/reset-demo.sh`；未设置 token 或 HTTP 失败时脚本非零退出，不打印凭据。返回 resetAt 与各类数据数量。
- 密码只由 `DEMO_ACCOUNT_PASSWORD` 注入，默认空白；启动与一键登录确保密码符合注册规则。同邮箱真实账号不会被提升为体验账号，停用体验账号不会因登录恢复启用。共享体验密码应视作公开凭据并定期轮换，禁止复用真实用户或客服密码。
- 模型档位与单条数据删除沿用现有 USER 行为与配额；额外锁定仍为后续项。种子不包含 AI 面试报告、匹配报告或额外学习路线。

## 12. 评审期保障与故障手册

| 场景 | 处理 |
| --- | --- |
| 后端 OOM 重启循环 | `docker logs`; 降低 `MaxRAMPercentage` 或提升内存限制；检查 HNSW 建索引任务 |
| 模型全部 429 | `LLM_DEFAULT_TIER=CHEAP` 重启；启用缓存；必要时切换备用 Key |
| jobs-mcp 站点失效 | 应用自动跳过；如全部失效，设置 `JOBS_SOURCE_MODE=LOCAL` 使用缓存岗位库 |
| 证书申请失败 | 检查 DNS 与 80 端口；临时用 `tls internal` 并在 README 说明 |
| 磁盘满 | 清理 `docker system prune`、旧备份；`agent_events` 30 天清理任务是否运行 |
| 数据误删 | 用最近备份恢复（§9.2） |
| 演示期间流卡住 | 前端自动 `resume`；手动刷新；确认 Caddy `flush_interval -1` |

评审窗口内（提交后至评审意见发布）每日检查一次 UptimeRobot 与 `/admin/usage`；不做任何功能变更，仅允许紧急修复并记录。

P1-4 看板审批运行约束（2026-10-09）：首期 ApprovalService 等待为单实例进程内状态，审批 POST 必须到持有 SSE 运行的实例；当前按单实例部署，不提供 Redis 广播。重启丢失待审批，需重新发起聊天。审批窗口十分钟，SseEmitter/浏览器整轮上限一百分钟覆盖最多八步；服务端每十五秒发送 SSE 心跳，现有 proxy_read_timeout 600s 是读取空闲超时，无需延长。待审批仅更新当前 owner/run 的数据库租约至十二分钟后，停机遗留运行仍按租约回收。

### 简历 PDF 导出字体（2026-10-09）

后端 runtime 镜像安装 `fontconfig font-noto-cjk`，不在仓库或应用 JAR 中打包字体。PDFBox / FontBox 将用到的 Noto CJK 字形轮廓嵌入 Type 3 字体并携带 ToUnicode，导出文件在客户端无需安装字体即可显示和复制中文。布局使用固定 `classic` A4 模板，不调用模型。

可通过 Spring 属性 `offerpilot.resume.export.font-regular` / `font-bold`（环境变量 `OFFERPILOT_RESUME_EXPORT_FONT_REGULAR` / `OFFERPILOT_RESUME_EXPORT_FONT_BOLD`）指定可读 TTC / OTF / TTF 文件；显式指定时不回退其他字体。未指定时依次查找 `/usr/share/fonts/opentype/noto/NotoSansCJK-{Regular,Bold}.ttc`（Debian/Ubuntu）、`/usr/share/fonts/noto/NotoSansCJK-{Regular,Bold}.ttc`（[Alpine font-noto-cjk](https://pkgs.alpinelinux.org/contents?arch=x86&branch=v3.22&name=font-noto-cjk&repo=community)）、`/usr/share/fonts/noto-cjk/NotoSansCJK-{Regular,Bold}.ttc` 和 `/usr/share/fonts/noto-cjk/NotoSansCJKsc-{Regular,Bold}.otf`。TTC 优先选简体中文 face；常规和粗体均须可用，缺失时仅导出请求返回 503 / 50004 并说明待配置属性，不阻止其他业务启动。
