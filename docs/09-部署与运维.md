公网使用 `DEMO_ACCOUNT_ENABLED=true`、`DEMO_SANDBOX_ENABLED=true`（默认），每次 demo-login 独立建号并复用 DemoResetService / demo/journey.json；不运行共享账号启动播种和每日 reset，不需要共享账号密码。`DEMO_SANDBOX_TTL=24h` 可缩短，必须至少1秒且 ≤24h。`DEMO_SANDBOX_DAILY_TOKEN_LIMIT=200000` 独立于注册 USER 日预算；按 UTC 零点重置，每次网关调用前检查、调用后记账，仍可能有一批在途调用超额。默认存量 `DEMO_SANDBOX_MAX_ACTIVE=30`、UTC 每日创建 `DEMO_SANDBOX_MAX_PER_DAY=100`，均须正整数；数据库事务 advisory lock 跨实例串行准入，存量包括播种中、已过期待删除和停用的沙箱。删除/失败不返还每日名额，aggregate 表只保留最近三日计数，不保存 IP。先按模型余额和预期评委人数调小上限；24h 沙箱可能跨两个 UTC 预算日。

## Gitee 镜像启用（Benjamin，2026-10-11）

已提供 [Gitee mirror 工作流](../.github/workflows/gitee-mirror.yml)：`main` push 或 `workflow_dispatch` 时同步 GitHub 上的全部分支、标签及完整历史，只获取 `refs/heads/*` 和 `refs/tags/*`，排除 `refs/pull/*`。缺少 `GITEE_SSH_PRIVATE_KEY` secret 或 `GITEE_REPO` variable 时，前置配置检查成功、镜像 job 在 job-level `if` 跳过，CI 保持绿色。GitHub 权限仅 `contents: read`；镜像任务串行、限时 10 分钟；固定 Gitee 官方 ED25519 主机公钥并严格校验。

Benjamin 一次性配置：

1. 创建**空的公开 Gitee 仓库**，不初始化 README/许可证；记录实际 `owner/repository`。Gitee 作为单向镜像：`git push --mirror` 会强制对齐远端引用，包括删除 GitHub 已删除的分支/标签，因此不要在镜像仓库独立开发。
2. 在自己的受控机器生成专用、无口令 SSH key：`ssh-keygen -t ed25519 -C "offerpilot-gitee-mirror" -N '' -f ~/.ssh/offerpilot_gitee_mirror`（首次使用该文件名）。公钥必须获得目标仓库**写入权限**。如部署公钥界面支持写权限则启用；但 [Gitee 官方说明](https://help.gitee.com/base/account/SSH公钥设置) 当前仓库部署公钥仅能拉取，通常须将 `.pub` 添加到专用镜像账号的账户 SSH 公钥，并仅授予该账号目标仓库写权限，避免使用个人全权限 key。
3. 在 GitHub 仓库 Settings → Secrets and variables → Actions 中，添加 repository secret `GITEE_SSH_PRIVATE_KEY`（私钥文件完整内容，含头尾及换行），以及 repository variable `GITEE_REPO`（实际 `owner/repository`，例如 `owner/offerpilot`；不带 URL 或 `.git`）。私钥只放 secret/受控本机文件，不输出到终端或提交到仓库。
4. 工作流进入默认分支后，在 Actions → Gitee mirror → Run workflow 选择 `main` 执行 `workflow_dispatch`。确认 mirror job 成功而非 skipped，再对比两端 `git ls-remote --heads --tags <实际仓库地址>` 的引用与 commit SHA，并在未登录浏览器中验证 Gitee 仓库公开可访问。
5. Gitee 仓库实际存在且验证通过后，README 仓库链接应同时列出实际 GitHub 与 Gitee URL，并更新 [11 的仓库清单](11-提交材料清单.md)。当前仅完成自动化准备，尚未建立/验证真实镜像，不预填 Gitee URL。

printf '%s\n' 'gitee.com ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIEKxHSJ7084RmkJ4YdEi5tngynE8aZe2uEoVVsB/OvYN' > ~/.ssh/offerpilot_gitee_known_hosts
export GIT_SSH_COMMAND="ssh -F /dev/null -i '$HOME/.ssh/offerpilot_gitee_mirror' -o IdentitiesOnly=yes -o BatchMode=yes -o StrictHostKeyChecking=yes -o UserKnownHostsFile='$HOME/.ssh/offerpilot_gitee_known_hosts' -o GlobalKnownHostsFile=/dev/null -o HostKeyAlgorithms=ssh-ed25519"

## 上传与体验行动夹具（2026-10-11）

multipart max-file-size=10MB、max-request-size=12MB 保持不变；server.tomcat.max-swallow-size=-1 使 Tomcat 读完被拒绝请求的剩余正文，保证 413 JSON 能被普通 HTTP 客户端收到。该值只改变拒绝后的吞读行为，不扩大允许上传或持久化的文件大小。

demo/journey.json 的 applications 使用 nextAction 和 nextActionDayOffset（相对数据库 current_date 的整数，null 表示无日期）。DemoResetService 按 current_date + offset 插入，六条分别为今天、逾期一天、未来3/1/5天与无行动；非空行动各不相同，NEXT_ACTION_EDITED 记录实际行动文本。保持稳定 ID、原重置事务与 owner 范围，不调用模型；重复重置同一天得相同计划，跨天随当前日期移动。

1. 复制 `deploy/.env.demo.example` 到根 `.env` 并 `chmod 600 .env`，替换全部占位值；必填 `DOMAIN`、数据库/Redis 密码、至少 64 字节随机 `JWT_SECRET`、32 字节 base64 `DATA_ENCRYPTION_KEY`、`DEMO_ACCOUNT_ENABLED=true` 与沙箱限额（仅共享录屏模式需有效邮箱/密码）。配置真实模型 key 后才能验收匹配热力图/简历改写；生产镜像不支持 `LLM_MOCK`（mock embedding 仅在测试目录）。公网默认保持 `MCP_SERVER_ENABLED=false`；需对外 MCP 时配置随机 API key、HTTPS 和网关限流。
2. **先替换认证对象存储**，按 §2.1 校验镜像 digest、正确/错误密钥与匿名访问、建桶及受控 HTTPS 对象入口。默认 S3Mock 不校验密钥，即便仅监听回环也不可用于公网应用；认证覆盖启用独立 STORAGE_DOMAIN 的只读代理，默认本地配置不代理对象。
3. 配置 DNS/防火墙。通常只开放 80/443；数据服务仅绑定 127.0.0.1。`PG_HOST_PORT` / `REDIS_HOST_PORT` / `MINIO_HOST_PORT` / `JOBS_MCP_HOST_PORT` 默认 5432/6379/9000/7001；`HTTP_PORT` / `HTTPS_PORT` 默认 80/443，可为第二套栈全部覆盖，容器内端口不变。`DOMAIN=localhost` 保留自动本地 TLS；非标准宿主机端口本地测试使用 `https://localhost:<HTTPS_PORT>`（自签名可仅本机 `curl -k`），HTTP 重定向仍指标准 443，不能当公网 ACME 端口映射。
4. 从仓库根执行下列命令，确认镜像构建、迁移和种子完成。Caddy 必须等 backend `service_healthy` 及 frontend `service_completed_successfully`；其内部未发布的 8080 `/healthz` 探针还要求 `index.html` 非空。后端/S3Mock/Caddy 的 `wget` 须在实际镜像内可执行。公网 `/healthz` 只检查代理；应用探针使用 `/actuator/health`，SPA 使用 `/`。现有 SSE/MCP/API 路由与安全响应头保留；未添加空值可能影响启动的 ACME email 全局选项。
5. 选择重置时区及 `DEMO_RESET_CRON`（默认每天 04:00，容器 UTC；Spring 六字段；`-` 禁用）。宿主机 cron 与应用定时二选一，例子及 STAFF JWT 12 小时续签限制见 [脚本说明](../deploy/scripts/README.md)。配置健康告警、数据库与对象配套备份并实际恢复一次；`backup.sh` 仅覆盖数据库。

```bash
# 公网 / 共享环境：先填写 .env 并按 §2.1 验证认证存储覆盖。
docker compose -p offerpilot-demo --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml --profile full config --quiet
docker compose -p offerpilot-demo --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml --profile full up -d --build
docker compose -p offerpilot-demo --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml --profile full ps
deploy/scripts/healthcheck.sh https://demo.example.com
```

长期服务使用 json-file 轮转（每文件 10m、保留 3 文件）；宿主机 cron 日志另配 logrotate。`restart: always` 只在进程退出时重启，Docker 的 unhealthy 状态本身不会重启容器；探针失败需告警并诊断。这里只验收单实例；生产 DNS、ACME、真实模型输出质量、浏览器语音/摄像头以及外部监控均待真实环境验证。

## 本地免费向量：Ollama bge-m3（2026-10-16）

S-1 认证限流配置（2026-10-09）：`offerpilot.rate-limit.auth-guest-per-minute` / `auth-login-per-minute` / `auth-register-per-minute` / `auth-staff-login-per-minute` / `auth-demo-login-per-minute` 对应环境变量 `AUTH_GUEST_PER_MINUTE` / `AUTH_LOGIN_PER_MINUTE` / `AUTH_REGISTER_PER_MINUTE` / `AUTH_STAFF_LOGIN_PER_MINUTE` / `AUTH_DEMO_LOGIN_PER_MINUTE`，默认 15/20/20/20/20，均须正整数。统计所有 POST 尝试，每 IP/路由从首次请求起计 60 秒，失败尝试与成功尝试均消耗额度。现有 `per-user-per-minute=60`、`concurrent-runs-per-user=2` 保持原键与值；前者不在本次执行，后者既有业务并发规则保持。本次不增加 LLM 日配额或 token 限额。

生产使用现有 Redis，键 `offerpilot:rate-limit:auth:<route-bucket>:<remote-ip>` 保存计数，首次请求设置 60 秒 TTL，后续和拒绝请求不续期；各实例共享额度。Redis 自动配置缺失（如 test profile）时按进程使用内存计数，过期项在下一轮请求时按分钟清理；不适用于生产多实例共享限额。已配置 Redis 但故障时认证四端点返回 503/50003，恢复 Redis 后按其原计数/TTL 继续；不会悄悄开放不限量创建。

客户端 IP 必须来自可信反向代理。应用沿用 `server.forward-headers-strategy: framework`，限流只读取 Spring 处理后的 remoteAddr，不自行读取原始转发头。部署应禁止公网绕过代理直连后端，并在代理入口剥离或覆盖客户端提供的 `Forwarded` 和所有 `X-Forwarded-*` 头；多级代理仅信任受控上游。否则伪造头能改变 IP 桶，或所有用户被计入代理同一 IP。尤其不能仅拼接未经验证的 `$http_x_forwarded_for`。CORS 已暴露限流头，429 保留允许的来源与 `Retry-After`。

JWT_SECRET 必须配置为至少 64 字节的随机串（例如 `openssl rand -base64 64`），生产和 dev 均拒绝缺失、短值或 change-me 占位密钥；测试仅使用隔离 test profile 的固定测试值。可从 backend/.env.example 建立本机 .env.local，所有真实凭据只放环境或忽略的本机文件。JWT 当前为 12 小时，无自动刷新；部署前设置新密钥并验证登录。轮换密钥会使旧登录 JWT 失效，访客凭据与历史数据不受影响。

V12 自动停用 V11 中尚未轮换公开密码的固定测试账号，不删除数据。已改密/改邮箱账号保留；正式客服需按受控流程设置密码，不使用仓库中的测试密码。部署的迁移以目录实际版本为准，不能修改已共享 V11。

Windows 的 deploy/start-backend-detached.cmd、start-frontend-detached.cmd 通过脚本自身目录调用既有 windows 预览/静态前端入口，不依赖他人用户名或仓库绝对路径；前端入口需要先运行 prepare.ps1 生成 Nginx 预览包。Maven Wrapper 使用明确的 3.9.11 下载路径。

### 本地开发代理与同源（2026-09-26）

Compose 的 PostgreSQL、Redis、对象存储和 jobs-mcp 宿主机端口均绑定 127.0.0.1；容器内仍通过服务名访问。已存在的 PostgreSQL 容器需以原 pg_data 卷重新创建才能生效，不能删除卷或重新初始化数据库。

`pnpm dev` 的 Vite 代理转发 `/api` 与 `/actuator/health` 时会去掉浏览器的 `Origin` 头。原因是 `changeOrigin` 只改写 `Host`，原样转发的 `Origin` 会让后端把同源代理请求当作跨域；未配置 `CORS_ORIGINS` 时后端只放行 `http(s)://localhost:*`，因此通过 `127.0.0.1` 或局域网地址打开开发服务器时，访客身份、对话、简历、岗位请求都会返回 403。代理只在开发服务器生效，生产构建不受影响。Windows Nginx 入口仍请使用 `http://localhost:8080` 访问：当前配置以 `Host $host` 转发且不带端口，用 `127.0.0.1:8080` 打开同样会被判定为跨域。

### 2.1 对象存储：演示用 S3Mock 与生产替换

**演示 / 本地开发：S3Mock 不认证 `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`。** 后端签名不能阻止其他客户端访问对象。默认 Compose 必须保持 `127.0.0.1:9000:9000`，不得将 9000 暴露到公网、通过代理公开 S3Mock，或与不可信容器共享其网络。回环绑定只是本地缓解措施，不是认证机制；[S3Mock 官方说明](https://github.com/adobe/S3Mock#important-limitations) 将其用于本地测试并说明认证限制。

**共享 / 非 localhost / 生产（包括公网演示）：必须使用强制校验 access key + secret 的 S3 兼容存储。** 可选择 AWS S3、Cloudflare R2、有可信可拉取镜像或二进制的自建 MinIO，或配置好身份与访问策略的 SeaweedFS S3 gateway。不得启用业务 bucket 的匿名读写。云服务使用其签发的访问密钥；其他服务按对应文档开启认证，不能假定设置任意名为 `MINIO_ROOT_*` 的变量就会生效。

后端配置仍为 `MINIO_ENDPOINT`、`MINIO_ROOT_USER`、`MINIO_ROOT_PASSWORD`、`MINIO_BUCKET`、`MINIO_PUBLIC_ENDPOINT`，MinIO Java SDK 已签名内部请求，替换重点是让服务端真正验证签名。MINIO_ENDPOINT填后端可达的S3地址；保留服务名minio时仍为 `http://minio:9000`。认证覆盖提供独立STORAGE_DOMAIN，只允许GET/HEAD，保留Host、路径与查询；MINIO_PUBLIC_ENDPOINT配置为对应https地址。现有简历原件与PDF仍由应用鉴权API返回，不新增前端直接下载接口；存储验收工具单独生成外部地址签名核对代理。预建MINIO_BUCKET或按后端行为授予建桶权限，设置桶策略禁止匿名读写。

可选模板 [docker-compose.storage-auth.example.yml](../deploy/docker-compose.storage-auth.example.yml) 以 MinIO server 为例，保留服务名及回环端口，不发布 9001 控制台；默认 `up` 不加载，CI只渲染检查、不运行它。**这是待配置模板，没有提供经 `docker pull` 验证可用的镜像 digest。** 设置 `STORAGE_AUTH_IMAGE` 为可信镜像的 `registry/repository@sha256:<digest>` 并自行验证可拉取；默认 `registry.invalid` 占位值故意不能运行，不能作为生产镜像。MinIO 会实际使用 [root 凭据环境变量](https://github.com/minio/minio/blob/master/docs/config/README.md)；请在忽略的 `.env` 或进程环境提供真实强凭据，与后端保持一致，不得沿用示例密码。

模板需要 Docker Compose **2.24.4 或更高**，使用 [`!override`](https://docs.docker.com/reference/compose-file/merge/#replace-value) 完整替换 `minio` 服务，避免继承 S3Mock 参数。所选镜像需提供 `minio` 可执行文件与 `curl`；否则按镜像调整入口和健康检查。MinIO 探针使用 [`/minio/health/live`](https://github.com/minio/minio/blob/master/docs/metrics/healthcheck/README.md)，不能沿用 S3Mock 的 `/`；此探针仅证明存活，上线前还需确认正确凭据可以读写、错误凭据和匿名对象请求被拒绝。

在仓库根目录操作（先填写 `.env` 中的存储配置与 `STORAGE_AUTH_IMAGE`；配置含敏感值，勿提交或分享 `config` 输出）：

```bash
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml config
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml pull minio
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml up -d minio
# 存储就绪、bucket / 对象迁移并验收后，启动完整应用
docker compose --env-file .env -f deploy/docker-compose.yml -f deploy/docker-compose.storage-auth.example.yml --profile full up -d
```

后续启动、重建和发布命令（包括 §7 / §8）也必须带两个 `-f`，否则可能切回 S3Mock。接入外部云存储时，按服务端配置更新端点与凭据，并在自己的部署覆盖中移除本地 `minio` 服务及后端对它的 `depends_on`；不要同时启动默认 S3Mock 充当生产存储。

模板使用独立 `minio_auth_data` 卷，原 `minio_data` 保留；两种服务的磁盘格式不能直接互换。已有数据应在受控迁移窗口通过 S3 API 导出 / 导入，保留 bucket 和 object key，核验后再切换后端。**对象数据与 PostgreSQL 必须配套备份和恢复**，保留迁移前备份；§9数据库备份不能代替对象备份，应采用对应存储服务的备份/快照机制并验证恢复。

- `DemoAccountBootstrap`（identity）在共享模式启用且环境密码有效时创建虚构 USER/is_demo 账号，启动刷新 BCrypt 哈希，补齐 FLASH 偏好。空白/非法配置 WARN 跳过；配置邮箱属于非体验账号时不接管。修改邮箱可复用唯一既有体验用户；多个体验用户且邮箱未匹配时跳过。
- `DemoJourneyBootstrap`（bootstrap）在零简历时调用 `DemoResetService.seedIfEmpty`。无需额外 `--seed=all` 进程，不调用 MCP 或模型，不重复灌入职业库。源数据在 `offerpilot-bootstrap/src/main/resources/demo/journey.json`，全部虚构。
- `DemoResetService` 复用 PostgreSQL 事务与体验用户行锁，删除该用户业务数据及依赖行，灌入 2 份 READY 简历及真实 DOCX 源件、10 个虚构岗位、6 条看板记录、2 场文字面试（1 完成、1 进行中）、1 份职业画像与 3 项成长完成记录。岗位 site=demo，仅供展示，无实际投递链接。真实岗位缓存、职业库和其他用户数据保留；公开虚构岗位用唯一键更新，保留其他用户引用。
- `DEMO_RESET_CRON` 默认 `0 0 4 * * *`，按后端服务器时区执行；`-` 禁用定时重置。仅开启且账号配置有效时运行。共享改动会被重置，请勿输入真实个人信息。数据库替换提交后清理旧源文件对象；对象存储删除失败会 WARN，可按文件 key 清理残留，数据库重置已完成。
- 手动调用 `POST /api/v1/admin/demo/reset` 需要有效 ACTIVE STAFF JWT（不接受普通 USER/访客）。先从 `/api/v1/auth/staff/login` 获取 accessToken，在环境设置 `STAFF_TOKEN`，运行 `API_BASE_URL=https://<domain>/api/v1 bash deploy/scripts/reset-demo.sh`；未设置 token 或 HTTP 失败时脚本非零退出，不打印凭据。返回 resetAt 与各类数据数量。
- 密码只由 `DEMO_ACCOUNT_PASSWORD` 注入，默认空白；启动与一键登录确保密码符合注册规则。同邮箱真实账号不会被提升为体验账号，停用体验账号不会因登录恢复启用。共享体验密码应视作公开凭据并定期轮换，禁止复用真实用户或客服密码。
- 模型档位与单条数据删除沿用现有 USER 行为与配额；额外锁定仍为后续项。种子不包含 AI 面试报告、匹配报告或额外学习路线。

## 12. 评审期保障与故障手册

| 场景 | 处理 |
| --- | --- |
| 后端 OOM 重启循环 | `docker logs`; 降低 `MaxRAMPercentage` 或提升内存限制；检查 HNSW 建索引任务 |
| 模型全部 429 | 检查供应商额度与限流；遵循 Retry-After；必要时配置备用供应商并重启 |
| jobs-mcp 站点失效 | 默认 AUTO 在失败/超时/全部失败/错误导致空结果时回退示例快照，页面标注「离线快照」；录制可设 LOCAL 完全跳过岗位网络调用；LIVE 保留报错 |
| 证书申请失败 | 检查 DNS 与 80 端口；临时用 `tls internal` 并在 README 说明 |
| 磁盘满 | 清理 `docker system prune`、旧备份；`agent_events` 30 天清理任务是否运行 |
| 数据误删 | 用最近备份恢复（§9.2） |
| 演示期间流卡住 | 前端自动 `resume`；手动刷新；确认 Caddy `flush_interval -1` |

### 简历 PDF 导出字体（2026-10-09）

后端 runtime 镜像安装 `fontconfig font-noto-cjk`，不在仓库或应用 JAR 中打包字体。PDFBox / FontBox 将用到的 Noto CJK 字形轮廓嵌入 Type 3 字体并携带 ToUnicode，导出文件在客户端无需安装字体即可显示和复制中文。布局使用固定的 `classic` / `compact` A4 模板，不调用模型。

可通过 Spring 属性 `offerpilot.resume.export.font-regular` / `font-bold`（环境变量 `OFFERPILOT_RESUME_EXPORT_FONT_REGULAR` / `OFFERPILOT_RESUME_EXPORT_FONT_BOLD`）指定可读 TTC / OTF / TTF 文件；显式指定时不回退其他字体。未指定时依次查找 `/usr/share/fonts/opentype/noto/NotoSansCJK-{Regular,Bold}.ttc`（Debian/Ubuntu）、`/usr/share/fonts/noto/NotoSansCJK-{Regular,Bold}.ttc`（[Alpine font-noto-cjk](https://pkgs.alpinelinux.org/contents?arch=x86&branch=v3.22&name=font-noto-cjk&repo=community)）、`/usr/share/fonts/noto-cjk/NotoSansCJK-{Regular,Bold}.ttc` 和 `/usr/share/fonts/noto-cjk/NotoSansCJKsc-{Regular,Bold}.otf`。TTC 优先选简体中文 face；常规和粗体均须可用，缺失时仅导出请求返回 503 / 50004 并说明待配置属性，不阻止其他业务启动。

Windows 未显式配置时，还会在 `%SystemRoot%\Fonts` 查找 `NotoSansCJKsc-{Regular,Bold}.otf`；常规字体依次回退微软雅黑 `msyh.ttc`、宋体 `simsun.ttc`、黑体 `simhei.ttf`，粗体依次回退 `msyhbd.ttc`、`simhei.ttf`、`simsun.ttc`。每个候选须通过中文字符和字形轮廓可读性检查。只在服务端读取系统字体并嵌入实际使用字形，不复制或分发字体文件。

REST慢匹配反代（2026-10-10）：deploy/nginx/default.conf的/api/显式proxy_read_timeout 240s（原来600s仅在/api/v1/agent/，REST实际默认60s）；Caddy /api/* transport显式dial 10s、response_header/read/write 240s；Vite开发API代理的timeout/proxyTimeout均240000ms。Agent SSE原有600s和心跳保持。同步REST不受spring.mvc.async.request-timeout 600000影响；Tomcat连接/keepalive超时限制接收与空闲连接，不是控制器执行时间。层级调查与实际延迟见研究记录。

## 后台生成运行条件（2026-10-20）

V41由Flyway升级；没有新服务、队列基础设施或密钥配置。当前单实例执行器固定4线程、32项排队，AbortPolicy拒绝溢出；每owner至多5项且同类型/实体一项活动任务。关闭时中断执行器；启动时诚实地将遗留任务标失败，不自动重复付费调用。显式取消尝试中断模型等待，领域条件写入/协作取消边界防止迟到结果覆盖任务终态；已提交报告可继续出现在历史中。HTTP断开不触发取消。
