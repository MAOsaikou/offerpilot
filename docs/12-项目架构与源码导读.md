## 1. 从哪里开始

OfferPilot 是一个 Vue 前端、Spring Boot 模块化单体后端和独立 jobs-mcp 服务组成的求职助手。当前最完整的链路是持久化聊天、简历上传解析及基础诊断、真实岗位搜索和简历匹配。职业探索、面试、成长规划等页面已有本地能力或占位，但还没有完整的后端 Agent 闭环。

- 看模块边界：[03-系统架构设计](03-系统架构设计.md)。看 Agent 与模型：[04-AI技术方案](04-AI技术方案.md)。
- 看实际接口和数据：[05-接口文档](05-接口文档.md) 区分已实现与未实现路由；数据结构见 [06-数据库设计](06-数据库设计.md)。
- 看页面规范、部署和测试：[07-前端设计规范](07-前端设计规范.md)、[09-部署与运维](09-部署与运维.md)、[10-测试与评估方案](10-测试与评估方案.md)。

## 2. 仓库结构与运行边界

| 路径 | 当前职责 | 实现边界 |
| --- | --- | --- |
| `backend/offerpilot-bootstrap` | Spring Boot 启动、配置、Flyway 迁移、HTTP 集成测试 | 启动时装配其他 Maven 模块；已含 V1–V10 迁移 |
| `backend/offerpilot-platform` | 模型网关、公共错误处理、配置、JobsMcpClient | 对外招聘 MCP 客户端已接入；不能把依赖声明视作所有通用工具已完成 |
| `backend/offerpilot-identity` | 访客凭据和当前用户解析 | 有访客身份和资源所有者隔离；正式邮箱登录、刷新令牌和跨设备恢复未完成 |
| `backend/offerpilot-agent` | 聊天、会话、SSE 事件、Orchestrator、专家注册 | 计划执行和诊断/匹配部分专家可运行；职业、面试、成长专家仍占位 |
| `backend/offerpilot-resume` | 简历上传、对象存储、异步解析、版本、基础诊断 | 已有服务端闭环；定向改写采纳和 PDF 模板导出未完成 |
| `backend/offerpilot-job` | 招聘搜索、岗位快照、证据匹配和报告 | 已接 MCP 搜索与详情；看板服务端业务仍未实现 |
| `backend/offerpilot-career` | 职业条目种子和 Holland 规则排序 | 402 条职业数据和规则层已存在；面向用户的测评与推荐 API 尚未形成 |
| `backend/offerpilot-interview` | 面试领域预留模块 | 当前主要是模块边界，尚无 AI 面试服务端状态机 |
| `mcp-servers/jobs-mcp` | 从企业公开招聘接口读取站点、岗位与详情 | 标准 MCP 的 3 个工具已测试；外部站点可用性会变化 |
| `frontend/src` | Vue 路由、共享 API、页面、跨页面组件 | 同时有服务端链路和浏览器本地功能，需逐页判断 |
| `deploy` | Compose、代理和 Windows 统一启动入口 | 启动 dry-run 已验；干净机器及公网部署仍待验收 |

根目录的 `README.md` 用于启动和项目介绍；`AGENTS.md` 指定开发与文档同步规则；`CONTEXT.md` 固定领域术语。后端各侧的本地规则还见 `backend/AGENTS.md`、`frontend/AGENTS.md`。

## 3. 三条已打通的主要链路

### 聊天与计划

`frontend/src/features/chat` 通过 `frontend/src/shared/api` 发起会话请求。`AgentController` 接收请求，`ChatService` 处理持久化多轮消息和模型输出；需要计划时由 `IntentPlanner`、`PlanValidator`、`Orchestrator` 和 `ExpertRegistry` 组织步骤并通过 SSE 发送事件。会话、消息和已接受的卡片可以刷新后恢复；运行取消有实现。

专家不是全部可用：有明确简历/版本标识时可以调用基础诊断，有岗位与简历版本标识时可以调用匹配；职业探索、面试官和成长教练仍返回占位结果。聊天中的自动招聘搜索、写操作审批、`Last-Event-ID` 续传和运行回放尚未打通。前端有续传调用并不代表后端已经提供恢复端点。

### 简历与诊断

`ResumeController` 和 `ResumeService` 接受上传并记录任务；`MinioResumeObjectStore` 保存原件，`ResumeParseWorker` 调用 `ResumeDocumentReader` 与 `ResumeExtractor` 生成可编辑的结构化内容。服务端新版本、历史和冲突保护已有实现。基础诊断由 `ResumeDiagnosisController`、`ResumeDiagnosisService` 绑定已保存版本，保存问题、原文证据和历史报告；前端在简历详情展示诊断并可继续聊天。

文字/图片模型路由、解析任务恢复和上传安全校验已在代码与测试中覆盖。真实模型解析准确率、诊断语义质量和响应耗时尚未完成规定样本集的评测。`PatchDiffViewer` 的采纳状态不生成服务端新版本，两套 PDF 模板也尚未实现。

### 岗位搜索与匹配

`JobSearchView` 和 `JobDetailView` 调用 `JobController`；`JobService` 经 `JobsMcpClient` 使用 jobs-mcp 的 `list_sites`、`search_jobs`、`get_job_detail`，保存岗位快照并去重。`JobMatchService` 将明确选定的岗位和简历版本交给模型，校验双方原文证据，保存匹配报告及历史。MCP 三个工具和 HTTP 集成测试均已验证。

目前岗位页可按字段搜索，聊天专家没有把自然语言自动解析成一次真实招聘搜索。岗位收藏后的阶段、备注保存在浏览器本地工作区；没有看板后端接口、跨设备同步、状态历史、拖拽或自动投递。

## 4. 前端如何判断一页是否真正接了服务端

`frontend/src/app/router/index.ts` 定义页面入口；`shared/api/client.ts` 管理请求和访客身份，`shared/api/sse.ts` 解析事件；`features/chat/composables/useConversationChat.ts` 管理聊天历史和运行状态。`widgets/AgentPanel` 展示计划/步骤/工具过程，`widgets/CardRenderer` 按卡片类型选组件。

| 页面 | 当前主要数据来源 |
| --- | --- |
| 聊天、服务端简历、岗位搜索/详情、匹配报告 | 后端 HTTP/SSE；刷新可读取已保存数据 |
| 求职看板、固定题库面试、成长清单 | 浏览器本地工作区；不等于服务端协作或跨设备能力 |
| 知识笔记（V19 增量） | 后端私有 CRUD/分页/混合检索；旧 workspace.notes 仅作为需确认导入的本地原件 |
| 职业探索 | 本地目标/偏好与静态方向；后端职业库规则未接成完整探索 API |

卡片类型声明多于已注册的专用组件。当前 17 种类型中 5 种有专用渲染，其余使用通用回退；展示卡片不代表对应生产方或审批操作已经实现。开发 Mock 与测试协议桩只用于确定性验证，不能作为真实模型质量或公网可用性的证明。

## 5. 数据、测试与运行

PostgreSQL 保存访客、会话、消息、Agent 运行、简历、版本、岗位和匹配报告；Flyway 迁移位于 `backend/offerpilot-bootstrap/src/main/resources/db/migration`。对象存储保存简历原件。职业种子位于同一 bootstrap 模块的 `seed/`。查看表和生命周期以 [06-数据库设计](06-数据库设计.md) 为准，不用本导读推断某张规划表已经存在。

本次验证快照：后端 90 项中 89 项通过、1 项真实模型评测默认跳过，Maven verify 成功；前端 55 项通过，lint、类型检查、生产构建通过；jobs-mcp 16 项通过，三个 MCP 工具已实际调用。隔离浏览器还验证了简历诊断、真实岗位收藏和本地功能。真实模型质量、四条自动 E2E、性能指标、全新机器和公网部署仍待验证；详情见 [10-测试与评估方案](10-测试与评估方案.md) 和 [完成度审计](research/2026-09-28-项目完成度审计.md)。

开发前先看对应契约文档，再定位本节的生产方与消费方；改动后同步契约、运行受影响检查。新增后端功能优先明确 HTTP/事件与持久化边界，再接页面；新增前端页面须区分本地状态和服务器数据。不要用删除工作区文件或重置无关改动来制造干净环境。
